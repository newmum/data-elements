### 0.3 三条必须跑通的前端主线

**主线 A：配置到运行。** 选场景 → 选来源/目标快照 → 映射与转换 → 配置调度/运行集群 → 校验 → 发布任务版本 → 本地执行 → 查看表级结果、日志与即时对账。

**主线 B：画布到统一管理。** 创建/导入任务流 → 识别组件与连接 → 补齐来源/目标/集群归属 → 一键登记 → 进入同一任务管理与监控体系 → 后续版本变化可识别，不重复登记。

**主线 C：差异到复核。** 发现即时或盘点差异 → 定位任务/表/窗口/主键 → 发起受控补传或重新执行 → 生成新证据 → 复核 → 核销原账单，原差异和处理过程留存。

### 0.4 四条不能混淆的语义

**任务创建成功 ≠ 任务运行成功；运行成功 ≠ 数据对账一致；核销完成 ≠ 数据已被自动修复；传输回执 ≠ 目标已持久写入。**

所有页面、状态、统计和 Mock 计算必须围绕这四条分别设计。不能用一个绿色“成功”同时覆盖多个过程。

### 2.3 “版本不变”的精确定义

**第一层：声明不变。** 保留每个现有依赖名和版本字符串，连同 `^` 一起保留。不自动升级、降级、去掉前缀，也不移除已有 X6 插件。新增业务代码不要求增加依赖。

**第二层：实际解析版本不漂移。** `^18.3.1` 是版本范围，不等于已经安装的精确版本；两项不带范围前缀的 CodeMirror 包则是精确声明。只有原工程锁文件及安装清单才能确定原环境的实际依赖树。[R1][R2]

开发门槛：取得原 `package-lock.json` 或相应包管理器锁文件，记录 Node/npm 和 `npm ls --depth=0`；使用原锁文件复现，不删除后重新安装并宣称“版本未变”。没有原锁文件时先形成依赖解析差异报告，原实际版本标“未知”，不擅自用最低版本或最新版本替代。新依赖只能单独审批，锁文件检查同时覆盖被间接改变的旧依赖。

## 3. 产品定位与三中心边界

### 3.1 海通的核心工作对象

海通面向集成任务、流程定义、任务版本、运行实例、表映射、传输批次、提供方/接入方账单、盘点策略与差异证据。它组织数据移动的全过程，不拥有所有源数据库的事实定义，也不以工作流图替代业务资源目录。

| 中心 | 权威工作对象 | 向海通提供什么 | 海通回传什么 |
|---|---|---|---|
| 万象数据治理 | 探查得到的表结构快照、标准及治理结果 | 来源/目标技术结构、字段 ID、类型、可引用标准 | 按任务版本产生的技术血缘、运行证据、对账差异引用 |
| 数据资源中心 | 基于技术快照编制的资源与业务目录、发布和订阅 | 已存在目标资源、业务用途、获批交付范围/版本 | 数据装载或分发结果、交付批次、及时性/完整性证据 |
| 海通数据集成中心 | 数据流任务、运行、传输、对账 | 本中心维护 | 不直接改技术快照、审批目录或重写已批准共享范围 |

业务目录不是另一个源表列表。选择目录分发时，海通必须引用它的发布版本和已批准字段投影，不能因为底层表还有字段就全部读取/发送。选择技术表仅代表知道其结构，不等于取得真实数据权限。本期角色检查为 Mock，不声称具备生产权限服务。

### 3.2 一个端到端例子

虚构的广播电视业务中，万象记录“节目备案表”快照；数据资源中心规划“节目服务库”并登记“节目备案共享目录”。海通从这张技术快照配置接入任务，按映射写入服务库的本地样例数据；当共享目录的订阅批准后，再按批准字段生成分发任务。每次接入/分发运行产生批次与对账证据。业务目录状态由资源中心维护，结构定义由元数据服务维护，任务状态由海通维护。

海通运行不会把资源中心的“目录已发布”改成“任务已发布”，也不会把数据写入数量解释为资源目录数量。三者通过 ID 与版本引用串联，而非按名称猜测。

## 5. 视觉与交互基础规范

### 5.1 品牌与清晰度

### 5.2 Logo、图标和插画资产规范

Logo 用“通道汇聚/双向流动”构成海通独立标识，不挪用万象立方体或资源中心基石。交付矢量母版与透明 1024 PNG，网页优先 SVG，小尺寸 PNG 必须有 2x/3x，不从效果图裁 20px 图标放大。菜单 12 个语义图标、任务节点、统计图标使用统一 SVG；数据库标识复用有来源与许可记录的原始品牌资源，不重绘近似商标。

每个模块提供独立本地 SVG 页头插画，浅深各一套。文字和业务标签是 DOM，不写进图片；图片与文案分列，`object-fit:contain` 等比显示。1440/1670/1920 保持清晰；768 降低装饰占比；390 隐藏非必要装饰但不隐藏关键动作。不能以模糊滤镜、白色遮罩或低分辨率截图冒充高清插画。

### 5.4 高保真验收规则

设计稿确认后锁定 Token、图标源文件与插画文件，不在开发中替换为临时截图。页面要真实可点击、可选择、可输入；不得用整张设计图覆盖 UI。审查主标题、菜单、表格、placeholder、深色浮层、100%/125%/150% 浏览器缩放与图像像素密度；截图必须来自实际 React 应用，隔离 DOM 和 AI 效果图不能计为应用验收。

AntD 5 的主题与弹层使用 ConfigProvider、App 上下文，避免静态消息实例脱离主题；浅深与紧凑算法按冻结版本核对。[R5]

## 6. HT01 集成总览

### 6.1 用户任务与页面布局

总览回答“哪些任务应先处理、哪些数据尚未到达、哪些批次仍有差异”。布局为简洁页头、关键指标、运行/及时性分布、待处理事项、近期执行。不要加入没有采样依据的 CPU 大屏或虚构同比增长。

| 区域 | 内容 | 点击结果 |
|---|---|---|
| 关键指标 | 已启用任务、执行中实例、异常实例、超期任务、待核销账单 | 带时间/状态筛选跳转对应列表 |
| 运行分布 | 接入/同步/分发/跨网；完成、失败、取消、结果未知 | 不将任务总数与执行次数相加 |
| 数据量 | 当前期间已确认写入记录、未确认记录、拒绝记录 | 下钻表与批次，单位始终为“条” |
| 及时性 | 正常、已超期、待首次执行、暂停、不适用 | 解释“超期”的应完成时间 |
| 待处理事项 | 配置失效、节点断联、积压、跨网回执超时、对账差异 | 按影响与持续时间排序 |
| 最近运行 | 任务名、版本、批次、来源/目标、耗时、状态 | 打开固定运行版本，不打开当前草稿 |

### 6.2 统计口径

默认期间“今天”，按工作区时区，显示实际起止。运行成功率 = 成功终态实例 /（成功 + 失败 + 部分成功）实例；取消、运行中、未知单列，不静默视为成功。零分母显示“—”。多表任务的一次运行按一个实例统计，表子项另有完成比，不把每张表算成独立任务。

“已确认写入记录”按逻辑批次去重，重试过程的尝试计数只出现在“处理尝试”指标。吞吐仅在对应时间区间、记录口径明确且有本地样例计时数据时计算；不知道则“未采样”，不能显示 0 伪装正常。

### 6.3 空态与异常

空工作区显示“从向导创建或登记已有流程开始”。读取失败保留面板骨架和重试，不显示清零后的正常总览。无待办显示中性“当前没有待处理事项”。超期与积压指标未配置规则时显示“未配置”，不是“全部正常”。

## 7. 核心领域、版本与状态

### 7.1 领域对象必须分开

| 对象 | 作用 | 不等于 |
|---|---|---|
| IntegrationTask | 稳定任务身份、名称、业务域、负责人、场景 | 某次运行 |
| TaskRevision | 来源/目标、流程、表映射、规则、调度等不可变可执行定义 | 持续变化的草稿 |
| FlowDefinition | 组件与端口及其业务连接 | 只存坐标的 X6 JSON |
| TableBinding | 一对来源表/目标表及字段映射和写入策略 | 一条画布装饰边 |
| RunInstance | 一次触发，绑定 taskRevisionId、逻辑时间窗和集群 | 一直显示“运行中”的任务开关 |
| TableRun / LogicalBatch | 运行中某张表/分支的处理单元 | 网络报文或 FlowFile 数量 |
| Attempt | 同一批次的执行尝试 | 新的一份业务数据 |
| Registration / BatchCreationJob | 纳管记录 / 批量创建作业 | 数据同步运行 |
| Provider/ReceiverStatement | 固定批次、表、分支、指标口径的双边账单 | 总览中的实时计数 |
| InventoryPolicy/Statement | 固定策略版本 / 一次盘点的结果 | 随页面刷新重新计算的历史 |

### 7.2 状态维度

| 对象/维度 | 建议状态 | 核心规则 |
|---|---|---|
| 草稿校验 | NOT_CHECKED / VALID / INVALID / STALE | 参数、结构或引用改变使校验失效 |
| 任务版本 | DRAFT / PUBLISHED / RETIRED | 发布版本不原地改写；停用调度不删除版本 |
| 调度状态 | DISABLED / ENABLED / PAUSED | 与运行实例状态分开 |
| 实例运行 | QUEUED / RUNNING / STOPPING / SUCCEEDED / PARTIAL / FAILED / CANCELLED / UNKNOWN | 未知不强制映射为失败；停止不代表回滚 |
| 批量创建 | PREPARING / CREATING / PARTIAL / SUCCEEDED / FAILED / CANCELLING / CANCELLED | 已创建项保留，失败项可独立重试 |
| 即时比对 | WAITING / MATCHED / MISMATCHED / INCOMPARABLE / FAILED | 双边到齐、口径可比、批次终态后才能确认结果 |
| 核销 | OPEN / READY / CLOSED / REOPENED | 与比对状态分开；保留历史证据 |
| 盘点运行 | QUEUED / RUNNING / SUCCEEDED / PARTIAL / FAILED / CANCELLED | 运行完成不等于盘点一致 |
| 盘点结果 | CONSISTENT / DIFFERENT / INCOMPARABLE / INCOMPLETE | 错误和缺数据不得作为零差异 |

这些是本地业务状态机，不映射为真实 NiFi 状态码；以后有真实执行引擎时由适配器显式转换。所有非法转换在服务层拒绝，不能只靠隐藏按钮。

### 7.3 草稿、发布与执行

修改任务创建新草稿；现有启用版本继续执行直到用户明确“发布并切换后续运行版本”。运行开始时冻结任务版本、来源/目标结构引用、调度触发时点、表映射、转换与对账口径；之后编辑不会改变已启动实例。

保存草稿、校验、发布、启用调度和立即执行是不同动作。发布后默认不开启定时任务，首次启用显示下一次时间和预期范围，避免批量创建就意外执行。

## 8. HT02 集成任务管理

### 8.1 列表与任务详情

列表支持按任务名称/代码、场景、来源、目标、所属集群、负责人、开发方式、调度状态、最近运行状态筛选。表格列：任务名/代码、场景/来源方式、来源→目标、表数、发布版本、调度摘要、运行集群、最近结果/结束时间、及时性、负责人、操作。

每行最多一个高频主动作：“配置”或“查看”；其余放更多菜单：打开画布、立即执行、暂停/启用、复制、查看流程、查看版本、归档/删除。批量动作预检每项，给出成功、失败、跳过原因，不使用一个成功 toast 掩盖部分失败。

详情页签：基本信息、流程、表与字段映射、调度及集群、运行记录、对账、版本记录。页头同时显示草稿状态和启用版本；“查看运行流程”固定到该 run 的发布版本。

### 8.2 新建、修改、复制、删除

新建先选接入、同步、分发、跨网场景；再选“向导配置”或“画布开发”。两者产出统一 TaskDefinition，不维护两套平行数据。高级画布包含向导无法表达的节点时，只允许查看向导摘要；不能切回向导后悄悄丢组件。

名称建议 1—80 字，代码 1—64 个字母/数字/下划线/连字符，工作区内归一化判重。业务域、负责人必填；描述不超过 500 字。修改 sourceId、tableRef、字段映射、转换、写入策略、调度、集群使相应校验失效；只改说明不让所有运行证据过期。

复制重新生成 taskId、节点/端口/边业务 ID、任务代码；保留可复用配置和来源版本引用，默认草稿/未启用，不复制运行、账单、历史水位或批准令牌。删除仅对无运行/登记/账单引用的草稿开放；有历史的任务归档，保留按 ID 查看证据。运行中先停止，不一键删除队列和历史。

## 9. HD01 场景向导创建

### 9.1 场景模板

| 场景 | 默认路径 | 特别约束 |
|---|---|---|
| 数据接入 | 来源读取 → 映射/转换 → 目标写入 | 目标引用资源中心已有可写目标；没有目标表时引导先建设 |
| 数据同步 | 来源窗口读取 → 去重/转换 → 增量或全量写入 | 明确全量范围与水位策略；不默认实现实时 CDC |
| 数据分发 | 已批准资源范围 → 投影/脱敏 → 分发目标 | 固定目录发布与订阅授权；不能扩大批准字段 |
| 跨网传输 | 来源 → 发送 → 接收 → 落地 → 回执核对 | 网络区和通道必填，收包成功不等于落库成功 |

“模板”仅提供可编辑的初始结构和缺项引导，不预先写入虚假的可用连接、成功状态或性能数字。

### 9.2 六步向导

| 步骤 | 主要内容 | 下一步门槛 |
|---|---|---|
| 1 基本信息与场景 | 名称、代码、业务域、负责人、场景、目的 | 必填与代码判重通过 |
| 2 来源与目标 | 数据源、库/Schema、表或集合、快照版本、选择范围 | 引用可解析且能力适用 |
| 3 映射与转换 | 字段匹配、目标类型、原值/转换、过滤、写入策略 | 关键字段有映射，无未确认类型风险 |
| 4 调度与执行 | 调度、时区、集群、超时、重试、逐表/任务策略 | 计划时间和参数有效 |
| 5 对账与验证 | 即时对账边界、指标语义、可选盘点策略、样例预览 | 支持的路径有可比口径；不支持处有明确提示 |
| 6 复核与发布 | 来源目标、任务流、字段/范围、风险、版本说明 | 校验无阻断，用户确认本地执行边界 |

桌面主体宽度随容器变化，步骤导航在顶，底部固定“保存草稿、上一步、下一步/发布”。复杂映射可展开全屏子工作台，但不能打开多层遮挡 Modal。保存草稿允许缺少下一步字段；提交发布必须全部通过。

### 9.3 预览和校验

样例预览展示转换前、转换后、拒绝记录和原因，明确来自本地合成数据及样本范围。只有配置 JSON/SQL 文本时显示“配置可保存；当前模式不执行该语法”，不能先返回一组预置结果伪称 SQL 查询完成。

校验结果按来源、目标、映射、转换、调度、对账分类，可定位到步骤与字段。离开时保留表单，恢复后仍显示原选择和错误。来源快照已更新时提示差异，用户确认采用新版本后才重建映射。

## 10. 来源、目标与读取/写入语义

### 10.1 统一引用选择器

来源选择器读取共享 sourceId 和技术实体快照；按“数据源 → catalog/database → schema/namespace → 表/视图/集合”展示，名称、数据库品牌、所属系统和结构采集时间并列。可以搜索技术名、业务名、字段，跨不同来源的同名表必须可区分。

默认不另建一套海通连接密码表。独立 Mock 运行时由 SharedDataPort 提供本地注册表；三中心联调时换用统一仓储的同一对象。来源表单如确需打开，调用共同来源管理入口；未配置入口时不能显示一个无结果的“登记成功”。

### 10.2 读取方式与能力

| 方式 | 前端必须配置 | 本期 Mock 行为 |
|---|---|---|
| 全量 | 明确来源表/投影/过滤、批大小 | 读取当前本地数据版本的选定记录 |
| 时间字段增量 | 增量字段、字段时区、初始水位、延迟容忍 | 固定窗口与水位，按记录真实计算 |
| 复合游标 | 时间字段 + 稳定唯一键 | 同时间戳用稳定键排序，避免边界漏数 |
| 指定批次重放 | 原任务版本、窗口、批次/表项 | 不重读任意扩大窗口，不跳过授权 |
| 自定义 SQL 配置 | SQL 文本、参数说明、预期输出结构 | 只支持声明的本地结构化查询子集；其余只保存，不执行 |

CDC、数据库日志订阅、存储过程等原文没有指定且当前 manifest 不能证明已有实现。本期不默认新增这些执行能力。SQL Editor 是编辑工具，不是浏览器数据库引擎。

### 10.3 写入方式

默认“追加写入”；更新/插入需明确目标唯一键映射、空键处理、类型转换及已有记录策略。包含未知键或重复键时阻断更新式发布，或由用户选择仅追加并接受重复风险。批次失败时不推进该表检查点；多表可以分别推进已完成表的水位。

目标同名已存在不能自动删表重建；“覆盖/清空目标”“执行任意 DDL”不在默认范围。需要新建结构时跳转数据资源中心的建模/物化流程；海通负责数据移动，不私自代替资源建设。

对更新写入分别记录新增、更新、未改变、已应用去重、拒绝和待确认数。只有目标状态有明确证据时才把“已应用去重”作为逻辑接收完成；不能把它并入物理新写入行数。

## 11. 映射、转换与 CodeMirror 编辑

### 11.1 字段映射界面

左右显示来源字段和目标字段，中间显示映射及转换类型；批量建议后必须有“应用建议”确认。大表采用可滚动紧凑表格，不为每个字段都生成难以阅读的长斜线。

字段列：来源业务名/技术名、来源类型、目标字段/类型、转换方式、主键/增量用途、默认值、风险、预览。联合键作为一组映射整体保存。字段按稳定 fieldId 绑定，不用数组位置或名称作为唯一标识。

自动匹配优先完全同名，再按用户明确选定的大小写/前后缀规则；同义词为推荐，不直接匹配。匹配冲突、多个同名、未找到目标分别标识。空值与缺失不可用一个空字符串全部替代。

### 11.2 初始转换组件

| 类型 | 参数与预览 | 约束 |
|---|---|---|
| 原值 | 无转换；显示两端类型 | 类型不兼容仍需提示，不能因为同名就绿色通过 |
| 常量/默认值 | 常量类型、何时替代 | NULL 与缺失触发条件分开 |
| 字符处理 | trim、大小写、拼接、截取 | 明确字符编码；截断有损需确认 |
| 数值转换 | 目标整数/Decimal、舍入规则 | 大整数/Decimal 用字符串精确表示；溢出拒绝 |
| 日期转换 | 输入格式、源时区、目标时区、输出格式 | 不明确时区的值不能默认为浏览器所在时区 |
| 值域映射 | 版本化映射字典、未匹配策略 | 拒绝/保留原值/默认值明确选择 |
| 条件过滤 | 结构化 AND/OR 条件 | 过滤计数进入对账口径 |
| 脱敏投影 | 字段白名单、掩码规则引用 | 不能由海通绕过目录批准范围 |

聚合、拆行、合并、多分支路由可作为高级组件设计，但必须声明输入/输出基数与对账可比方式；未实现组件只读保留或阻断执行，不能由通用“转换成功”处理。

### 11.3 编辑器规则

CodeMirror 6 用于 SQL、JSON、转换配置。提供语法高亮、格式化 JSON、定位错误、复制、恢复原值和结构化参数说明；敏感字面值在导出/日志前拦截。编辑器撤销优先作用于文本，失焦后快捷键才交给画布。

不使用 `eval`、`new Function` 或任意用户 JavaScript 执行转换。Mock 执行器只接受白名单转换 AST；未知函数拒绝并定位。JSON 校验只校验已声明 Schema 的字段，不能把“JSON 语法正确”当作“业务配置可执行”。

### 11.4 对账投影

内容对账采用“来源数据经过该任务已冻结转换后的预期目标值”与实际目标值比较。例如来源 `" A "` 经 trim 后，应与目标 `"A"` 比，而非原串。存在业务过滤、拆分或聚合时必须保存可比较路径；缺少确定映射则标“不可直接比对”，不能把正常转换当成数据差异。

## 12. 调度、校验、发布与运行控制

### 12.1 调度表单

任务调度支持手动、固定间隔、按日/周/月的日历规则；盘点频次保持原文的单次/按星期/按月，单独配置。每种规则显示时区、首次触发、下五次时间、结束时间、未运行补偿策略。

固定间隔 24 小时与本地日历“每天 02:00”分别保存，不能在夏令时地区互相替代。按月不存在的日期默认“跳过该月”，可显式选择“当月最后一天”；两种策略需要预览。高级 Cron 仅在原项目有解析器并核实版本后启用，不因有 Day.js 就宣称支持任意 Cron。

### 12.2 执行参数

| 参数 | 设计默认 | 规则 |
|---|---|---|
| 同任务并发 | 1 | 冲突时排队/跳过选项；不默认并行写同窗口 |
| 本地记录批大小 | 500 | 仅本地样例可配置，不当作真实引擎推荐值 |
| 失败重试 | 默认 0，用户可设有限次数 | 仅可安全重放的表项；提交结果未知必须先核对 |
| 多表失败策略 | 停止后续表 / 继续独立表 | 有依赖的下游表不跟随“继续”忽略依赖 |
| 超时与及时性 | 必须明确时间单位 | 运行超时与应完成时间分别保存 |
| 暂停调度 | 停止后续自动触发 | 默认不取消已运行实例 |
| 停止实例 | 先 STOPPING，再安全边界停止 | 已写记录保留；不是回滚按钮 |

### 12.3 发布预检与执行前复验

发布预检检查：引用有效、字段/键完整、类型/转换支持、流程可达、出口完整、目标适用、集群版本能力、调度合法、授权范围、对账边界。运行前再次校验引用和授权有效性，避免草稿校验后来源被停用仍显示正常执行。

立即执行确认显示发布版本、表数、窗口、目标、写入方式、预计样例规模和本地运行说明。发布运行固定来源数据版本（Mock 快照），失败重试不得偷偷使用已经变化的来源记录来“补齐旧账”。

## 13. HD02 全屏 X6 任务流工作台

### 13.1 与万象一致的操作，不同的业务语义

继承全屏、选择/平移、框选、搜索、属性按需打开、关闭返回和快捷键优先级。海通节点是查询、转换、路由、写入、发送、接收等处理组件；X6 连线是有向数据流，端口表示成功/失败/待重试等出口。**不复用 ER 节点的主外键含义，也不把 X6 替换成 React Flow。**

布局为顶部 56px 会话栏、左侧 280px 组件/对象库、中间画布、右侧 360—440px 属性面板、底部轻工具栏。属性面板默认关闭；复杂配置可展开，但不让两侧同时挤压窄屏画布。画布全视口，不保留外层侧栏。

### 13.2 工具栏与操作

顶部：任务名/草稿/启用版本、保存状态、保存、校验、发布/登记、本地试运行、专注模式、主题、关闭。低频 JSON 导入导出、版本对比放更多；危险“清空画布”需独立确认且可撤销草稿，不清空任务历史。

| 操作 | 交互规则 |
|---|---|
| 单击节点 | 选中，不立即弹大型表单 |
| 双击节点 | 打开组件属性，焦点到首个可编辑字段 |
| 拖动节点 | 仅标题/拖拽区域移动，表单文字可选 |
| 空白拖动 | 按当前选择/平移工具；Space 临时平移 |
| 多选 | Shift 点选、选择工具框选；批量对齐/固定 |
| 端口连线 | 只允许方向和类型匹配；错误出口也必须有去向或显式终止 |
| 单击边 | 显示出口类型、队列摘要、路由说明；不直接执行任务 |
| 缩放 | 底部缩放、100%、适应画布；不缩放整个页面 |
| 搜索 | Ctrl/⌘+K 搜索组件/表/字段引用，定位高亮，不改变布局 |
| Esc | 先关闭编辑器建议/下拉，再子表单，再专注/面板，最后请求关闭全屏 |

Ctrl/⌘+S 保存当前草稿；Ctrl/⌘+Z/Y 在画布焦点中撤销/重做。输入框、CodeMirror、Modal 内优先处理自身快捷键。Delete 不在输入状态删节点。复制节点时生成新节点/端口/边 ID，只重连选中集合内连接，不复制运行状态与凭据。

### 13.3 组件规范

| 组件组 | 组件 | 关键配置与输出 |
|---|---|---|
| 读取 | 表查询、结构化查询、已批准资源读取 | 来源快照、投影、窗口；成功/空数据/失败 |
| 转换 | 字段映射、值域映射、条件过滤、脱敏 | 规则版本、前后样例、拒绝原因 |
| 组织 | 多表组、条件分支、受控合并 | 表列表、依赖和基数语义 |
| 写入 | 表写入、文件样例输出 | 目标结构、键、策略；提交/拒绝/未知 |
| 跨网 | 发送、接收、回执核对 | 通道引用、分段状态、批次关联 |
| 证据 | 指标采样、对账边界、异常收集 | 行数单位、边界 ID、对应表/分支 |

组件模板在本地注册表声明属性、端口、可执行能力、校验规则和归一化 DTO。原工程组件名称尚未提供，不能把这些设计名写成已经支持的 NiFi Processor 类名。

### 13.4 结构校验与图数据

节点/端口稳定 ID，业务定义单独存储；X6 的位置、尺寸、缩放、小地图等作为 layout。需要处理孤立节点、没有终点的路径、未接错误出口、不支持组件、跨网络区未经过传输组件、无界循环等。正常 ETL 依赖图默认要求无环；受控重试是执行策略，不通过随意反向连线制造无限循环。导入原图有环时保留原图只读并说明不可执行，不静默删边。

使用 X6 History 的事务批处理合并一次拖拽/批量映射；运行遥测刷新不进入撤销栈。React 节点采用支持主题上下文的适配方式；挂载只建一个 Graph，卸载销毁 Graph、事件、观察器，防止 React 开发模式重复挂载累积监听。[R3][R4]

### 13.5 保存、返回与只读运行图

草稿自动保存默认防抖约 1 秒，保存必须带 expectedRevision；失败显示“未保存”，允许保留/导出草稿，不能先写已保存再异步失败。关闭返回打开来源的筛选、选中与滚动状态；从深链接直接打开无来源时回任务列表。

运行详情的流程图只读，显示对应组件与表项的运行证据，不使用当前草稿替换历史。点击“基于此版本修改”生成/打开草稿后才可编辑。运行图的队列数量使用明确采样时点；过期数据变为“未刷新”，不是继续发光表示正常。

## 14. HT03 任务登记

### 14.1 场景与输入

原文要求将画布任务反向解析并一键登记。本设计提供“从本地画布登记”及“导入外部流程文件”两个入口。输入可以是本产品 FlowDefinition JSON、受支持版本的 X6 流程导出，或由适配器明确支持的外部流程格式。没有收到 NiFi 流程样例，不能宣称支持任意 NiFi 版本/Registry/Snapshot 的自动解析。

登记列表：流程名/标识、所属集群、外部版本、已登记任务、解析状态、未识别组件数、绑定完整性、最近登记、操作。集群选择是管理归属，不会自动把流程部署过去。

### 14.2 四步解析登记

**导入 → 组件解析 → 业务补全 → 登记预览。** 解析形成组件、连接、参数、来源/目标候选和未识别项；保留原始文件 hash 和导入版本。随后用共享 sourceId/entityId 绑定候选对象，补负责人、场景、调度、集群、对账边界。

同一文件不得通过 `dangerouslySetInnerHTML` 直接渲染；未知 HTML/脚本/外部 URL 不执行。包含凭据的字段提示剔除或替换引用，不写入浏览器导出。外部文件较大先检查大小与结构，拒绝超限并说明，不卡死后才失败。

### 14.3 重复、版本与漂移

管理身份由 workspaceId + clusterId + externalFlowId + sourceSystem 组成；同版本/同内容重复登记返回已有记录。外部版本变更形成“待更新”，展示新增/删除/修改组件和受影响表映射；用户确认后形成新任务草稿，不覆盖启用版本或已有运行。

能够识别并满足执行规则的流程可登记为可发布草稿；含未知组件的流程可登记为“仅管理/不可本地执行”，清楚显示阻断项。登记成功不等于部署成功；运行实例仍须来自受支持执行适配器或 Mock 运行器。

### 14.4 一键的真实含义

“一键登记”仅在预检全部满足后一次提交登记、任务身份、初始版本及日志。失败回滚这些相关记录，不留下无来源半任务。多集群同名流程按不同外部身份并存，不能按流程名称去重。

## 15. HT04 两库批量创建任务

### 15.1 页面与步骤

步骤：选两库 → 选表范围 → 匹配表 → 匹配字段/调度 → 预检 → 提交创建作业。来源库和目标库引用共享连接与结构版本，可同引擎或跨引擎；表格同时显示来源完整路径与目标路径，不能只显示同名短表名。

全库选择冻结当时可见表清单；“全库”不是之后自动纳入新表。自定义选择支持搜索、多选、排除、仅显示未匹配。提交时再核对清单版本变化，新增表需用户确认后加入。

### 15.2 表名匹配规则

| 规则 | 示例 | 冲突处理 |
|---|---|---|
| 同名 | `program_record → program_record` | 同 namespace 内多个候选则待确认 |
| 去来源前缀/后缀 | `src_program → program` | 仅去指定边界位置，不全局字符串替换 |
| 加目标前缀/后缀 | `program → ods_program` | 目标必须存在可写结构或明确暂不创建 |
| 指定组合 | `src_program_raw → ods_program` | 预览归一化前/后名称 |
| 人工映射 | 任意两张适用表 | 标识为人工，后续自动匹配不覆盖 |

大小写策略单独配置，不能假设所有数据库都大小写不敏感。多个来源映射同一目标默认阻断；需要汇聚的业务应使用专门流程并配置键/冲突策略，而不是让批量向导悄悄合并。

### 15.3 字段默认与逐项结果

按照原文，同名字段默认“原值转换”；同时必须校验目标必填、类型、长度、键、不可写字段。未匹配目标必填字段为阻断；来源多余字段默认不传并计入投影说明；未确认类型有损转换不可自动通过。

每个表对显示已匹配/待确认/阻断、字段匹配数、目标必填缺失、任务名/代码、调度偏移、预计创建状态。先允许下载匹配方案 JSON，修改后重新预检；不导出真实密码。

### 15.4 随机 24 小时调度

原文要求原样保留为默认：`interval = 24h`，在作业确认时为各新任务一次性产生 `phaseOffsetMinutes ∈ [0,1439]`，保存 anchor、时区、首次时间、后续固定间隔。页面列出前五次触发；用户可以在提交前调整。Mock 测试允许注入可重复随机种子，实际配置生成后不再随刷新重新随机。

这是错峰设计，不保证随机结果完全无碰撞。任务创建完成默认未启用调度，批量启用另行确认，避免数百任务被创建时立即对目标产生写操作。日历“每天某时”是另一选项，不把它偷偷替换掉 24 小时间隔。

### 15.5 串行创建作业

一次提交先持久化 BatchCreationJob，再返回作业详情；前端页面可离开。按批组织、逐项串行创建，默认每批 20 项、创建并发 1、组间短暂让出执行线程；这是本地 UX 默认，不宣称为真实集群性能参数。原文“后端创建无需等待”在本期以本地持久任务模拟，未来后台实现不在本文范围。

幂等键为 jobId + itemId；成功项重试不会再造任务。取消保留已创建任务，未处理项为取消，不假装全部回滚。重试只处理失败项并保留 attempts。详情显示总数、成功、失败、待处理、已取消和逐项日志；创建成功不增加“已同步记录数”。

## 16. HT05 多表同步任务

### 16.1 与批量创建的区别

**批量创建：N 个表对 → N 个可独立调度的任务。多表同步：N 个表对 → 1 个任务流/1 次任务触发 + N 个表级执行单元。** 两者不能仅换一个按钮名称而使用同一数据模型。

### 16.2 配置与列表

任务列表显示任务名、来源→目标、表数、有效映射/阻断、统一调度、集群、最近整体结果、表级完成比、负责人。新建复用表匹配组件，但产出一个 TaskRevision 和 TableBinding[]。

任务详情包含表组矩阵：来源/目标、读取方式、映射、转换、写入策略、优先级、依赖、最近检查点、当前表状态。可以“批量应用”共同规则，再对个别表覆写；批量更改需预览影响，不无提示抹掉人工规则。

### 16.3 依赖与资源

默认串行表执行，可配置有限并发；每张表批量读取、转换与写入，不需要在画布上复制一百组组件。多表组节点显示表数和异常数，展开矩阵查看单表。表依赖需无环；无依赖表允许独立推进，有依赖表只在前置要求满足后执行。

“资源节约”作为同流程共享配置/连接上下文的设计目标，不生成虚假的节省百分比。实际线程、连接池和真实资源使用只能以后由执行引擎度量，本期不宣称达到生产收益。

### 16.4 检查点、局部失败与重试

每表单独检查点、水位和逻辑批次。某表失败后按任务策略继续独立表或停止后续；已提交数据不默认回滚。整体 PARTIAL 保留成功表，下次只重试失败表的原窗口；成功表不重复计数和写入。

对账以表/分支/目标分别生成，不用所有表总行数相等证明每张表正确。任务可运行完成但部分表对账仍 WAITING，两个状态同时可见。

## 17. 任务运维公共模型与统计口径

### 17.1 一个任务，多个视图

接入、分发、跨网监控共用 Task/Run/Batch，不复制任务。`scenario` 表示创建场景，`direction` 表示相对数据平台的 INBOUND、OUTBOUND、INTERNAL。内部同步默认在接入监控可筛选；跨网任务按方向可以同时出现在跨网视图和相应接入/分发视图，但全局统计按 ID 去重。

监控页面默认刷新当前查询的摘要，不每秒重载整个工作区。选中行、筛选、页码、展开详情和滚动位置保留；刷新中的旧数据带“更新中”，失败带最后成功采样时间。

### 17.2 必须统一的指标

| 指标 | 定义/单位 | 展示限制 |
|---|---|---|
| 查询输出记录数 | 查询组件实际输出的业务记录 / 条 | 不是报文数、字节或 FlowFile 数 |
| 转换输出数 | 转换/过滤后发往具体出口的记录 / 条 | 多分支单独统计 |
| 目标确认记录 | 有提交/已应用证据的逻辑记录 / 条 | 不能使用收到网络包数量替代 |
| 拒绝/过滤数 | 有规则与原因的记录 / 条 | 合法过滤与错误拒绝分开 |
| 待确认数 | 已发送但落地结果未确认 / 条 | 不自动算丢失或成功 |
| 队列积压 | 条目数量与字节数分别显示 | 单位不互换，不全部称为数据量 |
| 执行耗时 | startedAt 至 endedAt，执行中至采样时点 | 排队时长独立 |
| 数据及时性 | 期望完成时间/数据水位与实际到达差 | 最近任务成功不自动等于数据最新 |

任务及时性建议提供“本次是否按时完成”与“数据是否达到期望窗口”两项。例如任务准时结束但只处理上周数据，不能显示“数据更新及时”。首次未运行、手动无 SLA、暂停调度分别显示待首次、不适用、已暂停。

### 17.3 运维动作与风险

修改打开新草稿；复制重置状态；查看流程打开该版本只读画布；立即执行明确参数；暂停只停后续调度；停止当前实例保留已提交批次；重试选择表/批次并检查幂等及原窗口；删除遵循有历史归档原则。批量操作显示逐项可执行性，不对 UNKNOWN 提交结果执行盲目全量重试。

## 18. HT06 接入任务监控

### 18.1 布局与字段

页头说明、运行状态和及时性摘要、过滤栏、任务/实例切换、主表和详情入口。表格：任务名/发布版、来源→目标、集群、调度、最近开始/结束、运行状态、接入窗口、期望完成时间、查询输出/确认写入、积压、即时对账、操作。

“任务模式”每行一个任务的最近摘要；“运行模式”每行一个实例。时间筛选解释按计划触发/实际开始/完成的哪个时间过滤，不混用。

### 18.2 运行详情

顶部固定 runId、任务版本、场景、逻辑窗口、来源/目标与当前状态。页签：流程、表级批次、指标、日志、即时账单、重试记录。多表可以从整体 PARTIAL 一键只看失败表，再定位到组件与字段。

日志行包含发生时间、级别、组件、表、批次、attempt、错误代码、摘要与处理建议；结构化详情不把完整样例数据无条件输出。可复制错误标识、导出当前筛选日志、跳转画布高亮相关组件。

### 18.3 常见异常的下一步

| 异常 | 页面提示 | 允许的处理 |
|---|---|---|
| 来源字段变化 | 原字段已删除/类型变化，列出映射影响 | 编辑草稿，确认新快照，发布新版本 |
| 目标键冲突 | 拒绝数、键样例与写入策略 | 调整策略或受控重试；不自动清表 |
| 长时间排队 | 队列名、等待时长、节点/集群采样时间 | 查看队列，暂停后续触发，按策略重调度 |
| 读取后进程失联 | 已知/未知提交范围 | 先对账核对，不直接认定整批未写入 |
| 及时性超期 | 应完成时间、最近水位与相差窗口 | 查调度/失败表，补发指定窗口 |

## 19. HT07 分发任务监控

### 19.1 与接入的区别

复用运行表、日志与图查看方式，增加提供资源、发布目录版本、订阅/批准引用、接收方、交付字段数、渠道、发送/接收/落地状态。分发基于明确授权范围，不能因来自同一表而继承其他目录的批准字段。

一个源分发到三个目标形成三个 deliveryLeg，每个 leg 独立统计和对账。整体显示“2/3 目标完成”，未完成目标可独立重试；不能把成功目标的 200 条加到失败目标的待收 100 条上得出“一致”。

### 19.2 数据量与回执

同时显示预期发送、已发送、已接收、已确认落地、拒绝、待确认；不支持落地回执的渠道显示“落地结果未知”，不能把 HTTP 200 或文件包已上传解释成目标表写入成功。本期均为本地模拟回执，界面详情明确来源。

### 19.3 资源中心联动

若任务由批准订阅生成，固定 publicationId、subscriptionId、grantVersion 和字段投影。任务复制默认成为未授权草稿，重新选择有效批准引用后才可执行。目录下线/订阅撤销时阻止新分发；已发送批次不声称可被远程收回，保留处理记录。

当前只有海通 manifest，不证明已有目录授权接收端。本期通过 SharedResourcePort 和合成批准记录设计流程；真正与资源中心联调时核对契约版本，不能只把菜单跳转称为数据互通。

## 20. HT08 集群统一监控

### 20.1 集群列表与登记

集群列表：名称/代码、引擎类别、网络区、环境标签、管理地址摘要、节点在线/总数、运行实例、队列条目/字节、最旧排队时长、公告数、采样时间、状态、操作。

新增/编辑表单：名称、代码、引擎类型及版本标签、网络区、用途、管理地址描述、节点清单、并发额度、说明。地址在本期只作本地配置，不发请求、不保存真实密码。引擎类型可声明 NiFi 风格、本地执行器或只读外部描述；没有真实协议样例不得宣称连接测试通过。

修改能力或引擎版本使受影响任务的发布/运行检查失效；仅改说明不影响任务。有关联任务或运行中的集群不能硬删除，先停新分配或归档。节点名称与 nodeId 分开，重命名不丢历史。

### 20.2 集群详情四个页签

| 页签 | 内容 | 交互 |
|---|---|---|
| 概览 | 运行/队列摘要、能力和采样有效期 | 跳转受影响任务 |
| 节点 | 状态、心跳、运行数、队列、可用资源采样 | 只读查看；停用前展示运行影响 |
| 队列 | 队列名、组件连接、条目/字节、阈值、最旧项 | 定位流程及批次，不默认暴露原数据 |
| 公告牌 | 级别、来源节点/组件、时间、代码、摘要、确认人 | 筛选、确认已读、关联任务 |

CPU/内存/磁盘等没有真实或合成采样记录则显示“未采样”。Mock 初始采样有固定时间和确定性事件，不每次刷新随机抖动。公告已读只改变阅读状态，不代表错误解决。

### 20.3 队列和背压

队列分别配置条目阈值、字节阈值、告警水位和最旧等待阈值。达到阈值显示受阻上游及影响下游。参考 NiFi 的队列/背压/公告术语可帮助用户理解，但不照搬其默认阈值成为本产品要求，也不据此认定海通已集成 NiFi。[R6]

本期不提供“清空真实集群队列”按钮。清除本地模拟待处理项必须确认范围与结果，不删除已生成账单。节点恢复后不能同时让旧领取者与新领取者提交同一批次，执行器用租约 token 与版本校验。

## 21. HT09 跨网传输

### 21.1 向导内容

在通用向导上增加：来源网络区、目标网络区、通道引用、发送端集群、接收端集群、允许资源/字段、包格式、分片阈值、回执超时、失败恢复策略。跨网表示额外传输阶段，不等于允许绕过安全边界。

两端本期都是本地模拟器，网络区和地址为场景标签。没有实际网闸、总线或协议材料，不设计假“已连通生产专网”测试。不新增安全中心页面；脱敏/许可来自共享策略引用或明确的本地约束。

### 21.2 分段状态

| 阶段 | 记录 | 不能混淆 |
|---|---|---|
| 生成待发数据 | 任务/表/窗口、批准投影、记录数 | 不是已发送 |
| 打包 | packageId、内容版本、分片清单、摘要 | 包摘要不是逐行内容对账 |
| 发送 | 发送 attempt、字节、结果 | 不是接收成功 |
| 接收/校验 | 回执、包/片完整性、收到时间 | 不是目标写入 |
| 目标落地 | 写入结果、拒绝、待确认 | 才形成接入方相应落地证据 |
| 比对 | 双边账单、差异、核销 | 不用整包成功替代行级对账 |

传输详情用时间线与分段状态表，不把所有阶段挤进一个进度圆。失败重发相同包使用同一逻辑包标识与新 attempt，接收方去重；允许只重传失败分片，但不能伪造缺失片已收到。回执到达较晚时形成新回执版本，已展示账单的更新可追踪。

### 21.3 日志与恢复

错误按生成、发送、接收校验、落地、回执分组。回执超时显示“接收/落地结果待确认”，不是自动重传全包；用户先核对本地接收记录，再选择安全重试。取消后已接收/已落地结果保留，不能声称跨网分布式事务整体回滚。

## 22. 数据对账的统一语义与算法边界

### 22.1 即时对账与盘点对账

| 维度 | 即时对账 | 盘点对账 |
|---|---|---|
| 关注对象 | 一次运行的逻辑批次/表/传输分支 | 指定策略、时间区间内的来源与目标数据 |
| 证据来源 | 查询输出、转换输出、发送/落地计数及回执 | 固定数据版本、键集合、字段内容摘要和差异 |
| 首要问题 | 这一批是否按约定完整交接 | 这一期间是否存在漏数、多数、内容不一致 |
| 默认范围 | 数据流中的可比较边界 | 按时间字段、主键及字段映射定义 |
| 不说明的事项 | 行数相等不证明每个字段内容相同 | 不对账之外的数据和未来变更作保证 |

### 22.2 比较单元与关联键

最小比较单元为 `taskRevisionId + runId + logicalBatchId + tableBindingId + deliveryLegId + comparisonContractVersion`。提供方/接入方各自产生不可变 statementRevision。attempt 记录执行尝试，但不能让重试变成另一份逻辑应收数据。

原文要求记录“查询组件输出条数”，因此必须保留 queryOutputRows。若随后发生过滤、转换、路由，应另外记录 expectedReceiverRows；不能直接把 queryOutputRows 与目标行数相比后把合法差值叫丢数。

### 22.3 守恒关系的适用条件

简单保基数路径可以采用：

```text
查询输出 = 合法过滤 + 转换拒绝 + 可发送记录
可发送记录 = 已确认接收应用 + 目标拒绝 + 待确认
已确认接收应用 = 新增 + 更新 + 有明确证据的已应用/未改变记录
```

每项须互斥、口径相同、批次边界一致；不满足条件时不能套用。实际物理新增/更新行数与逻辑应用记录数分别保留。多路广播以目标 leg 分别对账；聚合、拆行、合并使用显式转换后的预期边界或标“不可直接比对”。不累加各节点输出数作为全流程应收。

### 22.4 具体示例

某批查询输出 1000 条，其中经业务过滤 50 条，约定应收 950 条。接入方确认新增 920、更新 20，拒绝 5、待确认 5，则逻辑已应用 940，差额暂为 10。由于仍有待确认，该账单先显示“等待终态/待确认 5”，同时展示已知拒绝 5。

待确认 5 得到有效回执后，已应用 945，终态差异 5。只对拒绝的 5 条执行受控补传并确认，累计逻辑已应用达到 950，新的对账修订一致。不能把第二次尝试的“查询 5”加到原应收 950 上形成 955，也不能删除原差异记录。

### 22.5 对账对象与变化

账单引用该次运行的固定图、表映射、字段策略和时间窗。任务后来改了字段，不重算旧账单。迟到回执、补传结果、人工复核均形成新证据/新比对修订；原记录不可被“核销”覆写。

数据读取失败、证据不足、双方快照不可比、统计口径未知各有明确状态；不把缺失值填 0，不把无结果做成一致。

## 23. HT10 即时对账与核销

### 23.1 列表与详情

列表筛选任务、运行、批次、表、方向、集群、比对结果、核销状态和时间。列：任务/批次、来源表→目标表、提供方应收口径、接入方已确认、差异数/待确认、证据更新时间、比对结果、核销状态、操作。

详情分为“批次摘要—双边账单—数据流路径—差异处理—核销记录”。左侧提供方账单，右侧接入方账单，逐项解释查询输出、过滤、转换拒绝、预期接收、新增/更新/已应用、拒绝和待确认。中间路径从固定任务图追踪相关边界，高亮关联组件；不声称通过任意 SQL 血缘自动推导所有预期记录。

### 23.2 账单生成和配对

读取组件输出与接收落地阶段均形成计数事件。运行/批次到安全边界后生成账单；另一侧尚未出现时 WAITING。按比较单元配对，不按“最近时间相近”猜测。双边 revision 变化后新建 comparisonRevision，并显示旧结论已被新证据取代。

单次读取结果本身无总数时显示“已确认范围”；源端扫描未完成不得生成“全部一致”。接收方不能修改提供方账单数字以求对平。

### 23.3 核销条件

默认只有 MATCHED 且逻辑批次已终态、无待确认、证据完整、比较口径未失效的账单进入 READY。核销时记录账单双方 revision、comparisonRevision、操作者、时间、说明和关联处理单；批量核销先逐项校验。

存在差异默认阻断核销，操作为“查看差异/发起补传/重新比对”。需要接受业务差异的特殊场景可后续增加“差异认可核销”，须独立策略、理由和复核，不作为本期默认捷径。核销只关闭处理流程，不修改数据、不删除账单、不把原运行失败状态改为成功。

核销后若收到推翻原结论的新回执，生成新比对修订并将处理状态 REOPENED，原核销事件保留。防重复点击以账单修订+决定 ID 去重。

### 23.4 差异处理

补传预填原表、原窗口、失败记录键/批次和转换版本；范围不可超过原批准投影。没有行级失败键时只能生成待核查任务，不声称已精确补齐。新任务、原账单和复核证据互相关联；补传执行成功后仍需再次对账才能核销。

## 24. HT11 盘点对账策略

### 24.1 策略配置流程

步骤为“基础信息—双方对象与窗口—主键与字段—比较规则—频次与执行—预检”。支持关联已有集成任务预填映射，也支持人工选择技术对象；无任务不代表无来源版本，仍需固定快照与映射。

| 字段组 | 字段/规则 |
|---|---|
| 基础 | 名称、代码、业务域、负责人、说明、启用状态 |
| 比较对象 | 来源/目标 sourceId、entityId、结构 revision、namespace、关联任务版本（可选） |
| 对账区间 | 固定起止/相对时间窗、工作区时区、延迟容忍、双方读取基准时点 |
| 创建时间字段 | 来源字段、对应目标字段、源值时区/格式、转换方式 |
| 主键 | 来源键与目标键的有序映射，支持复合键；空键/重复键策略 |
| 数量比较 | 行数或去重键数，必须明确；两者同时显示时不混为同一计数 |
| 内容比较 | 字段有序映射、转换后口径、规范化版本、SHA1 算法标识 |
| 频次 | 单次、按星期、按月；星期/日期/时间/时区/生效终止 |
| 输出 | 差异分类、字段级明细、掩码策略、附件格式和导出上限 |

### 24.2 区间与一致读点

统一采用左闭右开 `[start, end)`，两端转换到明确时区后比较。原值无时区时要求用户指定源时区，不默认浏览器时区。冻结 Mock 的来源与目标 dataRevision，再计算，避免扫描时数据继续变化导致结果漂移。

任务存在正常传输延迟时，可配置等待窗口关闭后再盘点，结果注明截至时点。不使用同一时间区间但两个不相容快照生成“一致性保证”；无法取得等价口径时 INCOMPARABLE 或附局限。

原文使用“创建时间字段”必须保留；它能界定创建记录的范围，**不自动覆盖该区间外历史记录后来发生的更新**。需要检查这类变化时可新增“更新时间/全量复核”策略选项，明确属于扩展，不悄悄替换原创建时间字段。

### 24.3 主键与数量

先检查键映射的完整性、NULL/缺失/重复，再做内容比较。数据库声明 PK 可以作为提示，但应基于本地样例验证当前比较范围内的键唯一性；没有 PK 可人工指定候选键，标注来源与验证范围。

若键不唯一，仍可生成双方原始行数及重复键诊断，但不能随机取第一行继续逐行内容比较。纯数量比较可运行，结果必须写“仅核对条数，未验证逐行内容”。两端同为 1000 条不说明主键集合或内容相同。

### 24.4 SHA1 内容比较：保留原需求，不偷换算法

原文明确要求 SHA1，本方案保留 `SHA-1` 为“原需求兼容”配置，并在策略/账单记录算法和规范化版本。可增加可选 SHA-256 强化配置，但不在未经确认时改变原 SHA1 默认业务口径。

外部技术说明：SHA-1 不应承担密码学安全用途；Web Crypto 仍提供摘要能力，但摘要一致不能作为防恶意篡改证明。[R7] 因此本项目将 SHA1 用于按约定比较数据内容，不用于口令、安全签名、跨网认证或“已合规”判定；高保证场景还应保留字段级核对方式。

### 24.5 内容规范化设计

**先对齐语义，再计算摘要。** 来源按已冻结字段映射/转换生成预期目标投影；目标按同一有序字段契约读取。不要直接对两个不同字段名的原始 JSON 对象作 SHA1。

每条记录编码为一个规范结构：契约版本 + 有序字段槽位 + 逻辑类型 + 值存在状态 + 规范值。槽位由已确认映射定义，不使用两边不同的 fieldId 直接入摘要。使用固定结构 JSON 数组与 UTF-8 编码，所有精确数字以规范字符串保存，不能依赖对象属性遍历顺序。

| 类型/情况 | 规范化规则 |
|---|---|
| NULL / 缺失 / 空字符串 | 分别编码 `null / missing / value:""`，不可互换 |
| Int64 / Decimal | 字符串表达；Decimal 按策略固定/规范化 scale，记录舍入，不转浮点 |
| 字符串 | 默认精确字符；trim、大小写、Unicode 规范化只有用户显式启用才执行 |
| 日期/时间戳 | 按声明源时区转规范时点或日期，不混淆日期与瞬间 |
| 布尔 | 严格类型；0/1、Y/N 需显式映射 |
| JSON | 递归排序对象键；数组保持顺序，除非有显式业务规则 |
| 二进制 | 固定字节编码和大小上限；超限标不支持，不静默截断 |
| 不可转换 | 记录具体键/字段为失败项，不将异常编码成空值继续判一致 |

按规范化主键配对记录，再比较行摘要；不一致时进一步计算字段差异。键集合摘要使用排序后的键和计数，不使用会抵消重复行的简单 XOR/相加。无内容变化但显示格式不同的情况，由是否启用相应规范化策略决定，不凭 UI 人工美化影响比对。

### 24.6 算法与结果

流程：冻结策略和两端数据版本 → 选定区间 → 应用来源转换/过滤 → 校验键 → 比较数量/键集合 → 比较行摘要 → 生成字段级差异 → 固定账单和附件。耗时步骤进入 Worker，支持中断；不是在主线程一次 JSON.stringify 整库。

分类至少包含来源有目标无、目标有来源无、内容不一致、重复键、空键、字段不可映射、区间不可比和读取失败。执行成功可以得到 DIFFERENT；部分表失败得到 INCOMPLETE，不显示整体一致。

## 25. HT12 盘点对账单、差异附件与复查

### 25.1 列表与详情

列表：策略名/版本、来源→目标、实际区间、创建时间字段、主键组、比较模式/算法、来源/目标行数、差异键数、执行状态、比较结果、执行时间、操作。主操作“查看差异”，无差异时“查看账单”；导出、复查、历史在更多。

详情页展示冻结策略、双方数据/结构版本、区间及时区、数量摘要、键检查、内容结果、未比较范围、规范化规则和错误。差异数按定义去重，字段差异个数和受影响记录数分开，不能将一行三列差异显示为三条丢失记录。

### 25.2 差异阅读

按差异类型筛选，列表主键组、双方存在状态、变化字段数、所属表、处理状态。点击后双栏显示来源预期值/目标实际值，只突出实际差异并保留原始类型；大值折叠可展开，不截断后假装相同。敏感字段按配置掩码；掩码后仍注明“值已隐藏”，不把两个星号相同当作原值一致。

### 25.3 附件

支持差异摘要 CSV、结构化 JSON、字段差异 CSV。附件元信息含 statementId、策略版本、区间、双方版本、算法、规范化版本、生成时间、总行数/导出行数、是否截断、掩码说明。历史附件使用当时冻结内容，不点击下载时重读当前数据。

导出按申请范围与字段投影裁剪，防止超范围敏感信息进入文件；CSV 对公式开头字符作转义。默认差异预览分页，每页 50 条；单文件本地输出上限作为设置显示，超限要求缩小范围或分片，不静默丢弃尾部。

### 25.4 复查与任务联动

“重新盘点”生成新执行、新账单，不覆盖旧结果；可选择原策略/原窗口复验或显式改策略。由差异发起补传，预填差异键与版本，用户确认写入方式后建立新任务。数据修复没有充分支持时只生成待核查记录，不开放任意 SQL 自动改库。

原文只明确即时账单核销，因此盘点默认是“差异处理/复查记录”，不强行添加同名核销流程。后续需要统一处理中心时可通过关联证据聚合，但不重复产生不可追踪的另一套差异。

## 26. 与万象、数据资源中心的衔接

### 26.1 运行时隔离，业务数据共用

海通使用自己的 package.json 与锁文件独立构建。其他中心若使用不同 React/AntD 版本，不能把其 JSX、全局 Store、React Context 直接导入海通后要求同一依赖树兼容。默认以同源独立入口 `/haitong/`、`/wanxiang/`、资源中心入口装载各自 bundle；跨中心切换是整页进入另一入口，不混装多版本 React，也不使用 iframe。

独立构建不等于三份数据。共享对象通过无框架依赖的 DTO、版本化共享仓储/适配器访问；来源、技术结构、标准、目录授权与执行证据分别有权威维护者。只有已通过契约兼容检查的中心能写共享对象，不能让海通把旧工作区按自己的版本全量覆盖。

### 26.2 共享对象清单

| 对象 | 最小引用 | 海通读/写边界 |
|---|---|---|
| 数据源 | workspaceId + sourceId + configRevision | 读取与参数检查；共享来源编辑通过统一入口，不自建凭据副本 |
| 技术实体/字段 | entityId + structureRevisionId + fieldId | 固定结构输入，映射失效需确认，不编辑快照 |
| 标准映射 | standardId + revisionId + ruleRef | 引用转换依据；候选可跳转，不直接发布标准 |
| 仓库目标 | resourceId + structureRef + writableCapability | 选已有目标；需要建表跳转资源中心 |
| 业务目录 | catalogEntryId + publicationId | 仅用于业务说明/批准范围，不替代底层结构 |
| 订阅批准 | subscriptionId + grantRevision + projection | 执行前核对状态，不能增字段/扩期限 |
| 运行/血缘 | taskId + taskRevisionId + runId + table/field lineage | 海通提交事实证据及引用，区分设计关联和执行路径 |
| 质量/对账差异 | statementId + differenceId + evidenceRevision | 可作为治理工单输入，不等于数据质量规则已经判定根因 |

### 26.3 任务接力

| 起点 | 目标 | 返回与保护 |
|---|---|---|
| 海通来源/目标选择 | 万象定位技术实体或字段 | 返回向导原步骤和映射，不自动换结构版本 |
| 海通无目标表 | 数据资源中心建模/物化 | 返回选择新登记资源；只创建结构不宣称已同步数据 |
| 资源中心订阅批准 | 海通创建分发草稿 | 预填批准投影，任务未启用，不自动立即发送 |
| 海通运行详情 | 万象查看相应技术血缘/问题 | 定位 run/版本，不用 ER 逻辑线替代执行证据 |
| 海通对账差异 | 万象相关问题入口 | 带差异证据，目标不支持时提供结构化导出，不假装已建工单 |

接力载荷只传短 ID 与版本；详细上下文保存在共同仓储临时表中，不把密码、完整原始数据或任意 URL 放地址栏。返回 URL 限白名单入口。对象失效显示具体原因，不打开同名替代对象。

### 26.4 本期联调边界

目前上传的是海通 manifest，不是三个中心完整可运行源码及共享协议。本说明书设计出 SharedDataPort、ResourceGrantPort、LineageSink 三个接入边界；可以在独立海通 Mock 中运行，但“三中心真实共享和往返”必须在实际联调后验收。不能用三张相同 seed 的页面截图证明数据已打通。

同源 IndexedDB 可用于本地共享持久化；BroadcastChannel 只通知更新，不承载完整数据或认证。[R8][R9] 不同域名/端口场景必须另有明确桥接方案，不能声称自动共享。

### 27.1 分层职责

    ↓ 命令 / 查询

### 27.3 三种状态各司其职

| 状态类型 | 放置 | 规则 |
|---|---|---|
| 持久业务事实 | IndexedDB/共享仓储 | 任务版本、运行、账单、核销、样例版本是权威数据 |
| 查询缓存 | TanStack Query | 以工作区、对象/版本、筛选组成 queryKey；提交后按范围失效 |
| 编辑会话/UI | Zustand | 选中节点、临时表单、面板、草稿命令、保存状态 |

| 内容计算 | Worker | 接收冻结输入与 jobId，返回结果，不直接修改页面全局状态 |

查询失效后应按 key 重取，不把旧筛选的慢请求写进新筛选列表；React Query 的查询失效机制可承载这一过程，具体 key 和事务策略是本项目设计。[R11]

### 27.4 X6 适配层

`GraphAdapter` 负责 TaskDefinition 与 X6 cells 的双向转换、组件注册、节点数据更新、端口一致性、历史事务、选择同步和销毁。保留 X6 2.x 独立插件 import；业务服务不依赖 Graph 实例，便于单元测试。

向导编辑和图编辑都写统一领域定义；改变 layout 不重写任务业务版本。属性面板提交经过校验再进入一次命令事务，禁止“表单 state 已保存、Graph state 仍旧”的两份事实。

## 29. 本地 Mock、持久化与任务运行

### 29.1 Mock 的职责

不是为每页写一个静态数组，而是以同一份源样例、目标样例、任务定义、调度、转换和回执真实计算。来源/目标数据分别保存版本；接入执行改变本地目标样例，对账读取改变后的固定版本。没有成功写入时不能让目标统计先增加。

本期只使用合成业务结构和记录，不从真实数据库取数。示例可围绕节目备案、播出机构、许可证、播出排期和统计报送；保留业务含义，明确不声称来自国家广电总局真实数据。旧工作区的来源/标准不因初始化被覆盖。

### 29.2 建议场景数据（设计规模，不是完成数量）

| 数据 | 建议样例 | 检查目的 |
|---|---|---|
| 共享来源 | 保留已有 8 类品牌注册信息；实际读写能力按 Mock profile | 来源身份和能力分开 |
| 技术结构 | 12—24 张合成表/集合，含复合键和同名跨库表 | 表匹配与字段映射 |

### 29.3 事务、租约与失败

IndexedDB 内相关任务、状态、目标样例和证据在同一可验证事务提交；摘要计算放在事务外完成后，提交时再次比较数据 revision，避免 Worker 耗时使输入变化后覆盖新数据。事务失败保持原数据并显示未保存。[R8]

多个标签共享本地作业队列，通过持久租约 ownerToken 竞争领取；每次提交检查 token 和 revision，防止失联旧页面恢复后覆盖新结果。BroadcastChannel 仅使查询失效，真正内容从仓储读取。[R9]

浏览器关闭后不执行；再次打开恢复检查点。错过多个计划周期默认最多补一批并记录跳过数量，用户可显式创建其他窗口补跑。这个行为属于本地演示调度约束，不代替正式服务器调度。

### 29.4 有意义的失败状态

用确定性条件构造错误：重复目标键、非法转换、停用来源、未知组件、过期快照、缺回执、队列已满、已撤销授权。运行结果由这些条件决定；短时延只用于展示阶段，不随机掷骰决定成败。

存储配额不足、JSON 导入损坏、Worker 中止分别保留编辑内容和错误。不可用存储不静默退回内存并显示“已保存”。任务临时调试数据不得污染真实用户已有的本地工作区。

### 29.5 备份与迁移

本期海通有独立 schemaVersion 和中心域，共享对象保持原 ID；导入先做预检和引用验证，默认导入新工作区，避免覆盖另两中心数据。备份不包含真实密码。导入执行中的任务默认暂停，复核输入版本后才能恢复，不能一恢复就自动向目标写入。

如果未来收到原海通已有存储格式，应做专用适配和迁移标记；仅凭 package.json 不能编造“自动兼容原任务”。原文件保留，失败不产生半迁移。

## 30. 通用交互、异常、可访问性与性能

### 30.1 表格和表单

通用表格支持搜索、筛选、列设置、紧凑/舒适、固定名称/操作、导出当前筛选全部记录。默认每页 20，可选 20/50/100；对账差异默认 50。分页和筛选互相协调，减少数据后页码回有效范围。隐藏列不修改字段投影或授权。

每行主动作最多一个，其余更多菜单分常规与危险组。多行技术路径允许两行/Tooltip/复制，禁止页面横向撑开；表格自身横向滚动。表单错误定位到字段，复杂向导顶部显示错误数量；提交锁防重，失败不清空输入。

### 30.3 身份与权限视图

采用开发人员、运维人员、对账人员、复核人员的本地能力映射；不新增完整用户管理。发布、启动、核销和敏感导出有独立权限标识；只读查看也不暴露密码/完整原值。身份切换仅用于验证流程，不等于真实认证。

### 30.4 响应式与可访问性

至少覆盖 1920×1080、1670×940、1440×900、1366×768、768×1024、390×844；桌面补测 125%/150% 缩放和 DPR=2。画布桌面优先，小屏面板覆盖而不把节点字缩成 9px。Enter/Space 打开品牌切换，上下键选择，Esc 关闭；抽屉关闭恢复焦点。

颜色不作为唯一状态表达，图标按钮有可访问名称。placeholder 14px，不依赖极淡灰；必要帮助不能只放 hover。尊重 reduced-motion，暂停不必要动画。图表附可读数值表，不能只提供颜色块。

### 30.5 性能预算（待实测目标）

常规画布目标 100 组件/200 连接，多表用组节点而非展开数百表；大于此范围应记录设备和性能，不承诺无限规模。字段列表上千条采用分页/按需渲染，图更新只刷新变化节点。首版本地盘点建议单对象 10,000 条以内、总输入 50,000 条以内为体验测试范围；超过明确提示分窗，不将此当作正式引擎容量。

Worker 负责摘要/批量匹配，主线程保留进度取消；进度根据真实已处理/已知总数，无总量时用阶段状态而非虚假百分比。若引入虚拟化/图布局依赖，走第 2 章追加审批，不为达标偷偷升级版本。
