# 海通数据集成中心轻量版部署手册

## 安装包内容

| 位置 | 用途 |
| --- | --- |
| `frontend/` | 已构建的 NiFi 流程列表和画布，由后端提供静态访问 |
| `backend/` | 独立 Java 服务和运行依赖 |
| `db/init.sql` | 流程控制库的完整 H2 初始化脚本，首次启动自动执行 |
| `db/example-mariadb.sql` | 可选的联调建表和示例数据 |
| `drivers/` | 示例流程的 MariaDB JDBC 驱动 |
| `examples/` | Java 质检可执行 JAR 和源文件 |
| `application.env.example` | 安装参数样例 |

## 运行条件

- 海通运行机安装 Java 21，可以通过 `java -version` 检查。首次运行无需 Maven、Node.js、Nacos 或原平台数据库。
- 准备一个海通后端可以访问的 Apache NiFi。验收版本是 2.9.0，使用该版本完整发行包中的 Standard、MongoDB、JSON Record 和 DBCP 组件。建议为本应用建立专用父流程组。NiFi 服务账号需要读取组件类型、在父组下创建和管理子组、处理器、队列和控制服务的权限。JAVA 加工还需要 NiFi 的执行代码权限。 [Apache NiFi 下载](https://nifi.apache.org/download/)
- 准备业务 MongoDB、关系库及最小权限账号。数据库地址必须从 **NiFi 执行主机** 可达。JDBC 驱动和质检 JAR 要放在 NiFi 执行机能读取的位置。集群运行时，每个执行节点需要相同的绝对路径和文件，写入去重及多节点读取策略由部署方确认。

## 配置与启动

1. 解压 ZIP，复制 `application.env.example` 为 `application.env`。文件使用 UTF-8，每行填写一个 `名称=值`，值本身直接写入，外层无需引号。文件与数据目录权限限制到运行账号。也可通过进程环境变量注入同名配置。

   | 参数 | 值 |
   | --- | --- |
   | `HAITONG_ADMIN_PASSWORD` | 轻量版管理员 `admin` 的密码，至少 12 位 |
   | `HAITONG_STORE_KEY` | H2 文件加密密钥，至少 16 位且无空白字符，备份时单独保管 |
   | `NIFI_URL` | NiFi 根地址，例如 `https://nifi.example.net:8443` |
   | `NIFI_PARENT_GROUP` | 专用 NiFi 父组的 UUID。从 NiFi 画布地址复制。独立实验实例可使用 `root` |
   | `NIFI_USERNAME`、`NIFI_PASSWORD` | HTTPS NiFi 服务账号与密码。仅限本机测试 HTTP 实例可留空 |
   | `NIFI_TRUSTSTORE`、`NIFI_TRUSTSTORE_PASSWORD` | NiFi 使用私有 CA 时，填写本机可信 PKCS12 文件的绝对路径及密码 |
   | `HAITONG_BIND`、`HAITONG_PORT` | 默认 `127.0.0.1:8090`。远程使用时由同机 HTTPS 反向代理转发到此端口 |

2. Windows 解压到较短的可写路径，例如 `D:\haitong-flow`，在解压目录运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1`。Linux 运行 `bash ./start.sh`。前台运行时用 Ctrl+C 停止。长期运行可交由操作系统的服务管理器，运行目录设为解压目录。
3. 打开 `http://127.0.0.1:8090/`。用账号 `admin` 和配置的密码登录。也可检查 `GET /healthz`，预期得到 `{"status":"UP"}`。
4. 将示例中的 JDBC 驱动及 `quality-check.jar` 复制至 NiFi 执行机的专用目录。驱动路径和 JAR 路径在各自节点里填写，使用 NiFi 执行机的绝对路径。

正式环境使用 HTTPS 访问 NiFi 和海通服务。私有 CA 的信任库可用 Java 的 `keytool -importcert -storetype PKCS12` 生成。只给可信管理员开放海通登录，JAVA 加工会使用 NiFi 服务账号的权限执行所选 JAR。

## 数据备份和故障定位

- 海通启动时创建 `data/haitong-flow.mv.db`。停服后备份该文件，并分别保留原加密密钥和 NiFi 自己的流程配置、加密密钥及运行存储。单独恢复海通控制库只能恢复设计，执行仍需对应的 NiFi 流程组。
- 海通登录成功后流程部署失败时，检查 `NIFI_URL`、TLS、父组权限及组件是否存在。数据库连通性、JDBC 驱动加载、Java 进程错误可在「打开 NiFi」中查看组件公告与失败队列。
- 配置了调度的 NiFi 流程会在 NiFi 进程内运行。维护前在海通或 NiFi 停止相应流程，应用服务退出后仍可在 NiFi 管理这些组。
