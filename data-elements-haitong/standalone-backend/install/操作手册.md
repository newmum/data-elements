# 海通数据集成中心轻量版操作手册

## 创建和管理流程

1. 登录后打开「NiFi 流程」，选择「新建流程」并填写名称。
2. 点击画布上的添加按钮选择数据源。使用节点右侧的加号添加后继节点，也可用画布上的端口连线。双击节点编辑配置，点击「完成配置」回到画布。
3. 按顺序点击「保存」「部署」「启动」。部署会在配置的 NiFi 父组下创建一个独立流程组。使用「停止」管理当前组，通过「打开 NiFi」检查处理器、队列及公告。
4. 保存配置变更后，需要重新部署才会应用。重新部署会创建新组并替换旧组。先停止旧组并处理完旧队列。失败数据可从 NiFi 的失败连接检查和重放。

每张画布使用一个来源。来源默认单次运行，每次点击「启动」读取一轮。关闭来源的「每次点击启动只读一轮」后可指定周期。当前 MongoDB 读取每轮按配置的查询条件重新扫描，JDBC 读取每轮执行配置的 SQL。周期运行前，请配置来源筛选、MongoDB 更新键或目标库的去重策略。

## 示例一 · JDBC → MongoDB

1. 在联调用 MariaDB 执行 `db/example-mariadb.sql`，它创建 `haitong_validation` 下的来源表、目标表和 4 条示例数据。
2. 新建流程。添加「JDBC 数据源」，选择 MariaDB，填写连接地址、账号、密码、NiFi 主机上的驱动 JAR 路径。查询填写

   ```sql
   SELECT record_id, amount, status FROM flow_source ORDER BY record_id
   ```

3. 连接「MongoDB 写入」。填写 MongoDB 主机、端口、数据库和集合，示例使用 `haitong_validation.flow_input`。有认证时填写用户名、密码和认证数据库。按需设置更新键 `record_id`，按业务键匹配写入。
4. 保存、部署、启动。通过 MongoDB 查看 `flow_input`，预期有 4 条示例记录。

## 示例二 · MongoDB → JAVA 质检 → JDBC

1. 新建流程，从「MongoDB 数据源」读取前一流程的集合。查询条件可填写 `{}`。
2. 连接「JAVA 加工」。运行程序填 `java` 或 NiFi 执行机的 Java 21 绝对路径，JAR 路径填 `quality-check.jar` 在 NiFi 主机上的绝对路径。样例无需额外参数。
3. 连接「JDBC 写入」。选择 MariaDB，填写 JDBC 连接参数和驱动路径，目标表填 `flow_target`。保存、部署、启动。
4. 目标表应有 `validation-01` 和 `validation-02` 两条记录，`quality_status` 为 `PASS`。示例会拦截负金额和非法状态两类数据。

`examples/QualityCheck.java` 可作质检模板。NiFi 把 JSON 对象或数组传给 JAR 的标准输入，诊断信息写标准错误。样例同时支持 MongoDB Decimal128 的 Extended JSON 表示，规范化通过记录的状态值。混合批次只向下游输出通过记录。全批未通过时，样例向标准输出写回原批并以状态码 2 退出，NiFi 将该输出送入失败队列。自定义 JAR 也应明确处理失败输出。替换 JAR 后，请用小批量样例先核对字段名和数据类型，再运行定时任务。 [NiFi ExecuteStreamCommand](https://nifi.apache.org/components/org.apache.nifi.processors.standard.ExecuteStreamCommand/)

修改样例规则后，可以从安装目录用 JDK 21 编译，并把新类更新到样例 JAR 的副本中。Windows PowerShell 和 Linux Bash 均可执行以下命令。部署时使用新的 JAR 文件名，方便对照运行版本。

```sh
mkdir quality-build
javac --release 21 -encoding UTF-8 -cp "backend/lib/*" -d quality-build examples/QualityCheck.java
cp examples/quality-check.jar examples/quality-check-custom.jar
jar --update --file examples/quality-check-custom.jar -C quality-build QualityCheck.class
```
