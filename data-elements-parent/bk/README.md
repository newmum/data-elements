# 布控引擎（可选后端功能）

此目录集中保存布控引擎的 Java 源码、测试和 `surveillance-match.json` 组件清单。Java 包名、HTTP 路由、Kafka 业务配置和数据库表名保持兼容。

本次整合核对了旧后端仓库的 rfl 提交 `79dce09`（布控与品高）、`6409458`（预警引擎）和 `0cb5652`（资源 Topic 修复）。这些提交对应的功能已经存在于当前工程；移动时保留当前工程后续的租户隔离、批量查询、分页和排序修复，不用旧版本覆盖新版本。

## 构建与移除

- 目录存在时，后端 `pom.xml` 的 `bk` profile 自动加入本目录源码、测试及资源。
- 临时排除：在后端目录运行 `mvn "-P!bk" clean package`。
- 同时排除两个可选功能：`mvn "-P!bk,!pinggao" clean package`。
- 永久移除：删除后端的 `bk/` 目录后重新执行 `clean package`。文件激活条件失效，不需要修改核心 Java 代码。必须执行 clean，避免旧 class 留在产物目录。

NiFi 模板和流程分组行为由本目录的 `SurveillancePipelineExtension` 提供。核心画布只依赖通用扩展接口；移除此目录后不再注册布控模板和布控专用分组规则。

已有业务数据、数据库完整结构定义及前端布控入口不随源码目录删除而删除。如需彻底下线，还应停用对应前端入口和已部署 NiFi 流程；不要为了移除代码删除业务表。
