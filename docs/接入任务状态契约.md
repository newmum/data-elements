# 接入任务状态契约

适用于接入任务页面及 `POST /ods/dataAggPage` 的 `viewLevel=table` 分支。

## 字段与枚举

复用现有请求/响应字段 `accessStatus`（字符串）和响应字段 `accessStatusText`。该字段由查询接口计算，不是数据库的独立状态列；登记进度 `asset_status`、登记流程 `flow_status` 和历史任务状态 `task_status` 继续承担各自原有职责。

| accessStatus | accessStatusText | 口径 |
| --- | --- | --- |
| `0` | 待接入 | 当前表没有直接发起且来源、目标均在当前租户和角色可见范围内的有效任务。 |
| `1` | 已接入 | 本表直接发起的至少一个授权任务，经当前 NiFi 快照确认仍有运行组件或正在结束的活跃执行。 |
| `2` | 待审批 | 为第五步接入申请预留。本轮未引入申请单，筛选返回空列表；后续申请业务提供权威审批事实后启用。 |
| `3` | 待启动 | 本表已有授权任务，已确认没有运行任务，包括尚未部署的任务、已停止及其他非运行流程。 |
| 空字符串 | 状态待确认 | 本表已有部署标识，但 NiFi 快照不可用，暂时无法确认是否运行。仅在“全部”中显示，不推断为已停止。 |

筛选顺序为全部、待接入、待审批、待启动、已接入。`all` 或未传入表示全部。

## 判定与分页

- 状态按本表的直接来源任务计算。展开区继续展示授权的级联链路；下游正在运行不会把已停止的上游来源表标为已接入。
- 每次分页只读取一次 NiFi 根快照。已接入、待启动在 SQL 筛选前读取并复用于返回行状态；其他页签在查询结束后读取，避免长查询返回旧版本后连续补刷。运行组标识以每组最多 500 项绑定到 SQL，不拼接外部标识文本。
- 状态条件在数据库分页和总数计算前执行，不能先读取一页再按运行状态过滤。任务、来源表、目标表和画布均保留当前租户与有效记录条件，来源、目标数据源均校验角色范围。
- 有效画布的 `nifi_process_group_id` 优先；旧任务无有效画布时使用 `data_access_agg_task_t.process_group_id`。历史成功批次、旧启动标记及画布生命周期值不能替代实时运行结果。
- 页面状态列使用接口返回值。任务数量仅控制查看/创建任务操作，不再把“有任务”直接显示为已接入。

## 后续审批业务边界

`2` 仅预留状态契约，本轮没有创建审批单、审批写接口或新的数据库列。后续明确申请对象、重复申请、撤回/驳回、审批通过与任务创建顺序后，再确定持久化结构和关联关系。正式引入待审批记录时，任务启动入口必须根据权威审批单校验通过状态；前端按钮限制不能代替该服务端规则。

分发任务本轮仅同步实时标签布局和搜索提示，保留既有分发状态契约。旧数据源视图分支的兼容返回也保持原口径。
