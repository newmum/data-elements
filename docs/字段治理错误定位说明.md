# 字段治理运行错误定位

适用于共享字段内核及 NiFi 扩展 1.1.21。编辑协议仍为 `schemaVersion=2.0`，执行计划协议仍为 `planVersion=1.0`。

## 每条错误的内容

`errors[]` 保留原有的 `code`、`ruleId`、`stepId`、`message`。`message` 按“记录位置 → 来源字段及值 → 目标字段 → 失败步骤及问题值 → 约束 → 原因 → 处理结果”组成，可直接在 NiFi 内容查看器中阅读。

新增的结构化信息如下：

| 属性 | 含义 |
| --- | --- |
| `sourceFields[]` | 本次实际执行时访问的来源字段，含 `name`、中文 `comment`、原始 `value`、`missing`、`truncated` |
| `targetField` / `targetComment` | 当前失败规则对应的目标字段及中文注释 |
| `operator` | 失败步骤的算子；输入为 `INPUT`，最终目标检查为 `TARGET_VALIDATION` |
| `inputValue` | 当前规则开始处理时的输入，可能已经来自输入表达式或其他目标规则 |
| `problemValue` | 真正失败时的值；可以是转换后的中间值或未匹配的单个字典编码 |
| `valueTruncated` | 输入值或问题值的显示摘要是否经过截取 |
| `expected` | 目标逻辑类型、精度、小数位数、长度、可空性及当前步骤的要求 |
| `reason` | 保持稳定错误码所对应的具体失败原因 |
| `effect` | 本条转入 invalid，或整批保留并转入 failure |
| `recordIndex` | 从 0 开始的原始记录序号，与外层 `inputRecordIndex` 一致；人类可读描述同时显示从 1 开始的位置 |

字段注释来自当前已授权登记表的 `db_table_column_t.column_comment`，随 Schema 批量读取并装入计划，不按错误行或字段再次访问数据库。编译时刷新有登记引用的旧 Schema 注释。没有 Schema 引用的旧任务发布时，复用当前画布来源/目标组件已有的字段快照补充注释，不增加读取、不附加类型约束；多个来源的同名注释冲突时不猜测。独立规则也可使用 `input.comment`、`target.comment`；旧规则兼容 `fromLabel`、`toLabel`。确实没有注释时显示“未登记中文注释”，不按字段名猜测业务含义。

条件规则只报告已执行条件及分支实际读取的字段，不把未执行分支的值当成问题值。表达式尚未生成结果时，显示已访问的来源字段；不会虚构一个计算结果。缺失字段、NULL 和空字符串分别表示。

## 示例

假设来源 `MAPX`（经度）的值为 `119.379023855114`，目标字段 `LONGITUDE`（目标经度）为 `DECIMAL(8,2)`，错误描述包含：

> 第2条记录（inputRecordIndex=1），规则=longitude-rule；来源字段：MAPX（经度）="119.379023855114"；目标字段：LONGITUDE（目标经度）；规则输入值="119.379023855114"；步骤=target（目标类型及约束校验）；问题值="119.379023855114"；要求：DECIMAL(8,2)，允许NULL；原因：小数位数12超出目标DECIMAL(8,2)可精确表示的范围；请扩大目标小数位数或显式配置舍入规则；结果：本条记录转入 invalid，不写入 success；其他有效记录继续处理。

`trim → CAST` 失败时，来源原始值和 `inputValue` 可以是 `"  abc  "`，`problemValue` 则为 `"abc"`。多值字典输入为 `"A,UNKNOWN"`、部分未命中策略为 ERROR 时，问题值显示 `"UNKNOWN"`。

## 输出与兼容边界

- `ROUTE_INVALID` 的完整详情位于受控 invalid 内容队列，原始记录仍在外层 `record` 中。旧的错误重放读取器允许新增属性，不增加错误包嵌套。
- `FAIL_FLOWFILE` 保持整批原文、原事务语义。failure 的 `ht.error.message` 提供行号、字段、规则、步骤及原因，值用 `***` 表示；原值仍在受控内容中。
- 平台预览沿用敏感字段与字典结果的遮蔽规则；新增错误文本不能绕过原有预览遮蔽。
- 单值结构化摘要最多显示 512 个 Unicode 字符；超长值带明确标志，完整原值在 `record`。人类可读 message 中的长值摘要更短，字段明细保留较完整摘要。正文最多列出 8 个来源摘要，结构化列表最多列出 32 个实际来源；这是错误显示预算，不限制表字段探查。
- 新增定位信息不改变成功/invalid/failure/retry 路由、字段回退策略、字典缺失策略或数值舍入策略。整数非零小数位和整数范围溢出给出不同原因，不静默截断。
- 读取器、写出器或外部数据库服务在取得记录前失败时，不能可靠归因到某条数据的某个值；此类错误继续提供已知的系统错误码和安全说明，不捏造字段位置。

## 更新要求

先安装与目标 NiFi 版本相符的 `haitong-mapping-nar:1.1.21`，再更新包含同版内核的共享后端。已有原生处理器仍使用原 Bundle，不会因新增 NAR 自动升级；通过受控字段节点升级或保存发布采用新版本，并在需要时重新加载登记 Schema 以携带中文注释。历史错误内容不会自动重写。

开发验证使用 NiFi 2.9.0；NiFi 2.11.0 提供匹配 SDK 构建及组件测试。实际业务流程的队列、水位与 Bundle 不作为测试对象批量改写。
