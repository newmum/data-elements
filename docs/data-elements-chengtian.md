## 低代码日志管理

日志管理已收口为一个菜单、一个共享低代码页面 `log-management`，顶部按权限显示登录日志、操作日志、接口日志、安全日志、导出日志、归档日志六个页签；日志策略为同一栏右侧的配置按钮，点击弹窗配置各类别的保留天数与成功请求采样比例。源码唯一位于根 `lowcode/09.系统管理/09.日志管理/日志管理(log-management).vue`，原八个入口/统计组件已核对引用并软删除，不保留第二份页面业务代码。页面仅含页签与配置入口、查询栏、表格和分页，无顶部标题或统计卡；表格以序号、人员、时间、功能路径与具体操作为先。页签复用节点配置所用 Element Plus 页签及系统主题；表格和分页直接使用接入任务相同的全局 DataTable、Pagination，搜索栏沿用接入任务输入框和查询按钮样式，不保留独立的字号、行高、表头及状态标签覆盖。

查询、排序、导出、归档、冻结与权限契约见[公共日志实现说明](data-elements.md#logging-design)。通用参数快照链路已在已授权的本机 86 后端换包重启，所选 31 个 class 与当前 Maven classes 字节一致；新增关键词条件 Magic 函数及唯一日志组件已发布，组件两级缓存刷新、运行回读及函数冷加载脚本检查通过，所选资源无未发布差异。86 四行业 24 列 DDL、三方言四库原生验证 124/124 与五库导出已完成；14 演示及生产不在升级范围，IDAAS 参数能力与授权不扩大。

行业操作／接口日志以单个完整 `parameterKeyword` 替代固定参数下拉，最长 200 个 UTF-16 单位，与普通关键词、日期和结果按 AND 组合；旧成对精确参数继续兼容，但敏感原文不得先掩码再匹配旧索引，该旁路修正已测试并部署。详情按 `path/query/body/verified` 展示安全快照、六种采集状态及 `false/0/null` 的真实类型，支持树／JSON、脱敏复制和完整字面高亮；不从历史正文补造数据。旧数据技术入口仅对白名单再次脱敏并保留额外 `legacy`／来源未记录，不自动重建历史。默认查询 7 天、最大 90 天；列表不逐行补详情，批量一次预取后逐 ID 授权并按输入序返回。CSV 为摘要，防前导空白公式并回退已归一历史时间；JSONL／新归档保留安全快照，离线归档关键词检索不扩展，IDAAS 不新增此筛选。

真实页面在 1440／390 像素无横向滚动，20／100 行各一次列表请求，嵌套字段、`false/0/null` 与 `businessCode` 可查，敏感测试值详情无原值且检索为 0；相同显式筛选的 CSV 摘要与 JSONL 安全快照各 1 条。跨真实物理库记录详情和混合 ID 整批拒绝，未写业务数据或修改授权。共享页面、Mock 与澄天合跑 125/125，澄天生产及 Mock 构建通过；后端及其他宿主回归结果见公共说明，不据此宣称全仓通过。

## 工程概览与使用

`data-elements-chengtian` 是澄天数据中台的 Vue 前端工程，面向管理、配置、流程操作、低代码表单和数据要素业务场景，基于 Vue 3、Vite 7、TypeScript、Element Plus、Pinia、UnoCSS、VXE Table 和 form-create 构建。

### 人大金仓部署与切换

本机澄天租户 `2084109831682699267` 的数据源键仍为 `chengtian`，业务库切换为 `192.168.175.32:54321/baseline_ct`，schema 为 `public`。采用独立数据库加 `public` 的布局，保留现行无 schema 前缀的业务 SQL，避免为每个脚本增加库名或模式名。控制库仍是 MySQL `baseline`，Magic、低代码及中央身份控制资源继续从控制库加载；其他行业绑定保持原配置，前端仍通过 3000 代理到共享后端 8088。

Nacos 新增完整配置 `data-element_ct.yml`（Namespace `data-element`，Group `DEFAULT_GROUP`），包含基础与开发覆盖的有效配置，只改变澄天连接及默认租户。原 `data-element.yml`、`data-element-dev.yml` 保留。受限运行环境提供 `TENANT_CHENGTIAN_DB_USER`、`TENANT_CHENGTIAN_DB_PASSWORD`，不把脱敏配置中的占位符当作实际凭据发布。专用配置应单独导入，不能再在它后面叠加旧开发配置，否则旧连接会覆盖金仓：

```text
NACOS_CONFIG_IMPORTS=optional:nacos:data-element_ct.yml?group=DEFAULT_GROUP&refreshable=true
```

本机通过 `db/nacos/local.properties` 选择该导入以及对应的工程外受限环境。根 `start-data-elements.cmd`/PowerShell 默认启动及仅传 `-Restart` 的调用使用所选配置；显式传入构建、JAR、Nacos profile 等参数时使用原通用启动分支，须同时明确专用 import 和所需环境。后端使用既有持久身份加密密钥，不生成替代密钥。金仓 JDBC 连接固定 `public` 和空字符串保留设置，具体类型及 SQL 适配见[数据库原生表示](data-elements.md#database-schema)。

迁移按以下顺序执行：

1. 只读核对运行绑定、源码与共享资源，备份原 Nacos、受限运行配置及当前运行 JAR。
2. 新建 UTF8 的 `baseline_ct`，从当前 MySQL `chengtian` 一致性快照复制业务数据，保留原 ID、租户、账号密码校验值、角色及关联。完成全部原生索引、外键、生成列、注释和更新时间规则。
3. 独立验证实例使用新配置，禁用验证实例的后台任务，验证真实登录、租户会话、业务分页和批量权限边界。实际应用不要求复制或重写共享 Magic/低代码脚本。
4. 停止本机正式与验证后端后，使用 `kingbase-db.py reconcile-staging --apply --snapshot <新的受限目录>` 将尚未开放的金仓目标按主键收敛到最终 MySQL 快照。工具拒绝在 8088/18089 仍监听时执行；只变更目标，不回写源库，按外键依赖排序并在一个事务内提交。随后 `verify --snapshot <相同目录>` 对所有非生成列执行类型化全内容摘要校验。
5. 使用审阅过的适配包和专用配置恢复 8088，验证登录、`/sym/tenant/current`、实际数据源健康及常用页面；更新私有资源定位、五库原生结构与清单。校验报告仅存 `logs/kingbase-tenant-migration/`，含业务记录的恢复快照保存在仓库外受限目录。

原 MySQL `chengtian` 保留为切换前恢复来源。新库开始接收业务写入后，回切必须先处理金仓新增/修改的数据；不能直接换回旧配置造成写入丢失。专用配置不覆盖原 Data ID，恢复材料也不进入 Git。新环境建库入口为 `db/increments/000001_chengtian_kingbase_database.kingbase.sql`，完整空库对象为 `db/baseline_ct/init.sql`；已有业务库禁止重跑完整初始化。

本机切换前最终快照为 161 张表、354,415 行，逐表类型化内容摘要全部一致。正式服务上，澄天和公安真实登录及租户归属已验证，数据源、数据表、接入和分发任务 20/100 行分页共 20 项最终接口检查通过；澄天浏览器重新登录后数据源页正常加载。Java 兼容层同时将无长度 `CAST(... AS CHAR)` 转为 TEXT，避免金仓默认 CHAR(1) 截断关联 ID。本次共享资源只为 `04.数据汇聚分页接口` 补 `import log`，修复慢查询超过一秒时日志对象为空的既存故障；已单文件发布到控制库并热刷新、回读，查询和权限条件未改，低代码 Vue 未改动。行业后续结构对齐及旧表退役以公共主文档的当前结构章节为准。

任务管理的表视图请求 `viewLevel=table` 在金仓使用 `WITH RECURSIVE`，将画布毫秒时间戳转换为带毫秒精度的时间，再按有效链路的最新修改时间稳定分页。页面切换 20 和 100 行各触发一次分页请求，脚本测试在两种页大小下的 SQL 次数一致，并覆盖跨页顺序、空时间、同值排序和外租户记录。资源申请分页按当前租户及申请人读取关系主表，批量补齐目录、申请扩展字段和流程任务，消除列表对申请索引的依赖。20 和 100 条有数据的脚本测试均执行 6 次读取，线上账号的空列表和状态筛选已验证。金仓连接池同时适配目录和申请写入中使用的文本版本号递增，旧空值或非数字版本从 1 开始，数字版本递增。两条 Magic 资源已发布并回读，重启后页面复验通过。

### 接入任务与分发任务筛选

接入与分发任务共用 `data-convergence` 的树、筛选、表格和任务抽屉。分发入口 `data-convergence-hive` 显式选择分发模式，两端分别沿用原路由、默认排序、状态页签和服务端分页、树统计接口。分发模式保留“驳回修改”和分发建表配置。

两个任务页将实时连接状态放在左侧树标题旁；右侧查询框前的数据源类型筛选与数据源管理共用 `datasource-type-filter`，统一图标、名称和数量角标；筛选名称精简为“全部类型”“人大金仓”“Elasticsearch”“其他类型”，任务页控件宽164px，状态页签保留在左侧；默认提示为“请选择数据源类型”。类型与搜索组成按内容占宽的右对齐筛选组，换行后同样贴右；任务表操作列宽98px，操作内容保持居中。切换树节点保留类型、任务状态和关键词，查询与类型清除均重置到第一页。

`/ods/dataAggPage`、`/ods/hiveTargetPage` 的表级分页支持 `datasourceType` 和 `includeDatasourceTypeStatistics=true`，同一响应返回 `datasourceTypeStatistics`。任务页角标按当前租户有效、已登记且属于本任务类别的数据表记录计数（unit=table），跟随树选择、表名关键词和任务状态，自身类型条件不参与角标计算；未选类型时“全部类型”与分页总数一致，选择类型后该类型角标与分页总数一致。数据源管理继续按数据源个数统计。接入任务排除 ODS 绑定库，分发任务只保留 ODS 绑定库。显式选择空部门或空业务系统返回零，不扩大到全部范围。统计与分页共用同一 SQL 条件，额外一次按数据源分组的 COUNT 聚合，归入各类型，不按表行或类型发起补查。兼容驱动别名及推送、上报、代理接入方式；失败显示未知统计并提供重试，过期响应不覆盖新筛选结果。原有当前租户、有效候选与任务关联校验保持生效。

### 物化建表字段类型

接入任务和分发任务共用 `access-apply` 物化建表组件。字段类型候选优先使用当前租户 `tableColType` 字典，并在字典缺失时补充 CLOB、VARBINARY、FLOAT、DOUBLE，按类型值忽略大小写去重。选择 CLOB 后，字段预览和提交沿用既有 `dataType` / `columnType` 同步及服务端目标方言转换；支持 CLOB 的目标保留大文本类型，其他目标使用其对应大文本类型，不降为有界 VARCHAR。不新增按字段查询，也不修改现有物理表或租户字典记录。

同一来源的多个目标通过 `/ods/createTapleApply` 一次提交，最多 20 个。抽屉显示每个目标的完成、失败、未执行或待核对状态。再次提交会重查未完成或配置已修改的目标，保留配置一致的已完成项；所有所选目标成功后，才把完整目标 ID 交给任务画布。部分完成或响应未知时刷新任务列表，抽屉保留当前配置和结果。

组件管理器保留接入与分发实际使用的 `access-apply`。退役的同名副本 `access-apply_1` 经共享编译资源、四个行业的菜单、应用页签和动态表单引用核对后软删除，原记录保留回退所需的源码和编译内容。

复用 Hive 已有表时，先展示缺失分区及存储位置，整批预检通过且用户确认后才补齐缺失分区，再核验实际目录。显式删除非 Hive 已有表并重新物化前也会先预检整个建表请求。两类确认仍采用对应的目标操作，最后以一次批请求提交物化。

### 机构与用户维护

组织机构保存、移动、重命名、启停和删除使用当前租户内一次有界机构预取，最多5000条；使用运行版 Magic `Where.page(size, offset)`，不调用其不支持的 `limit()`。机构脚本使用驼峰结果映射，保证 `parentId`、`orgPath`、`serialNumber` 的读取和写入一致。移动或重命名同步子孙路径，启停支持状态级联；操作者从会话取得，写入条件显式保留当前租户。排序最多1000个ID，一次预取后逐ID核对租户、有效记录及同一父机构，全部校验通过才写入。删除前一次检查整棵子树的有效用户关联，有关联用户时应先调整用户所属机构，避免悬空关系。

用户账号与现有表单保持一致，非空且不超过50个字符，支持数字、短账号及中文；同租户有效账号仍检查大小写及首尾空格归一后的唯一性。所属机构必须属于当前租户且有效。编辑、启停保留未提交的资料、照片、密码及主职机构；启停仅提交ID和状态，继续禁止停用或删除当前登录账号，并在停用或改密后撤销原会话。用户机构筛选通过分页SQL内的 `EXISTS` 关联完成，不先加载机构全部用户ID；当前页角色与主职机构统一批量查询，关系表与角色表也显式校验当前租户，列表不返回密码摘要。页面保留既有布局，接口错误由统一请求层显示，局部提示不覆盖已显示的具体原因。

用户新增、详情表单的所属机构选项复用本页面当前租户的机构树，打开表单时先更新选项再回填机构ID；机构树异步加载完成也同步已打开表单。不使用长期缓存的 `org` 字典，避免刚新增或改名的机构在详情中不回显；该处理不增加按用户行或机构项补查。

<a id="overview--构建优化说明"></a>

### 构建优化说明

- 生产环境不加载 Vue DevTools。
- 主要第三方库已拆为独立 chunk：Vue、Element Plus、ECharts、AntV、VXE Table、ExcelJS、form-create、Ace Editor 等。
- 低代码设计器组件采用异步加载，减少首屏主包体积。
- 组件全局注册只保留实际使用的文件预览入口。旧知识库 Word、PDF、Excel 预览包装及对应 `@vue-office` 依赖已清理，通用表格导出仍使用 `exceljs`。
- Babel Standalone 在首次编译 TypeScript 低代码组件时按部署基路径加载，并发编译共享一次请求，失败可在编辑器内重试。普通业务页面和 JavaScript 组件预览无需加载该脚本。
- 登录后先生成当前用户的授权路由，再按实际页面加载低代码组件。工作台首包只含 `my-workbench`、`global-nav`、`shopping-car`。应用壳的静态页面只读取后两项，独立登录页无需组件包。接入任务和分发任务共用 `data-convergence` 入口包，包括导航、购物车、两个列表入口、物化建表抽屉和任务画布。同一会话内切换这两个入口无需再下载组件。进入数据表或数据源详情、打开需要完整组件的登记弹窗时，按原流程读取并复用同一会话的全量包。
- `POST /sym/component?action=runtimeBatch` 在共享组件缓存的一次快照中按入口名筛选。小包签名对应已核对依赖的编译脚本。编译脚本变化、组件缺失或名称冲突时，同一次响应返回全量包。入口包中必要组件在浏览器注册失败时，加载器尝试一次全量包。更新签名前须重新核对首屏依赖、动态入口及登记回退。编辑器的显式刷新可替换当前注册版本。
- 整页刷新和首次打开时，HTML 启动页、路由准备和低代码组件加载使用同一套带当前平台 Logo、名称和进度条的启动动画。导航就绪后，低代码组件的加载提示在主内容区显示，组件就绪即替换。首次路由资源加载失败时提供“重新加载”。动画遵循减少动态效果设置，各业务区域继续显示自身的数据加载和失败重试状态。真实模式和 Mock 共用这套页面加载提示。
- 菜单高亮、侧栏及主内容以已确认的路由为准。路由切换时直接替换旧页面，并保留列表与详情往返的缓存。尚在加载的低代码页面先显示统一的 Logo 加载动画，组件就绪后直接显示正文。

#### 页面接口返回 No static resource

#### 业务系统登记只显示步骤条，表单为空

先核对 `/sym/tenant/current` 的实际租户，再核对 `/sym/form?action=get` 的 `env` 与该租户 `sym_form.env`，不要仅凭前端工程名判断业务库。澄天租户 `2084109831682699267` 使用 `baseline_ct.public`，前端环境标识为 `CHENGTIAN`；公安租户 `2084109831682699264` 使用 `baseline_ga`，表单环境仍为 `公安`。澄天迁移保留的 12 份有效表单原环境值为 `公安`，已在限定租户、旧环境和有效状态的事务中改为 `CHENGTIAN`，保留记录 ID、表单名称、规则及辅助配置，并校验这些内容的前后摘要相同。公安表单无需修改，不把公安配置重新覆盖到澄天。

澄天专用部署改变默认租户时，还须保持历史 Elasticsearch 索引的固定归属。`es.tenant.legacy-tenant-id=2084109831682699264` 明确原无租户后缀索引属于公安；澄天使用 `elements_dataassets__tenant_2084109831682699267`，不随 `data-element.tenant.default-tenant-id` 改变而接管公安索引。旧部署未配置该新属性时保留原默认租户行为；关闭 `default-tenant-uses-legacy-index` 时所有业务租户使用独立索引。该项需要配套后端 `EsProperties` / `EsCommonService` 版本，不能只改 YAML 后宣称已生效。验证时比较列表记录的 `tenantId`、主库真实记录 ID 和详情回填；不得在归属尚未确认时重建或清空历史索引。

<a id="asset-workbench"></a>

## 数据资产工作台

共享 `my-workbench` 的概览、事项分页和导出入口分别为 `POST /dst/statistics/workbench/overview`、`/items`、`/export`，集中在 Magic 编辑器“数据盘点 / 盘点统计 / 工作台统计”分组。概览支持 `section=registration|governance|health|tasks|changes`，省略时保留完整响应以兼容已有调用。首屏固定并行读取这五个区域，各区域返回后立即更新自己的指标、骨架和错误状态，不等待全部完成；失败仅在所属区域提供重试。授权与采集差异查询复用通用函数 `workbenchData`、`workbenchChanges`，不新增 Java 统计业务服务。导出保持现有Excel列结构，复用概览的授权快照去重和接入任务范围，每批最多100个来源；原公共导出接口继续兼容其他调用方。

表事项 `kind=tables` 使用结构化查询。先按租户和角色筛选有效数据源，再按来源及表名小写选取代表行，依次优先已标注、字段较多、较新和较大表 ID。搜索、登记状态、业务类型和稳定排序均作用于代表行。处理清单先一次核验全部原始表 ID，失败时整批拒绝，成功后再应用列表筛选。20/100 条非空表事项分别为 3 次应用查询，含处理清单时为 4 次，另计身份范围解析。总数为零时 `list` 为 `null`，超出非空结果的末页时为 `[]`。保留达梦分页既有的绝对行号 `rowId`。

来源事项 `kind=sources` 复用表事项的租户授权与代表表规则，在数据库聚合并分页。探查阶段同时核对代表表有无和最近有效采集任务状态；字典、业务阶段按对应类型检查已保存的历史登记标记或已完成状态；审查阶段检查来源登记状态。未采集来源的表数和标注数显示为 0，按这些统计排序时仍将缺失统计排在末尾。20/100 条非空来源事项均为 3 次应用查询，空集或越界页均为 2 次，另计通用身份解析。分页沿用表事项的空返回和达梦行号。

只有当前认证应用中有效的系统管理员角色 `admin` 可见、可调用全局视图。其他应用的同名角色不授予权限；警种管理员与登记员默认“我负责的”，继续遵循既有 `ORG` 或 `OWNER` 数据范围，角色范围为 `ALL` 的用户在“我负责的”进一步限制本人创建的数据源。租户来自认证上下文，前端不能传用户、部门或租户扩展权限。批量处理清单最多100个表ID，读取前整批核验，存在跨租户、失效或无权ID即拒绝。

标注和登记使用当前有效数据源、表快照，按数据源与不区分大小写的表名消重，优先保留标注及字段信息完整的记录。已标注为 `annotated=1`，登记完成为 `asset_status=2`，未登记完成包含其他状态。字典、业务和日志分类统计仅计算登记完成的表，与数据源管理卡片的“已纳入登记（状态大于0）”分开表达。五步进度分别统计已探查来源、已标注表、全部标注且字典配置已保存来源、全部标注且业务/日志配置已保存来源、结束登记来源；无该类型表不阻塞相应配置阶段。业务配置完成依据保存阶段标记或已完成登记，不能仅因配置JSON非空视为完成。

登记总数与业务类型通过同一条SQL复用消重快照，任务总数与前五项共用一次任务范围扫描。非登记区域使用同一授权条件的轻量CTE，不为统计无关字段反复解析治理JSON；不引入统计缓存，不连接来源库。

字段治理先从当前租户和角色可见来源选取同名表代表行，再统计已保存配置中的统一格式字段、启用且具有翻译 SQL 的字典字段，以及已保存业务配置中的时间戳覆盖率。一次结构化读取同时检查预算，最多 20,000 份配置和 67,108,864 个数据库原生 `LENGTH` 单位。超出任一上限时数据库只返回一条标记。金仓对可验证的 JSON 形态只返回所需标志和计数，含重复键、特殊转义、非标准语法或不支持类型的历史配置仍交给 MagicScript 原样解析。其他方言也沿用相同的解析。异常或超限时页面显示静态参考标识并说明原因。连通和采集展示最近保存的检查/任务结果；未提供连接信息的数据源显示“未提供连接”，不按历史失败标志判为连接异常。接入任务沿用有效来源、目标、ODS分类及角色授权口径，运行状态来自平台最近保存的流程状态；有流程记录时优先采用流程状态，只有旧任务无流程记录时才回退历史任务状态。任务详情展示最近监控反馈、排队/输入/输出数据包（FlowFile）数量、线程、估算延迟及启动结束时间；数据包不当作表记录行数，缺少监控值时不填零。工作台打开和刷新均不连接来源数据库或逐表探查。

变更统计以授权有效表快照ID及来源建立白名单。新增数汇总每个授权来源最近一次成功探查的 `added_count`，明细按来源展示新增数并进入第二步办理；作业没有新增表关联明细时不能按创建时间猜测具体表。源端缺失清单来自同一成功作业的 `deleted_detail`，逐ID及来源核验；源端未匹配不等于已经确认物理删除。新增汇总行和逐表复核行统一搜索、稳定排序后服务端分页，因此分页记录数与涉及表总数含义不同，抽屉内明确说明。单次最多60000个有效快照、10000个缺失表，每页最多100条；差异记录格式异常或超限时显示明确原因与静态参考标识，不冒充真实零值。本组统计不依赖ES，不主动探查来源数据库。

结构修改差异目前仅保存在一次探查的用户临时视图中，没有完整持久化记录，也没有现用流程持续维护的全局修改投影，不能把检索空结果当作修改数为零。修改数按用户要求保留静态参考；卡片标记“部分静态”，主数仅统计已记录新增与源端缺失，不把静态修改数混入真实总量，修改明细页说明限制。

登记异常必改完整结论及占比、驳回后的待整改表与来源/历史清单、综合健康评分、智能建议置信度尚无完整持久化依据或评分算法，保留原型静态参考并就近标识。导出的独立登记完成时间尚未记录，继续留空，不能用更新时间代替。问题示例不冒充工单；其入口先选择真实授权来源，再进入登记审查。待标注处理清单为本次临时选择，逐项办理使用现有登记工作台，不伪造后台处理成功。视图切换无顶部提示；查询失败在对应区域提供重试，旧响应不能覆盖新视图。

工作台标题下不再展示额外的任务状态口径说明行及口径弹框入口。首次读取、刷新和切换范围时，各区域独立显示并移除骨架屏；已完成的卡片可直接操作，字段治理与业务类型分布分别加载，静态参考在可信范围确认后显示，占位沿用卡片结构并尊重减少动态效果设置；不再用整页加载遮罩遮挡标题和操作区。“数据表标注情况”跳转 `/datasource-manage/index?filter=unannotated`，“数据表登记情况”跳转同页 `filter=incomplete&metric=tableIssues`，分别选中“待标注”“未完成”列表筛选。数据源管理只读取白名单中的 `filter`，历史 `metric` 参数不影响筛选。筛选不改变服务端租户及角色范围，也不新增请求或逐行补查。

数据源管理搜索框前提供可搜索、可清空的“选择数据源类型”下拉。选项、选中值和卡片共用类型图标及配色：推送绿色、上报紫色、代理/API及通用图标蓝色，品牌SVG保持其自身颜色。MySQL、Oracle、人大金仓等使用统一类型别名，推送、上报、代理按卡片的接入方式单列，保留未知实际类型及标准零数量选项。类型角标来自服务端已归类的 `typeCounts`，原始 `dbTypes` 用于补充未知类型的名称；原始 `receive` 等内部标识归入“数据推送方式”。切换或清空类型后按当前其他筛选重读第一页。

数据源管理的顶部工具栏后直接显示组织树和数据源列表。列表调用 `/dst/database/departmentDataSources` 的 `mode=cards`。当前租户和 ALL/ORG/OWNER 范围下，先应用组织、业务系统、关键词、状态和类型筛选，再按更新时间及唯一标识稳定排序和分页。请求中的 `appId` 只筛选登记的业务系统。接口读取当前用户时使用登录会话中的平台应用解析角色。默认每页 24 条，可切换 48 或 100 条，越界请求回到实际末页。筛选变化回到第一页，翻页只读取卡片，展开表格由用户点击后按需分页。登记第一步侧栏使用同一接口的 `mode=choices` 独立搜索分页，翻页保留草稿和正在编辑的对象；候选只含展示字段，选中后读取详情并核验权限。

登记第一步的“所属系统”通过 `POST /dst/application/register-options` 一次读取当前租户完整选项，页面按名称和标识在本地搜索。系统管理员可以选择租户内全部有效系统，部门管理员和登记人员的选项取自当前登录账号的有效部门。接口忽略请求传入的 `keyword`、`limit` 及身份字段，沿用 `label`、`value`、`orgid`、`createdby` 的响应字段与名称、标识的原生排序。历史未填删除标记的系统继续可选。Mock 使用当前模拟会话的同一授权范围和响应结构。

左侧组织树和类型角标使用 `/dst/database/treeStatistics` 的 `mode=facets`。常规条件用一条分组 SQL 返回组织、应用、类型及状态数量。组织树使用未筛选的授权全集，类型角标随当前部门（含子部门）或业务系统、已提交关键词和状态变化，类型自身不进入角标筛选。各统计使用完整授权范围，卡片页大小只影响列表。加载和读取失败分别显示状态与重试入口。

“有变更”使用 ES 表投影的 composite 聚合遍历来源桶，每批最多 500 个 ID，再到主库批量核验当前租户、角色和筛选条件。卡片以更新时间及唯一标识作为游标，支持前后翻页；分页内只保留当前页所需的候选与计数。ES 超时、分片失败或游标异常时，变更列表提示重试，普通卡片继续显示其他可用信息。部门、状态和搜索变化合并为 150ms 后的一次角标请求，旧响应不得覆盖新筛选。

页面默认首屏并行读取列表、组织树及筛选角标，共 3 个业务请求。卡片 20／100 条均为 3 次业务 SQL 和 1 次 ES 查询，含代理服务时增加一次服务聚合；作者名称按整页批量解析，角色与作者解析的固定开销另计。登记候选每页 2 次业务 SQL。`DatasourceCardsPagingMagicTest` 验证 1,005 条、第 11 页、ALL/ORG/OWNER、代理服务独立范围、变更游标、索引故障以及 508 个变更候选的跨批合并。`DatasourceTypeFacetsMagicTest` 覆盖超过 10,000 条的全量分面、授权、状态与类型别名，常规分面 20／100 条均为 1 次业务 SQL。前端回归覆盖全量角标、筛选、翻页、重试、响应竞争和组织树选中状态。

待标注摘要表的名称、发现时间排序作用于完整授权结果，支持升序、降序、取消排序；排序只重查登记区域，不重新加载治理、健康、任务和变更。刷新保留排序与有效选择。各区域以范围批次和区域序号隔离过期响应，快速切换范围或单区域重试不会被旧响应覆盖。指标、阶段、业务类型和列表入口支持真实分页下钻、搜索、排序及登记/监控跳转；源详情仅由用户点击时单次读取。测试入口为 `WorkbenchMagicTest`、`tools/tests/workbench-live.test.mjs`、`tools/tests/test_workbench_export.mjs`。20/100 条完整概览核心均为 6 次 SQL，变更函数至多另计 3 次，权限适配器开销另计。分区域的 SQL 次数包含一次角色范围读取，登记 3 次、治理 2 次、健康 2 次、任务 2 次、变更至多 4 次。非空事项页为 3 次，带处理清单时增加 1 次整批 ID 核验，导出为 4 次。角色拒绝、跨租户/无权ID、差异记录失败、异步过期结果、零分母及导出失败均单独验证。登记进度采用可伸缩网格，进度条独占下一行，避免窄卡片横向溢出。

## 公安资源复制到澄天

该流程按用户授权，从当前运行绑定的公安业务库 `baseline_ga` 读取应用系统、数据源、表和字段、目录及数据项、接入任务与字段映射、逻辑模型、数据标准和应用配置，复制到澄天业务库 `chengtian`。固定来源租户为 `2084109831682699264`，固定目标为 `2084109831682699267`，不提供由请求参数选择任意租户的接口。


<a id="police-resource-import--导航与数据范围"></a>

### 导航与数据范围

澄天复用现有 `/datasource-manage/index` 和共享 `department-datasource` 组件，顶级菜单显示为“数据登记”，位于“数据盘点”右侧。只为已经拥有数据盘点入口的现有角色补齐这两个菜单记录的授权，继续启用菜单数据范围校验；不新增身份、角色、管理员标志或功能副本。

有效资源保持原业务名称，主键及关联标识按稳定命名空间重新生成，租户字段统一写入澄天。原组织仍存在于澄天时沿用；原组织缺失或未登记归属的导入记录由现有科信总队代管，不凭原库记录扩大授权范围。

已删除记录、布控、联调测试、无法关联有效数据源的表、无法关联有效来源表的目录和任务不作为有效业务资源导入。运行监控、执行历史、人工审批、旧流程组和不可变发布计划不冒充新租户的运行结果。公安持续变化的运行计数与配置变更分开比较，配置变化仍会阻止写入。

此前澄天的合成演示资源及现有业务数据保留。该复制过程不会把源租户的账号、角色、成员关系或 API 授权同步过来；必要的数据源连接设置仅保存在受限运行库与仓库外快照中，不进入 Git、日志或 ES 投影。


<a id="police-resource-import--接入目标与运行状态"></a>

### 接入目标与运行状态

复制的接入任务初始为未启动配置；复制的 NiFi 加工图初始为 `SAVED`，公安的流程组标识、部署结果、队列和运行计数全部清除。

已关联的目标表在 `ct_police_copy_targets` 中创建，目标连接属于澄天。加工图的 JDBC 写入节点重绑这些独立目标，不能通过复制结果停止、重部署或写入公安原任务的目标。原目标表也是下一段接入的来源时，下一段来源连接一并指向对应的实验表。

下一段来源迁入MySQL实验库时，`registeredDatasourceId`、`selectedDatabaseId`、`sourceDbId`必须一起指向实验数据源；物理表名和`sourceTableName`一起更新，来源组件采用`source.mysql`，移除旧厂商驱动及owner等连接属性。保留节点标识、位置、连线、过滤及增量配置。仅更新可见连接选项会留下旧达梦/Oracle来源标识，组合链路会因画布与任务记录不一致退回单任务视图，不能把该提示解释成NiFi断线或物理数据丢失。

对原目录中缺少挂接目标的有效表目录，预览指向已有来源表；任务缺少来源目录时补齐来源目录和数据项。数据源、表、目录和属性表中的关联采用同一组新标识。

“复制配置”不代表外部 Oracle、FTP、API、Hive 等网络环境均已恢复连接，也不把旧租户的运行成功复制为新租户成功。启动任务前仍需使用现行页面核对连接、字段映射、调度和实验目标；原有已验证的澄天合成接入任务不受影响。


<a id="police-import-target-schema"></a>

### 公安资源迁入的实验目标结构

`ct_police_copy_targets` 是澄天复制公安接入任务时使用的独立 MySQL 实验目标库，不属于公安业务库或四行业统一的平台业务表。公安原流程组、原写入目标和运行历史不直接复用。

目标表按原登记字段构造；Oracle、达梦、金仓等来源的类型只在这些新实验表中转换为可承载原值的 MySQL 类型。主键列在实验目标中强制非空；未提供精度的 NUMBER 以文本保留原值，过宽的非主键字符串采用 LONGTEXT，避免截断或超过 MySQL 行长度限制。两个 VARCHAR(800) 的完整业务键超过 MySQL 索引长度上限，保留原字段长度，并使用生成的 SHA256 二进制列建立唯一索引；写入的业务键仍为原 ROWKEY，不截断业务值。原数据库及原登记定义不因此修改。

`init.sql` 在实验目标创建后由根工具 `tools/export-db.py` 的 `mysql_export / SHOW CREATE` 完整导出；文件包含完整表、字段、主键、索引及注释，不包含业务记录、连接口令或账号授权。不得对已有运行库执行初始化文件。

复制源快照和回退材料包含受限连接配置，仅存放在仓库外私有目录。运行计划、计数及验收报告位于忽略的 `logs/police-copy/`。

<a id="police-resource-import--工具与验证"></a>

### 工具与验证

`tools/copy-police-resources.py` 默认只读计划，通过 `tools/chengtian-maintenance.py` 连接旧 MySQL `chengtian`。这套工具适用于公安绑定 `baseline_ga`、澄天绑定旧 MySQL `chengtian` 的迁入实验，当前澄天金仓 `baseline_ct.public` 不适用。准备迁入前必须已有独立目标连接，工具不再从合成数据源复制配置。分阶段入口为 `plan`、`menu`、`prepare`、`apply`、`index` 和 `verify`。`reprepare` 从仓库外已准备快照重新生成候选内容，写入前重新比较来源配置。

已迁入批次的来源兼容使用`repair-chain`只读规划，再以`repair-chain --apply`执行所选批次；`--pipeline-id`可重复指定当前核对的画布，所选ID必须属于受限复制快照。只处理至多100个明确画布，批量读取当前任务/登记关联并一次校验全部数据源的当前角色范围。仅当画布仍与原复制快照一致、保持SAVED且没有部署痕迹时补齐来源绑定；人工修改、已部署、跨租户、失效或无权引用均拒绝覆盖。执行前保存仓库外受限备份，按原DSL、版本时间及当前任务/登记关联进行原子并发比较，任一冲突整批回退。此操作不重建表、不写来源数据、不操作NiFi，也不在打开画布时隐式修复。

读取采用固定租户及每页 1,000 条的游标，限制单表和本批总记录数。关联预取后在内存中逐 ID 校验；写入按有限批次执行，不按列表行补查。首次写入前保存受限回退材料，目标 ID 已存在时不覆盖；中断后只允许核对并复用本批定义一致、仍为空的实验表。

ES 资产投影从当前澄天主表及白名单属性重新生成，按每批 200 条写入澄天独立索引。连接口令、令牌、连接池设置及治理快照不进入 ES；已退役的合成目录和业务明细不再进入索引。

日期属性统一转换为带时区的标准日期；无法解析的日期只从检索投影省略，数据库原值保留。登记、标注和连接状态沿用实际主表，不统一标记成功。资产投影不再附加合成业务索引和模拟标记。

超市列表和左侧组织统计由服务端确定租户索引，统一只检索已上架的数据目录。列表接受关键词、组织路径、业务系统、共享类型、加工程度和发布时间选项。翻页只重新读取列表，筛选和排序变化回到第一页，分类统计可独立重试。每次检索支持浏览前 10,000 条，超过时结果数显示下限。索引不存在时返回空结果，其余查询错误继续报告。收藏、购物车和申请状态按当前部门关联当前页的目录，收藏和取消收藏按目标状态写入。

数据超市的搜索区、分类树与结果区随可用宽度伸缩。双栏布局下，左侧组织机构栏与右侧筛选及结果区等高，树超出可用空间时在栏内滚动。窗口宽度不超过 760px 时改为单栏，分类树通过「分类筛选」展开。筛选区随宽度重新判断是否显示「更多」，结果排序、卡片内容和分页可以换行。澄天的浅色与深色布局复用 `TopMenu`，共享菜单占位宽度和导航可用宽度，各自使用原有字号、字重与悬停效果。放不下的入口收进更多菜单。页面滚动由实际溢出的容器处理，根页面不强制预留滚动条空间，避免布局右侧出现空白边。

购物车和个人中心共用订阅申请表单。购物车一次最多申请 100 个目录，分别生成草稿。继续编辑保留原申请单及其目录，再次申请生成新草稿。保存和提交各使用一个批量请求，服务端按当前租户、申请人和申请状态核验整批记录。未完成的提交保留表单及已保存的草稿编号，成功后关闭并刷新申请列表。草稿箱和编辑详情以租户业务表为准。

数据超市详情展示当前租户已上架且登记审批通过的目录。打开有效详情后记录一次浏览，关闭申请弹窗刷新详情时沿用本次浏览记录。服务端对当前租户索引中的已上架目录原子递增 `viewCount`，统计失败时仍可浏览详情。浏览量目前只保存在索引里；定向和全量重建会替换目录文档，可能使浏览量回退。可申请时，从详情直接打开同一订阅表单，默认带入当前目录。详情按当前部门显示购物车和申请状态。

四行业目录主表已增加 `market_view_count`，为后续计数持久化切换准备；当前运行浏览接口仍写 ES，新列默认0不表示历史迁移已完成。原生演练确认递增需在同一事务中锁定当前租户的有效目录，使用带上限条件的加一操作；达梦需对已明确回滚的多版本冲突作有界重试，提交结果不明时不能重复递增。历史盘点按租户物理索引、每批最多100条读取，原始快照保存在仓库外受限目录；正式回填前还须停旧写入、排空在途请求并重新采集，不能将无主记录的索引投影补成业务目录。

保存订阅申请时，只对本次新增的目录校验上架及共享资格。保留在草稿中的目录及同一草稿键的重试沿用原登记和审批规则。本人可从个人中心或购物车草稿箱删除待提交的订阅草稿，并选择把目录加回当前部门购物车。回填跳过已在购物车或已有有效申请的目录。待回填目录已不可申请时，保留草稿并提示取消回填后重试。草稿删除、关联清理和回填在同一事务完成。

购物车由当前租户的当前部门成员共用。角标单独读取总数，打开购物车后按页查询，搜索和切换页码时保留已选目录。购物车分页、新增及更换目录、申请保存和草稿回填共用发布资格校验。调用方先按会话租户和业务范围核对登记及审批，校验函数在当前租户索引中一次查询最多 100 个候选，核对上架、共享属性和关联资源。购物车角标、空页和没有候选的页不查询索引。已失效目录显示原因；索引超时、部分失败或返回不完整时，受影响目录显示“暂时无法确认资格”，可重试当前页。两种记录都保留在购物车内并可移除，只有可选目录进入订阅表单。移除使用购物车行 ID，跨页选择按目录 ID 去重。移除与加购、草稿回填使用同一部门锁，服务端按会话所属租户和部门检查每条记录。

验收包括菜单位置与页面、真实澄天会话、导入资源关联、空的独立实验目标、未启动的新任务、20/100 行的请求与 SQL 数，以及无权或异租户 ID 的拒绝。运行材料位于根目录 `logs/police-copy/`，不提交 Git。


## 数据服务登记与代理访问

数据源卡片的蓝色主操作、编辑与删除按钮使用 Element Plus 的原生图标位置，加载时在同一位置替换为转圈图标。图标固定为14px方框，SVG不再设置偏移边距，保持旋转中心和文字位置稳定。代理访问卡片底部只显示“数据服务 N 个”和“接入方式：代理访问”，数量来自同一概要响应的 `serviceCount`；无服务时显示0。

`departmentDataSources` 先按当前租户及数据源菜单范围确定有效父数据源，再将当前页的代理访问 ID 一次传入聚合查询。服务计数按服务列表使用的 `DATA_SOURCE` 角色范围再次过滤，排除其他租户、已删除及未关联的服务。主卡片查询同时提供业务库的描述与探查总数。兼容的 `summary` 调用保留最多 1,000 条的原契约，由 `ProxyDatasourceCardCountsMagicTest` 覆盖菜单及服务的不同权限组合；管理页使用 `cards` 的服务端分页。

同一接口的已登记表和上报表均由数据库完成排序和分页。已登记表越界时读最后一页。上报表先批量校验每个来源的租户、角色和上报方式，再按来源与不区分大小写的表名去重，优先已标注和最近更新的记录，随后筛选业务表和日志表。20/100 项均为 3 次业务 SQL，已登记表另有一次当前页 ES 标签读取。旧式清单对最多 10000 个 ES 候选表按每批 500 项回填时间及登记状态，历史标识已变化时在同一来源按表名匹配。缺少索引投影时按可见来源回退业务库，最多读取五个各 10000 张的窗口，超过范围时使用独立分页。`DepartmentDatasourceReadsMagicTest` 覆盖排序、越界、去重先后顺序、跨租户和已删除记录，以及超过 10000 张登记表时的候选回填和窗口回退。

数据源登记中的“代理访问”以当前数据源为归属保存数据服务。新建且尚未保存的数据源的服务表为空，不请求全部门服务；先显式保存基本信息，再点击“登记服务”或“下一步”打开当前数据源的服务登记工作台。数据源主记录沿用 `db_datasource_t`，`pool_cfg.accessMode=proxy`，不要求物理连接或数据库表元数据。服务以 `api_info_t.datasource_id` 关联该主记录，保持 `resource_id` 的既有含义；该字段可以为空，历史未关联服务继续在数据服务管理中保留，不按部门或名称自动归属。

登记页标题为“当前数据源已登记服务”，支持服务端分页、名称与更新时间排序、名称／编码／地址搜索。工作台的列表、用户点选详情、新增草稿和保存都带同一数据源标识；“保存并新增”保留归属，成功关闭后刷新当前数据源的服务表。登记侧栏独立分页读取 `mode=choices`，代理源不初始化数据库表元数据，也不计入直连失败统计。服务列表接口先核验父数据源的认证租户及角色范围，再叠加服务自己的 ALL／ORG／OWNER 范围。保存接口校验父源存在、未删除、可访问且为代理访问；租户、创建人和部门来自服务端，普通编辑不能转移既有服务的数据源关联，省略字段时保留原关联。

外部数据源卡片展示“接入方式：代理访问”，主操作为“登记服务”，不展示数据库表标注指标。点击源名称或卡片复用登记第五步 `register-confirm`，上方使用公共数据源信息区并展示“代理访问”，下方仅列出当前源已登记服务的分页表格。第一步保存源信息、登记服务后，“下一步”跳过第二至四步进入同一个第五步；返回时直接回第一步。原共享 `detail-page` 中的代理专用分支、查询和样式已移除，不新增低代码详情页。未保存新源不请求服务；20／100行均为1次服务分页请求，后端SQL数固定为4次，且同时校验父源和服务自己的当前租户、ALL／ORG／OWNER范围。结束登记重新核验已登记服务，按当前角色服务范围一次聚合并在原子更新中再次校验存在性；20／100项完成核验均为2次读取，不读取物理表元数据。

第一步 `register-db` 和第五步 `register-confirm` 共用澄天宿主的 `ProxyDatasourceServices`，统一搜索、排序、分页与错误重试。第一步通过操作插槽打开登记弹框，第五步以只读模式展示；结束登记单独使用无关键词的服务核验，保留用户的搜索上下文。第五步的数据源概要和服务列表分别处理失败重试。部署时先更新注册公共组件的澄天前端宿主，再发布这两份低代码；宿主登记弹窗通过局部导入绑定原生登记组件，避免同名共享组件覆盖原生向导。

原生和共享低代码登记弹窗的步骤、初始状态及底部按钮由 `data-elements-chengtian/src/components/business/registration-flow.ts` 统一定义。每次打开重新创建步骤及加载状态，避免跳过标记与按钮状态串到下一次。`registration-actions.ts` 统一调度保存、下一步和完成登记。完成时将本次审查结果交给当前步骤提交，上报工作台接管后停止推进本地步骤，关闭弹窗后丢弃旧步骤返回的结果。修改后运行 `node tools/sync-registration-flow.mjs` 生成低代码 `register-modal` 和 `register-body` 的内联段，再编译发布受影响的组件。`--check` 用于核对生成内容。共享产物通过原有宿主导入运行。原生数据探查编辑保留五步，低代码单步编辑通过「保存并完成」直接提交当前步骤，成功后关闭。

资源目录详情的「数据质量」页签从当前账号已授权的路由查找正式数据质量入口，包括隐藏的授权路由。任务配置、执行记录和整改工单由正式页面处理。当前账号未开通入口时显示权限提示。

数据服务页使用同一部门范围，主登记入口称为“登记数据服务”。列表保留服务状态和关键词筛选，不再提供请求方式筛选；与代理访问服务列表统一展示服务名称、请求方式、服务地址、状态及更新时间，并保留操作列。操作列与数据探查页复用 `DataTable` 的 `buttons` 配置。编排、编辑、删除使用同一套链接按钮间距，列宽随按钮内容调整，表头居中，操作列固定在右侧。服务编码显示在名称下方，不再按窗口宽度隐藏核心列，必要时在表格容器内横向滚动。服务分组节点的编辑、删除操作使用透明背景，与树节点悬停和选中背景保持一致。代理跳转使用 `register=1` 标识本次登记意图，关闭登记框后再移除，不在打开时清理，以兼容按完整地址重建的页面。服务登记采用动态表单与低代码组合：`api-register-content` 通过 `$form.loadDefinition("登记API服务")`，按当前租户及 `$setting.systemCode` 从 `sym_form.form_json` 读取完整规则；`api-register-modal` 负责多条登记、草稿切换、部门服务分页和保存流程。表单配置不再与登记页各维护一套字段规则，详情查看与编辑也复用这一配置。

服务分组由 `data-serve` 的左侧树和部门范围内的服务分组接口管理。已清理无调用的旧目录抽屉 `category-drawer` 及其中的示例列表。

当前公安租户的“登记API服务”包含12个数据字段，分为基本信息、访问配置、服务参数及请求/响应示例页签。两个入口复用 `api-register-modal`，标题统一为“服务登记”，数据源入口仍按当前数据源筛选和保存关联。访问配置依次为整行服务地址、整行请求方式、并列的访问协议与返回格式。登记保存上游地址，平台发布地址由编排发布写入。已有服务保留其历史字段，列表分别展示上游地址和可复制的发布地址。校验错误在单元格内占位。

「接口信息」标题提供「调试 API」。调试从当前表单带入请求方式、地址及入参的示例值或默认值，草稿和已有服务都能试调用。面板允许填写 Query、请求头、临时认证和请求体，独立调用 `POST /dws/flowserve/gateway/api/debug`。调试按当前租户和角色逐对象核验服务及代理数据源。响应分别展示 HTTP 状态、业务码、耗时和脱敏正文，用户可将脱敏正文选为响应示例。调用失败保留草稿，切换草稿会清理调试状态。对可能写入的请求，发送前确认一次。

服务列表提供「构建服务」，保存当前分组下的服务草稿后打开云梯。新建编排服务可以先填写名称和编码，再在画布引用已有接口。编排发布时写入稳定的 Magic 入口及完整发布地址，上游地址继续用于请求执行。调试与发布的 HTTP 执行共用传输函数。上游地址以当前环境配置为准，详见 [云梯的 HTTP 服务编排](data-elements-yunti.md#http-service-orchestration)。

字段标题、顺序、分栏、必填/只读、字典、默认值、请求方式选项及间距、参数表列与工具栏、请求/响应页签及编辑器均在规则数组中定义。参数表使用通用 `FormTable` 适配现有 `VTable`，把新增、编辑、导入、移除后的行同步到 `publishParams`；参数校验由该字段的数组/对象校验规则声明。服务参数标题与导入、导出、新增按钮同一行，按钮靠右，参数表不再增加外层表单边框和说明文字；示例仅保留页签，不再显示“调用示例”标题。`CodeEditor` 作为原生动态表单字段使用，两个示例分别绑定 `requestExample` 和 `responseExample`。稳定字段名对应现有保存接口，新增业务字段的持久化仍须扩展接口契约，不能只增加一个输入框就视为后端已支持。

访问协议和返回格式继续使用当前租户的 `accessProtocol`、`returnType` 字典。常用选项源见 `docs/assets/data-elements-chengtian/dictionaries/服务登记.json`：协议补充 HTTP、HTTPS，返回格式包含 JSON、XML、纯文本、HTML、CSV、文件（二进制），保留既有 `restful` 等自定义项与记录标识。字典项是登记的接口元数据；不会因此启用新的传输协议实现。当前精简表单及补充字典发布到本机实际绑定的公安库 `baseline_ga`，其他行业既有表单、环境和字典保持独立维护，不能用模板覆盖其自定义配置。

可审阅的初始规则模板见 `docs/assets/data-elements-chengtian/forms/登记API服务.js`，运行时仅消费租户表单配置，不从该模板或低代码内置字段列表回退。共享页面改造时分别迁移四行业租户中 `env=公安`、仍为原始两项规则的默认记录，保留各自记录标识、租户、环境和 `form_config`；广电库已有的另一份 `env=海渔` 配置保持原样。后续按各租户实际配置分别维护，不能用模板全量覆盖自定义表单。每次打开登记工作台读取一次最新定义，切换草稿复用已加载定义；缺失、空规则、重复同名记录或语法错误时显示错误并禁止保存，支持重试。

动态表单渲染器的 `responsive` 能力按实际容器宽度调整分栏：不足820px时单列，不足480px时标签置顶。服务登记内容和数据源基本信息启用此能力，保留原动态规则、必填校验和字段值；输入框不超出容器，单选和复选选项自动换行。服务登记弹窗挂载到body，使用视口高度、固定头尾与独立内容滚动；小屏将服务草稿列表放在表单上方，避免嵌套弹窗裁切或保存按钮被挤出视口。

数据抓取中的API配置支持HTTP/REST与WebService两种协议，继续复用`api`数据源和`apiPullItems`扩展配置。WebService支持SOAP 1.1/1.2、WSDL 1.1本地绑定操作解析、手工服务地址和XML请求体，复用现有Basic/Bearer/API Key/OAuth2测试认证。读取WSDL仅提供操作、地址、版本及SOAPAction，不代表业务调用成功，不更新已登记数据源的连通状态；导入的WSDL/XSD不自动联网加载，可手工填写相应SOAP请求。实际连通测试按所选SOAP版本发送POST/XML，并从SOAP Body推断字段及记录集合，提取路径使用去除命名空间前缀后的元素名；SOAP Fault即使返回HTTP200也判定失败并显示原因。请求中的DTD和外部实体被拒绝，XML响应最多5MiB、40层、20000个元素。请求协议、XML、SOAPAction与响应字段配置随登记保存，认证秘密继续仅供当前测试使用，后续任务使用凭据标识。

登记三步引导用于数据抽取和 API 抓取的无连接状态、数据推送和数据上报，统一复用 `AccessOnboarding`。推送的模板下载、上传操作与引导标题同行靠右；抽取和 API 抓取的离线模板操作位于连接选择同一工具栏右侧。步骤标题为 16px、说明为 14px，窄容器自然换行，不通过缩小字号适配。新建数据抓取默认使用 API，已有 FTP 抓取继续按原类型打开。默认“提供连接信息”，直接展开首条 API 配置以测试接口并探查响应字段。选择“暂不提供”时，按“下载登记模板、导入已填写模板、核对并继续登记”操作。地址、请求方式、响应提取字段和调度规则填在 Excel 的“接口配置”工作表，以表英文名关联“数据表信息”和“数据字段”；导入后在引导下方核对 API、表和字段，点击“下一步”保存并继续。旧版模板在每张表均已登记对应 API 时可继续导入。代理访问使用服务列表的简洁空状态。数据上报支持 CSV、Excel、TXT、JSON，规范编辑后统一生成单表 UTF-8 CSV 投递；格式规则见 [海通上报工作台](data-elements-haitong.md#data-report)。

表单配置页使用与运行页相同的规则解析器，保存前检查数组结构、组件类型和嵌套字段重名，并重新读取所选记录核对规则是否已被其他编辑者更新。保存与重命名携带完整的 `tid/formName/formJson/env/formConfig`，保留辅助配置；保存期间阻止重复提交，保存后清理旧缓存，重新打开业务表单即可生效。多条登记的权限校验、接口载荷与保存事务留在现有低代码和服务端，不在表单表达式中重复实现业务后端。

当前渲染包为 `@form-create/element-ui@3.2.31`，可视化设计器为 `@form-create/designer@3.3.1`。本次不升级依赖：现版已经覆盖所需的原生组件、事件、嵌套布局、自定义组件和数组校验，并已完成实际登记验证。官方 Vue 3 渲染器已有 [3.3.5](https://www.form-create.com/v3/guide/update/3.3.5)，后续升级须对现有各类表单单独回归；不要直接安装该包的 `latest` 标签，当前该标签仍指向 Vue 2 分支。升级渲染器也不能替代部门范围、草稿状态和服务保存等业务流程。

登记弹框左侧提供本次登记列表及本部门已登记服务的分页搜索，右侧编辑选中的一条服务。支持添加多条待登记项、切换时保留各条未保存的字段/参数/示例，以及“保存”和“保存并新增”；保存后保留真实服务ID，继续修改不会重复创建。关闭或移除含未保存内容的草稿须确认，已保存的服务不提供草稿移除按钮。暂存内容仅在本次弹框会话中保留，不跨刷新保存；同一会话最多同时编辑100条。已有服务列表每页20条、最大100条，只读列表摘要，用户主动选择时才请求单条详情；列表使用 `serviceCreateType=api` 收窄为直接登记的服务，编排生成的服务继续由编排页面维护。

登记内容按基本信息、接口信息、参数信息与调用示例组织，省去重复的顶部介绍；请求方式独占一行，选项之间保留间距并允许换行。参数表的自动高度按全部行自然撑开，不在表内增加纵向滚动，编辑区统一滚动；宽参数表仍可在自身容器横向滚动。调用示例页签占满表单编辑区宽度，请求示例默认可编辑，初始规则模板中的请求和响应编辑区高度为280px；请求与响应分别保存，参数可为空，保存失败保留填写内容。左侧“服务列表”旁的角标统计当前页实际列出的服务和草稿，已打开服务去重，不再显示“本次登记”及初始空列表说明。服务描述默认显示三行；底部“保存”保留保存图标，“保存并新增”使用文档新增图标。服务地址支持 HTTP(S) 地址或已有服务的相对路径；登记操作只保存服务定义，不调用该上游服务。

服务登记左侧列表直接复用数据源登记的 `left-select` 组件，使用同样的单行布局、选中底色和实心状态图标。工作区自行控制选中项与分页，搜索和列表刷新不自动切换正在编辑的服务；草稿移除、未保存修改和切换保留机制继续有效。

服务参数在序号后通过“参数类型”选择入参或出参，原字符串、数字等类型列改称“数据类型”。方向沿用现有 `paramScope=request/response` 与 `api_param_t.param_scope`，兼容 `res` 标记；同一张表支持登记、导入和导出两种方向，缺少方向的旧格式默认入参，非法方向阻止保存。导入替换前提示影响数量；CSV 中的 JSON 引号、逗号、换行和前导零按文本保留，表格原生导入继续负责字段校验和载入，其他已支持格式保持原导入方式。

“是否必填”在服务参数中统一使用字符串 `1/0` 保存、以“是/否”显示，不直接套用值为 `true/false` 的通用字典。读取、导入和保存兼容布尔值、字符串 `true/false` 及“必填/可选”等旧值，避免下拉选择为是却误存为否；修复值域映射，不批量改写既有业务记录。

请求示例只取入参，响应示例只取出参，优先使用示例值，其次默认值，并按数据类型生成 JSON 值。已有参数且示例尚未初始化时首次自动生成；新服务首次进入对应示例编辑区或页签时生成一次。随后参数变化不会覆盖示例，页签栏最右侧统一提供一个“自动生成”按钮，仅重新生成当前选中的请求或响应示例，替换已有内容前须确认。一次生成状态随服务扩展信息保存，手工清空、保存或切换后不会反复补回示例。

服务列表、分组计数、详情与保存均从当前会话取得租户和角色范围；部门列表再按登录账号的实际部门收窄。客户端不能通过传入组织或租户标识扩大范围，新服务的所属部门和登记人由服务端赋值。现有服务修改仍须逐对象校验角色范围。共享低代码和 Magic 的唯一版本源分别为根目录 `lowcode/`、`magic/`，发布到控制库 `baseline`，业务定义保存在实际租户库，不创建第二套服务登记后端。

服务列表按当前范围在数据库筛选、统计和分页，普通排序只批量补齐本页参数数与分组名。按参数数排序时先聚合当前范围内的有效参数，再分页。分组树按当前租户读取字典，服务数按角色和会话部门统计，空分组与默认分组合并计数。详情一次读取所选服务的完整参数，保留旧参数的默认序号。三条查询的业务规则都在 MagicScript，脚本关联数使用现有控制库批量查询。

维护验证使用 `tools/tests/service-registration-ui.test.mjs`、`tools/tests/service-list.test.mjs` 与 Maven 的 `ProxyDatasourceServiceMagicTest`。列表每页 20、100 条均为一次分页请求。普通部门列表 5 条租户 SQL，按参数数排序 4 条。分组树 2 条，普通详情 4 条。列表和详情指定来源时增加一次父数据源校验，返回有数据的页面或详情时另执行一次控制库脚本计数。角色计算的固定开销单独计算。定向回归覆盖来源与服务两层授权、同部门不同登记人、软删除、跨租户、伪造部门及超过一页的参数排序。普通服务更新 20、100 个参数均为 2 次前置读取，代理服务更新另核验父源。

## 节点配置

后台管理的“节点配置”统一使用 `#/node-config`。原 `#/register/nifi-node-config` 和 `#/register/node-config` 保留跳转，菜单权限与低代码组件标识 `nifi-node-config` 不变。

抽取、推送节点的行内保留连通检测及适用的同步配置操作，编辑和删除收进“更多”，不提供复制菜单。推送节点不展示底层工程名称，编辑说明、连通检测与同步提示使用中文业务名称。

页面分为数据抽取节点、数据推送节点和数据服务节点。抽取节点继续使用 `nifi_node_t`；推送节点使用独立的 `push_node_t`，按当前租户的所属网络字典分组，不混入 NiFi 任务的节点选项。三个网络的示例地址仅供配置参考；没有部署的节点应停用，启用前先替换真实服务地址并执行连通检测。

登记数据源的“数据推送方式”将“推送频率”和“推送地址”放在同一行，频率在前，默认“非实时（10MB–1GB）”，另一选项为“实时（100KB–10MB）”；大小范围随频率一起保存，不另设大小下拉。已有实时配置回显为实时。推送地址与节点管理共用 `POST /ods/nifi-node/page` 的 `nodeType=push` 配置，按当前所属网络选择已启用的默认节点，或该网络唯一启用节点，拼接 `/api/v1/data-push`。未配置、加载失败或多个节点未指定默认时显示明确提示，不回退到演示地址或抽取节点地址。节点配置在登记组件初始化时只读取一次，切换数据源和网络只在已取得的配置中匹配；节点列表 20/100 项仍为一次请求、2 次业务 SQL，租户条件覆盖整批节点。

推送节点左侧图标显示最近一次连通检测结果：绿色可连通、红色不可连通、灰色尚未检测。鼠标悬停或键盘聚焦会显示状态说明、检测时间和耗时。检测由用户点击触发，列表不自动逐节点探测；推送节点检测结果保存在当前后端进程缓存，刷新页面可回显，服务重启或节点地址变更后恢复灰色。启用开关与连通状态分别显示，启用不等于可连通。

推送节点的“同步配置”打开清单弹窗，简短询问“确认将以下配置同步到某节点？”。清单按数据源列出数据表、字段数、节点实际状态和最近同步时间，状态分为未同步、已同步、待更新、未确认；表名同时展示中文和英文。清单每页20行，本地切页不补查；未纳入的来源单独列出原因。预览从所选节点的实际镜像取状态，不用平台发布时间或节点最近成功时间推断。读取失败显示未确认，可刷新清单后同步。确认会同步清单内全部有效配置，包含已经同步的表，保持完整快照语义，不提供截断快照的逐表勾选。同步成功后保留同一清单，逐表展示成功结果及汇总；失败或保存回执不完整时不展示成功。弹窗适应窗口高度，内容滚动，底部操作始终可见。

`POST /dst/database/push/sync` 的清单请求为 `{all:true,nodeId,preview:true}`，响应包含 `rows`、`sources`、`skipped`、`planHash`、`requestPath`、`targetUrl`。预览只读，批量读取当前可信租户的登记配置，并向节点发送一次 `REGISTRY_SYNC / STATUS` 请求。确认请求为 `{all:true,nodeId,planHash}`；服务端重新计算规范化清单摘要，源、表、字段、版本或目标变化返回409，要求刷新后重新确认，避免确认范围漂移。原 `{all:true,nodeId}`、单源 `datasourceId` 及本地只读 `dryRun:true` 保持兼容；`dryRun` 不调用节点。上限100源、1000表（每源100张）、10000字段和1MiB，超限整体拒绝。身份、当前行业库、可信租户和逐ID源/表/节点有效关联校验保留；按照登记业务约定，不叠加菜单 ALL/ORG/OWNER 范围。

接口地址在清单和结果中显示：平台发起 `POST /dst/database/push/sync`，当前本机后端完整地址为 `http://127.0.0.1:8088/dst/database/push/sync`；所选本机节点接收 `POST http://127.0.0.1:18083/api/v1/data-push`。后者统一使用 `deliveryType=REGISTRY_SYNC`；预览附加 `registryAction=STATUS` 和批量表引用，正式同步提交完整 `datasources`。目标始终取已保存且启用的当前租户节点，不接受请求指定租户、目标地址或服务凭据。同步只传登记配置，不发送业务记录或签发业务密钥。

20/100 张表的页面预览均为 1 次请求，确认另发 1 次提交和 1 次节点列表刷新，切页为 0 请求。平台批量预览固定 9 条业务查询和 1 次节点请求，确认固定 10 条业务查询和 1 次节点请求。平台按批保存契约及字段，已发布契约的版本或指纹变化时回滚，并在事务提交后向节点发送。接收端状态查询固定 2 次镜像读取，HTTP 审计另计。测试覆盖指纹、过期清单、远端额外 ID、跨租户节点和来源，以及完整回执校验。


## 数据文件上报登记

数据源登记第一步选择“数据上报方式”后，始终展示“选择数据源并上传文件 → 规范数据表登记信息 → 选择数据表并上报数据”的三步图示引导，不执行文件上传、解析或字段编辑。顶部保留完整五步导航；点击“下一步”先保存基本信息，再关闭登记弹框并进入海通 `#/report?datasourceId=...`。新数据源及没有上传记录的数据源只展示引导；已有记录时在引导下方使用共享 DataTable 展示序号、数据文件名称、字段数、数据量、状态及最近上报时间，表格按当前页实际行数自适应高度，保留服务端分页和排序。字段数累加文件内各表的实际字段数量，缺少字段列表的历史条目才回退到已存字段数，不能用表数代替。文件读取失败保留引导并提供重试，旧源迟到结果不能覆盖当前源。外层数据源卡片通过同一概要查询中的 `reportFileCount` 判断是否已有文件，已有文件时标题、卡片及“数据上报”按钮直接进入对应源的工作台；编辑仍打开引导、只读结果与基本信息。三个入口均传递去除认证参数的返回地址，工作台的正常返回与错误页返回都回到进入前的页面。

文件上传、区域识别、规范整理和投递统一在[海通数据上报工作台](data-elements-haitong.md#data-report)完成。已有文件、登记表和字段沿用 `file_upload_t`、`db_table_t`、`db_table_column_t` 及 `pool_cfg.reportRegistration`，不新增物理表。普通基本信息保存保留服务端已有清单，上传清单使用版本校验和短事务防止并发覆盖。登记流程中为上报增加的跳过步骤、文件校验前置条件和审查豁免已移除；非结构化文件登记的独立流程继续保留。

`POST /dst/database/metadata/report-registration` 的 `history` 动作提供只读服务端分页和白名单排序，`receipts` 分页读取真实上报回执。20/100份文件结果均为一次页面请求、一次租户限定 SQL；外层20/100卡片仍使用固定查询数，不逐数据源读取文件列表。上传工作台所用 `list`、`parse`、`save` 与提交接口均核验可信租户及每个文件、表和数据源关联，传入外源 ID 整批拒绝。运行及权限回归见 `ReportRegistrationMagicTest`、`ReportSubmitMagicTest`、`DatasourceCardTypeCountsMagicTest`、`tools/tests/report-registration.test.mjs`。

## 登记第一步的密码查看

第一步的连接密码和密钥输入框在新建草稿、尚未首次保存时保留眼睛按钮。是否已登记以当前记录的持久化主键判断，草稿展示编码不算已保存；保存成功后立即隐藏眼睛，再次进入已有数据源也不显示。鼠标停在对应输入框内按住 Ctrl 可临时查看，先按 Ctrl 再移入同样有效；键盘聚焦输入框后也可按住 Ctrl 查看。松开 Ctrl、移开鼠标、输入框失焦、离开窗口或标签页、关闭登记窗口、切换数据源或连接类型都会恢复隐藏。API 抓取存在多个接口时，临时查看状态按接口及字段隔离，不会同时显示其他接口的密钥。

此交互只改变当前输入框的显示类型，不发起密码读取接口、不改密码值及保存协议。新建转已保存、切换数据源或连接类型时重建密码输入框，以清除输入组件自身的眼睛开关状态；卸载时移除键盘和页面事件监听。验证入口为 `tools/tests/registration-password.test.mjs`。

## 登记审查中的推送规范

登记表单同时具备数据库类型、主机和 JDBC 地址字段时，才自动生成 JDBC 地址。文件推送表单可只保留业务来源地址，打开已有登记时按原配置回填。

第一步的数据推送方式使用与数据上报相同的 `AccessOnboarding`。非结构化数据展示“登记文件信息 → 查看推送规范 → 推送文件数据”，先登记文件定义，再查看文件集合、分片上传与认证要求，最后推送实际文件；结构化数据展示“登记数据信息 → 查看推送规范 → 推送业务数据”，三步标题统一为六个字，先登记数据表和字段，再查看接口地址、字段约束与认证要求，最后提交数据。两类引导在导入前后均保留，下载和上传按钮位于引导标题右侧。非结构化引导不再显示常驻的下一步提示及模板必填项说明，真实导入错误与未保存提示继续显示。结果框与上方引导保持20px间距，文件定义及结构化导入结果表按当前记录自然撑高，列宽自适应并允许长内容换行，避免结果区内部滚动。

数据源登记顶部始终保留“登记数据源、探查数据表、登记字典表、登记业务/日志表、登记内容审查”五步导航。非结构化推送与代理访问仍在实际执行时跳过中间三步，导航继续显示第五步的原编号；跳过项不作为可点击的返回目标。左侧数据源列表预留固定滚动条空间，使有无滚动条时状态对勾的横向位置一致。推送信息条展示“推送数据类型”和必填的“数据来源地址”：来源地址由人工填写上游程序或服务的 IP、IPv6 地址或 URL，仅校验非空，保存时去除首尾空白。它与数据抽取的主机地址共用 `db_datasource_t.pool_cfg.host`，没有单独的主机地址列，也不写入动态属性表。重新编辑从同一配置回填；显式清空时拒绝保存，省略字段的局部更新沿用已有来源地址。右侧网络名称继续跟随所选数据接入节点，切换网络不覆盖来源地址；历史未填写的来源保持空白，由登记人员补填。此字段不再自动读取推送接收节点，平台接收接口仍由第五步按当前网络的推送节点配置展示，来源地址不会改写节点接收地址。

字典表登记将字段翻译和状态过滤的说明放在对应字段左侧的提示图标中，配置项之间以“翻译”“筛选”标示。单类别、多类别和右侧数据预览、字段配置采用相同的分段切换样式，两侧标题栏及分隔线对齐；多类别搜索紧邻切换控件，右侧与下方字段选择器对齐，支持业务字段标识、表述和原始类别值的搜索，回车或点击搜索执行，清除后恢复全部类别。登记区底部与第二步一致，不额外留出间距。

第五步“数据表信息”统一使用与文件登记审查相同的 `DataTable` 紧凑表格，保留标题、搜索框、筛选和标题到表格的间距。中文名称、英文表名、业务类型、字段数、登记检查、接入状态、同步频率、接入数据量及各项同步时间分别展示；行内不堆叠多行说明，不再提供行展开。必改项和建议同时存在时只显示必改标签，悬停或通过键盘打开后可查看并定位全部必改项和建议；仅有建议时显示建议标签。字段数保留用户主动打开字段预览的入口，编辑、接入申请和同步管理操作仍按原权限执行。宽表仅在表格内横向滚动，操作列固定在右侧，并按当前页是否存在较长的任务管理操作调整宽度。

列表继续使用既有服务端排序分页与当前页批量接入摘要；`DataTable` 分页插槽沿用当前查询状态，只展示已经取得的一页，不增加逐表读取。结构化推送规范的表折叠项使用正常内容容器承载 JSON 示例和字段约束，不能用没有指令的 HTML `template` 包裹默认内容。`push-contract-review.test.mjs` 通过实际 Vue 编译和渲染验证展开内容中存在可见 JSON 示例，避免仅验证示例生成函数而漏掉页面空白。

第五步的数据表审查不限制数据源总表数，列表每页最多100张。完整范围向 `/dst/database/metadata/tables/review-order` 传 `allTables=true`，由数据库去重、排序及分页，不再随每次翻页上传整份表名清单。搜索和问题筛选保留精确表名范围，服务端用一次前向只读游标核对当前租户、当前数据源内的每个名称，只保留当前页及待校验集合；不存在、其他数据源或跨租户名称整批拒绝，不使用巨大IN或逐表查询。完整范围与名称范围不能同时传入。两种模式均先按数据源管理的ALL/ORG/OWNER范围校验所属数据源，不能通过扩大审查范围越权。20/100行的排序分页均为1次请求，完整范围均3次业务SQL，筛选范围均2次，角色解析的固定开销另计；本页接入任务仍使用一次批量摘要请求。`TableMetadataCollectionPagingTest`和`tools/tests/registration-review-paging.test.mjs`覆盖3万张表、1.5万张筛选、首尾页、排序、空结果、过期响应及租户/角色边界。元数据快照未就绪时不发起排序请求，空筛选清除旧错误，真实读取失败保留就地重试。

第五步进入后即可主动获取当前数据源的 X-Api-Key，无须先结束登记。查看规范本身不签发或轮换密钥。获取或轮换时，平台按当前租户校验数据源及推送方式，发布其中已登记表的字段规范，同步海通镜像和调用方授权，再签发密钥；不修改数据源总体登记状态。暂无已登记表时也可签发数据源密钥，空表镜像不授予任何表访问权限。首次签发只回显一次明文，重复获取只返回状态，显式轮换使旧密钥失效。认证区域依次展示 Content-Type、X-Api-Key、Idempotency-Key；表数据为application/json，附件原始字节为application/octet-stream。请求体参数完整展开，移除schemaVersion和occurredAt，版本由服务端维护。网络、权限或响应归属错误原位显示；无已发布表时展示登记字段，不编造规范版本。

第一步推送模板的“数据字段”增加“是否关联附件”“附件大小上限(MB)”“附件格式”三列。旧模板缺少这些列时按无附件处理；关联附件时要求字符串字段，长度至少36，大小上限为1至1048576的整数MB（1MB=1048576字节），格式为jpg/jpeg/png/pdf/docx的非空集合。扩展名不区分大小写、允许前导点及中英文分隔符；服务端仍校验整数字节上限和格式白名单，不能绕过Excel检查。附件字段保存fileId，不填写Base64或文件原文。

附件限制保存在已有 `db_table_t.field_governance_config.attachmentFields`，后续第三、四步治理保存保留该段，以第一步重新导入更新为准。发布时限制纳入规范摘要和版本，并保存到 `data_push_schema_t.delivery_config.attachmentFields`；节点批量同步与单独发布使用相同属性顺序，不能丢失配置或生成不同摘要。无需新增物理列。

登记审查按当前数据源已保存的推送类型展示规范，结构化与非结构化统一使用“数据推送接口规范”标题，已发布状态统一为绿色“已发布接口规范”；草稿、读取中和读取失败按实际状态展示。结构化请求使用 application/json，展示 deliveryType、datasourceId、tableName、可选 batchId、records 及登记表字段和 JSON 示例；示例使用 FTP，已配置并获授权的 Kafka 通道可使用 KAFKA。密钥区展示当前数据源凭据的同步状态和轮换入口，明文仅首次生成时展示。

非结构化上方“文件推送接口”统一为 PUT /api/v1/data-push，multipart/form-data，默认普通文件single模式，也支持 /api/v1/data-push/single 别名。页面使用相连的分段组件切换“普通文件”和“大文件（分片续传）”，模式说明显示在“文件推送步骤与请求参数”标题右侧并随选择更新，切换组件与第一步采用紧凑间距：普通文件仅展示一次性上传并提交、查询投递结果两类接口；大文件展示初始化、分片、完成并提交、查询结果，断点续传作为可选项。公共请求头集中展示，multipart的boundary由客户端自动生成。文件类别参数统一使用fileCode；原始fileName、大小和摘要在普通模式由服务端从文件取得，分片初始化才需另填fileName、size和可选sha256。候选类别来自当前授权快照，不逐文件向节点探测。文件推送各接口请求示例统一按HTTP请求报文展示，普通文件展示multipart表单分段，大文件按实际接口展示JSON或二进制请求体。请求示例默认展开，使用灰色静态标题，与右侧“复制请求示例”按钮水平对齐，不重复显示步骤名称；结构化推送复用同一示例标题栏。

大文件初始化的sha256仍为可选整文件摘要，分片X-Part-SHA256必填；普通文件无需填写大小或摘要，服务端流式计算并校验。页面保留大文件摘要说明及Linux/PowerShell获取示例。

登记模板新增必填“文件英文名”（fileCode），小写字母开头，仅小写字母、数字及下划线，最多80位，同一数据源内唯一。文件名称仍为展示名，文件说明保留业务说明。旧模板可继续读取；已有集合编码及上传记录不改写，旧记录可补充一次英文别名，已设置的英文别名保持稳定。别名保存在现有field_governance_config.fileRegistration.fileCode，节点配置file-code映射至原collection-id；新文件默认以fileCode作为集合编码。保存前统一批量校验当前租户、角色范围及关联ID，不新增物理表或列。

第一步文件模板结果仅保留已登记文件数量、下载/上传操作及真实错误、未保存状态，移除“文件登记模板导入结果”小标题和上次成功保存快照等描述。内容审查中的文件表与结构化表共用 review-workbench、data-table-information-card、data-table-toolbar、data-table-section-content 和 DataTable 样式，统一卡片内边距、标题间距、表头、边框和行高。

新分片接口位于/api/v1/data-push/uploads：POST初始化，PUT写入指定片，POST /{id}/complete同时请求合并和提交业务意图，GET /{id}查询最终投递结果；GET /{id}/parts只在断点续传时使用。202表示受理，READY表示文件可用，均不能代替deliveryStatus=SUCCEEDED。旧file-uploads及表/附件字段single接口继续兼容。文件集合策略仍由节点自身配置，平台登记不自动下发FILE策略或扩大密钥权限。

当前公安演示推送源保留四张表，其中 `police_person_info.portrait_file_id` 为可选的人员照片文件编号（varchar(64)，10MB，jpg/jpeg/png），`police_case_record.case_document_file_id` 为可选的案件文档文件编号（varchar(64)，20MB，pdf/docx）。对应集合编号为“表名.字段名”，已在本地节点配置这两个集合及该数据源调用方；其他字段定义与表数量保持不变。附件原文先上传到READY，表记录仅携带文件编号。

针对性验证见 `tools/tests/push-contract-review.test.mjs` 及后端 Maven 的 `RegistrationFieldSyncTest`、`DataPushSchemaRegistrationStatusTest`。20/100 表均为一次规范读取，无已发布表时字段快照按最多 50 表一批读取。主动获取密钥后追加一次规范刷新。20/100 张已登记表的签发前快照均为 8 条业务 SQL。独立字段快照接口的 20/100 表单批均为 3 条业务 SQL，逐 ID 校验有效来源、表与当前租户的关联，混入外租户时整批拒绝，排除外租户字段。数据与附件模式切换不增加读取请求。附件列表仅从当前已授权快照筛选，预览字段异步到达后重建列表并保留有效选择。

附件模板由 `tools/tests/push-attachment-template.test.mjs` 生成和校验工作簿，导入由后端 Maven 的 `MetadataImportAttachmentMagicTest` 执行实际 MagicScript。导入 20/100 张表均为 4 次读取，角色计算和登记状态刷新另计。写前批量预取旧字段，越权、外租户来源或非法附件配置在写前拒绝。一次最多 100 表、10,000 字段。

## 数据表详情与 Hive 预览

动态表单详情统一使用表单布局骨架屏：系统、数据库、数据表、资源目录、文件目录共用 `base-detail`，在表单配置与详情数据并行读取、表单值完成回填后显示内容；服务详情的记录读取与登记表单配置初始化、申请单只读查看也使用同一视觉。加载失败显示错误与重新加载入口；切换记录或离开页面后忽略旧请求结果，不将旧数据写回详情状态。骨架屏复用 `LoadingState` 的 `form` 类型，保留标签和值的分栏、长文本占位，窄容器自动单列，遵循减少动态效果设置。加载反馈不改写租户表单配置，不增加逐字段请求；20/100 个字段均为一次配置读取与一次详情读取，命中现有配置缓存时不重复请求配置。

数据源详情的“数据表信息”只读取已保存表快照，不在进入页签、分页或筛选时探查来源库。与登记第二步共用 `/dst/database/metadata/tables`，详情以 `paged=true、allSnapshots=true、includeGovernance=false` 分页展示全部标注状态；登记第二步默认仅已标注列表的契约保持不变。列表提供“是否标注”、业务类型筛选和删除快照；点击表名查看样例，点击字段数查看字段结构，预览复用登记第二步的字段和样例接口，按用户选中的单表读取。删除需确认，仅清理平台快照及关联配置，不删除来源物理表或记录。

“重新探查”显式启动登记第二步同一后台采集任务，保留已标注快照并纳入新增表；展示真实进度，失败可重试，离页停止轮询。“登记数据资源”使用当前来源打开五步登记的第二步“探查数据表”，继续按同一份快照显示待标注与已标注表，退出登记后刷新详情状态。`datasource-table-snapshot.test.mjs` 覆盖20/100行均为3次初始读取（来源、现有任务状态、快照页），后续翻页仅1次请求，无逐行字段查询；`TableSnapshotListMagicTest` 执行实际脚本，20/100项均为4次业务SQL读取（来源、分页计数与记录、业务分类汇总，角色计算固定开销另计），验证同名快照优先已标注、默认已标注兼容、业务分类及跨租户/角色拒绝。

“数据表字段”页签与登记第三、四步共用 `register-dbTable-catalog`；详情无论表类型，都直接复用第四步的字段配置表及编辑逻辑，按当前表 ID 读取登记快照。字段中文名、主键、时间属性、字典翻译及统一格式与登记流程读写同一份配置；详情模式使用独立状态，不改动进行中的登记会话，也不自动查询来源库预览。登记第三、四步和详情均用“不为空”复选框编辑可空性：勾选对应 `nullable=0`，未勾选对应 `nullable=1`，未知值以半选状态和“未知”文字提示，未经编辑保存时保留未知。保存更新登记快照，不对来源库执行 DDL。

详情页顶部保留“同步字段、导出、保存、同步变更”操作，不显示登记工作台标题、统计说明或多层卡片。字段表的列、内容和样式与第四步保持一致，类型及长度按登记字段类型原文展示；表格填满详情区域的剩余高度，长表在自身容器内滚动。选择字段后批量填充中文名仅作用于选中范围；未选择时匹配当前表全部字段。字典表的编码、表述、状态和类别规则仍在第三步维护，详情中的字段编辑不会改变这些规则。

详情页提供“保存”和“导出”。导出为带中文表头的 UTF-8 CSV，可用 Excel 打开，包含当前表全部字段及当前编辑值、可空性、主键、字典翻译、格式和时间属性，不受选中行或滚动位置影响，并处理电子表格公式注入。保存复用 `/dst/database/table/governance/save` 的 `editMode=fields`，按当前租户校验表及关联数据源，再一次预取字段并逐 ID 校验表归属；只更新字段治理属性及用户明确修改的可空性快照，保留原登记、审批状态、字典规则、物理类型及模板维护的附件限制。所有归属与可空值校验在事务写入前完成，`dryRun` 同样校验但不写入。

“保存”写入平台租户库的字段快照和治理配置，不会对来源数据库执行DDL，也不会直接转换来源记录。“同步字段”从数据库重新采集快照；“同步变更”方向相反，将已保存快照的字段新增、删除、类型/长度、非空、注释和主键定义同步到来源数据库。未保存的编辑需用户先确认“保存并比较”。结构比较复用同一路由的 `schemaAction=compare`，执行使用 `schemaAction=apply`；客户端仅发送表ID、比较指纹、完整表名及确认标志，不接受客户端连接配置、字段定义或SQL。`dryRun=true`仅比较，绝不执行DDL。

比较先校验当前认证租户及数据源角色范围，再读取本表至多2000个已保存字段；四次业务读取（表、来源、字段计数、字段页）及一次连接配置读取均固定，与20/100个字段无关。物理适配器一次`SHOW CREATE TABLE`获取原生结构，在内存逐字段比较。差异每页20项展示当前值、目标值和影响，服务端生成的DDL直接显示，不再折叠。点击“确认覆盖表结构”即提交当前比较计划，不再要求额外勾选或手工输入表名；客户端沿用接口确认标志与服务端返回的表名，仍保留指纹、权限、范围和重复提交校验。执行重新读取权限、快照及物理定义，指纹变化即拒绝，要求重新比较；结构备份成功后才执行一个`ALTER TABLE`，并重新读取结构核验结果。结构备份默认放根`logs/backend/schema-sync/`，不含连接凭据或业务记录，不构成字段数据备份。

当前物理同步支持MySQL/MariaDB普通表；执行要求MySQL8.0+或MariaDB10.6+的InnoDB表，其他来源明确提示使用原生工具维护。已有默认值、自增、字符集、排序规则、生成表达式及非主键索引等属性沿用完整原生列定义；不从不完整字段快照重建外键或普通索引，生成列的类型/可空性调整及不完整新增生成列需人工处理。变更可能因现有空值、重复值、外键或索引约束被数据库拒绝；删除列会丢失其数据，数据备份由操作者确认。采用单条DDL及严格模式，避免多条DDL部分完成或类型截断；数据库行为见[MySQL ALTER TABLE](https://dev.mysql.com/doc/refman/8.4/en/alter-table.html)和[MariaDB ALTER TABLE](https://mariadb.com/docs/server/reference/sql-statements/data-definition/alter/alter-table)。`TableSchemaSyncTest`覆盖结构属性保留、并发指纹、类型注入和固定读取；`TableSchemaSyncDatabaseTest`可在受限配置指定的验证来源创建临时表，验证真实比较、过期拒绝、确认DDL及数据/索引/默认值保留，结束后清理该临时表。

详情读取使用当前表、所属数据源、字段快照和字典表分页四类请求，不按字段逐行补查。字典候选限定当前数据源、每页最多 100 张；已有字典字段快照按最多 50 张一批读取，与业务字段行数无关，超过 100 张时明确提示维护入口。`tools/tests/test_table_detail_fields.mjs` 覆盖 20/100 个字段均为 4 次基础请求，以及完整导出、可空值、字典规则保留与公式保护；`TableDetailFieldSaveMagicTest` 执行实际 Magic 脚本，20/100 个字段保存均为 3 次 SQL 读取，覆盖跨租户、外表字段 ID、无效可空值拒绝及登记/审批/附件和字典规则保留。字段更新属于写入，写入量随实际修改字段数增长。

Elasticsearch数据源使用已登记的HTTP/HTTPS Endpoint和认证配置；`es`、`elastic`统一识别为`elasticsearch`。索引范围保存在连接配置的`database`（可空或通配表达式），不得用数据源中文显示名代替。一个普通索引对应一张登记表，mapping的对象路径展开为字段；隐藏/系统索引不进入采集。第二步沿用现有后台采集、分页快照和按需字段采集流程，完整索引清单不按500条截断，超过10000个时须缩小范围。

后台采集先请求 `GET /_cat/indices/<已登记索引范围>`，读取索引和统计。若返回 HTTP 403，使用同一连接认证和索引范围调用一次 `GET /<索引范围>/_alias?expand_wildcards=open`，根据响应的索引名登记，统计数据保留为空。ES 6 的该接口也返回没有别名的索引。若元数据同样被拒绝，采集返回失败并提示核对 `view_index_metadata` 和代理路径，HTTP 401 直接报告。连接测试只请求根路径，后续授权由各接口单独校验。字段探查通过 `/_mapping` 批量读取，索引元数据和字段可授权 `view_index_metadata`，需要预览文档时再对相同索引授予 `read`。只有索引统计需要 CAT 对应的监控权限。依据见 [ES 6.8 CAT 实现](https://github.com/elastic/elasticsearch/blob/v6.8.23/server/src/main/java/org/elasticsearch/rest/action/cat/RestIndicesAction.java)、[ES 6.8 别名查询实现](https://github.com/elastic/elasticsearch/blob/v6.8.23/server/src/main/java/org/elasticsearch/action/admin/indices/alias/get/TransportGetAliasesAction.java)及 [ES 6.8 索引权限](https://github.com/elastic/elasticsearch/blob/v6.8.23/x-pack/plugin/core/src/main/java/org/elasticsearch/xpack/core/security/authz/privilege/IndexPrivilege.java)。

ES 6 的 `mappings.<type>.properties` 与 ES 7/8 的 `mappings.properties` 统一为登记字段；旧版多类型字段定义冲突时明确拒绝，不静默丢字段。分页及样例预览兼容旧版整数 `hits.total` 和新版 `{value,relation}`；识别到旧版带类型 mapping 时不发送新版命中数追踪选项。协议回归覆盖两个版本的连接、完整索引采集、监控权限不足时的回退、20/100 项字段读取与预览。现场 ES 账号的授权及网关配置需用实际索引验证。

ES技术适配器负责HTTP、mapping和DSL转换，不执行SQL或平台业务表读写。索引分页只批量读取当前页mapping。20/100个普通短名称索引均为一次索引清单请求和一次批量mapping请求，CAT 403 时各增加一次索引元数据请求。单批至多100个且路径长度有界，长名称按路径预算分批。字段批量入口最多500个索引，任一索引超出登记范围时在远端请求前拒绝，元数据回退结果也按登记范围过滤。租户和角色范围仍由原Magic入口及登记主表校验，ES连接凭据只保存到服务端连接配置，不进入检索投影。

普通数据预览复用原接口，以原生`_search`进行过滤、排序和from/size分页，20/100条均为一次mapping和一次search，不逐文档补查；`track_total_hits=true`返回精确总数，超过默认10000条窗口时需缩小筛选范围。text字段的精确筛选与排序使用已有keyword子字段，缺少时返回明确提示；索引、mapping或分片查询失败不伪报成功。ES不使用JDBC/SQL，不提供本接口的字典类别分组。现有索引只读验证不创建测试索引或业务文档。

共享详情组件 `table-preview` 通过一次 `POST /dst/database/metadata/table/preview-data` 请求取得当前页、字段及中文表头。详情页传 `countMode=none`：服务端托管 MRS Hive 仅执行一次 DESCRIBE 和一次带上限的分页查询，多读取一条判断下一页，向页面返回不超过pageSize条记录及 `total=null、totalKnown=false、hasMore`。页面显示当前页、本页记录数、每页20/50/100条与上一页/下一页，不展示推测的总条数或总页数；失败保留真实错误和重试入口，同表及跨表迟到响应不能覆盖新请求。

该可选模式只改变托管Hive详情预览；其他数据库仍使用原有精确总数分页。接口省略countMode或传exact时保留原精确统计行为，字典分组和其他登记调用不受影响；无效计数模式直接拒绝。`hiveConnectionMode` 为可选连接属性，缺失或为空时仍根据 `metadataAccessMode=server-managed-mrs` 或已登记的 `hiveProfile` 判断托管连接；显式 `open-source` 始终使用该数据源自己的 JDBC 连接，不能因可选属性缺失而发生空值异常。Hive库表仍由当前租户登记和角色数据范围确定，字段、过滤和排序继续使用实际字段白名单。空页不会冒充总数为零，连接/认证/字段/数据查询失败不降级为成功。

首尾页、空表、条件查询与排序均有回归；分页SQL保持兼容旧Hive的ROW_NUMBER方式，不使用需要Hive 2.0+的LIMIT offset, rows，详见[Hive SELECT说明](https://hive.apache.org/docs/latest/language/languagemanual-select/)。结果传输及应用内存有界，不等于Hive引擎无需扫描或排序；大表深分页耗时仍由集群与物理数据布局决定。

验证入口为 `TableDetailPreviewTest` 与 `tools/tests/test_table_detail_preview.mjs`。20/100行详情模式均为1次页面请求、测试中5次固定元数据SQL和2次Hive查询（连接配置及角色计算固定开销另计），返回最多20/100行（Hive最多额外取1行）；精确统计模式仍为3次Hive查询。无权来源、外租户表和越界库名在Hive执行前拒绝。本机开发环境没有MRS客户端配置，真实Hive仅部署于生产；开发回归采用合成结果和查询边界验证，生产连接、授权和大表耗时需在生产发布时验收。

## 数据血缘系统详细设计与静态原型

### 1. 目标、交付范围与业务口径

本设计用于数据表详情的“数据血缘”页签，回答四个问题：数据由哪个部门的哪个库、表、接口或文件提供；经过哪个网络和实际执行节点；由哪个任务传输、解析或加工；最终进入哪个汇聚库、源数据库或服务调用方。数据库 IP、端口、库名、Schema、物理表名、网络与节点是核心信息，不能只显示抽象数据表之间的箭头。

本轮交付是详细设计和可交互的前端原型。共享组件 `table-blood` 替换原来的“暂无数据”，详情壳页签从“血缘分析”改为“数据血缘”，保留组件英文标识和旧 `tab=血缘分析` 链接兼容。页面顶部保留“示例链路”数据角标，删除“静态设计预览”和“点击节点追溯来源”等底部说明；所有节点、地址、部门关联、任务及执行记录仍为示例。没有对当前表查询真实血缘，没有创建业务表、发布新 Magic API 或改变现有任务。下文标为“拟扩展”“拟建”的内容均是后续实施方案。

业务血缘、物理传输和运行结果是三个不同维度。业务血缘关注源对象如何产生目标对象；物理传输补充节点、网络、接口和文件存储；运行结果证明某一次传输或写入发生了什么。登记配置不能当成执行事实，文件投递成功不能当成目标表入库成功，任务运行成功也不能自动证明其所有下游都成功。

“云汇聚库”“原始库”“源数据库”等是业务展示名称，由现有分层、分域及数据源绑定决定；不能把这些名称固定等同于 DST、ODS 或某种物理数据库。原型顺序是展示示例，实际链路以任务、部署与回执证据为准，可有多来源、多目标、分支、合流与循环，也可没有文件中转。

### 2. 当前工程能力与已知缺口

| 能力 | 当前权威来源 | 本设计的使用方式 |
| --- | --- | --- |
| 登记数据源、表、字段 | `db_datasource_t`、`db_table_t`、`db_table_column_t` | 引用真实登记 ID，不复制第二套主数据；展示部门、类型、库表和经授权的连接元信息 |
| 抽取 / 抓取执行节点 | `nifi_node_t`、任务与 Pipeline 已保存节点引用 | 明确节点类型、ID、网络和端点；不能只用“公安网”字符串代替实际节点 |
| 推送接收节点 | `push_node_t`、登记接收配置 | 引用网络、节点编码、节点地址及配置版本；默认节点后续变化不能改写历史事实 |
| 代理服务节点 | `service_node_t`、现用服务登记及关联配置 | 分开显示服务提供方、代理节点和调用方，遵守现有服务权限 |
| 接入 / 分发任务 | `data_access_agg_task_t`、`nifi_pipeline_t`、已部署 DSL | 提取显式源 / 目标引用和实际执行路径；独立画布手工端点允许无登记 ID，保持其来源类型 |
| 字段转换 | `data_access_field_mapping`、Pipeline 显式映射 | 有规则才生成字段血缘，不按字段同名猜测关系 |
| 层域绑定 | `sym_dict_t`、`dwm_center_layer_source_t` | 作为库表展示分组，绑定关系本身不证明发生了数据复制 |
| 上报原件及登记 | `file_upload_t`、数据源 `pool_cfg.reportRegistration` | 区分原件、工作表 / 区域、规范版本、投递成品及投递回执 |
| 加工图血缘 | `LineageAnalysisService`、`dwm_lineage_snapshot_t`、`dwm_lineage_edge_t` | 复用现有 Java 业务能力与关系表，扩展实体类型和证据范围 |

现有 `LineageAnalysisService` 已能推导登记任务源目标、加工图路径及显式字段映射，并记录 DEPLOYED 快照。现有快照仅以 Pipeline 为主体，边主要是 TABLE / FIELD 之间的关系；不能完整表达非 Pipeline 的上报批次、外部文件、网络节点、服务调用及历史端点。现有分析虽然限制返回180节点、360边，但部分内部查询仍全租户读取对象和规则；正式接入本详情页前，必须改为围绕根对象、有界分层查询。不能只把现有服务套一层接口就宣称符合大规模查询规范。

数据上报当前会先把原文件放入通用 MinIO，再解析、由浏览器生成 CSV 并投递 FTP。血缘主视图默认表达“部门文件 → 上报程序 → 投递文件 / 存储 → 后续接入任务 → 目标表”；MinIO 只有在真实存储证据存在时，作为可展开的技术暂存节点展示，不作为五种方式的强制业务环节。当前第三步行修改只进入本次投递内容，完整成品没有作为可恢复版本统一保留；后续上报血缘需补齐最终文件版本 / 摘要 / 存储引用，历史查看才能准确还原当次投递。

### 3. 五种接入方式的链路

#### 3.1 数据抽取（explore）

链路为“部门业务数据库 / Schema / 表 → 抽取任务及执行节点 → 真实目标库表 → 后续汇聚或分发任务 → 下游库表”。节点包含来源 IP / 端口、所属部门、网络、节点编码及执行服务地址。JDBC 直接写入不人为加入 FTP；采用文件交换、跨网交换或中间暂存时，只展示已配置且有依据的中间节点。

来源只有离线登记、没有连接和任务时，只能显示登记对象与“未关联接入任务”。无法确定实际执行节点时显示“执行节点待确认”，不能拿当前默认节点代替。增量水位和调度是任务属性；水位可解释读取范围，不作为一条独立数据来源。

#### 3.2 数据推送（receive）

文件推送示例为“部门系统 / 显式来源库表 → 所属网络的推送节点 → 接收服务 → FTP / 文件目录或其他真实落地对象 → 解析接入任务 → 汇聚表 → 分发任务 → 源数据表”。推送请求只证明请求或文件已经接收，后续落地与入库分别取证。

如果对方只登记了系统和接口，未知其真实数据库 IP，则来源显示“外部系统，内部库表未提供”；不虚构上游数据库。Kafka、对象存储、直接写库或其他接收类型按现有配置替换落地点，不强制经过 FTP。结构化表、附件及附件关联键是不同对象，附件边标为附件依赖，不把附件写成一张已入库表。跨网路径必须有交换或路由配置证据；缺失时显示断点，不补画一条已成功的跨网线。

#### 3.3 数据抓取（capture）

API 抓取为“登记 API 与逻辑表 → 物化目标表 → 创建并部署接入任务 → NiFi 按调度发出请求 → 按登记路径提取响应 → 字段治理和落库”。定时、间隔和仅执行一次使用 NiFi 调度。当前自动同步支持无需认证、无需分页的 REST JSON 全量抓取。FTP 抓取为“来源服务器 / 目录 / 文件规则 → 抓取任务及节点 → 目标文件或表”。

接口来源展示协议、域名或已登记 IP、端口、无敏感参数的路径、请求方法及数据提取路径。多个 API 或多个目录分别形成分支，不合并成一个无法解释的“数据抓取”节点。接口签名、Authorization、密码和含密钥的 Query 均不进入节点、快照、日志或导出。DNS 实时解析结果不能冒充历史来源 IP；只有域名时如实展示域名。

#### 3.4 数据上报（upload / report）

链路为“上报部门 / 文件版本 / Sheet及区域 → 上报程序与实际服务节点 → 规范化成品文件及投递回执 → FTP等实际存储 → 显式接入任务 → 目标库表 → 后续分发”。上传、规范保存、文件投递、目标入库是四个独立事实。

原文件、规范化 CSV、同一文件解析出的多张表分别有身份；文件同名不能作为关联依据。采用真实 `fileId`、登记表 ID、上报 `requestId`、回执 ID、最终成品版本及摘要关联。网络重试沿用幂等语义，不重复生成逻辑关系；追加新文件产生新版本或批次。没有后续接入任务时，主链路截止于投递存储，并提示“后续入库关系未关联”。文件投递成功不能把 FTP → 数据库的虚构边标成成功。

#### 3.5 代理访问（proxy）

主视图展示“来源服务 → 代理服务节点 → 登记服务 → 调用应用”的响应数据流；请求方向为“调用应用 → 登记服务 → 代理节点 → 来源服务”，必须在图例、关系类型及详情中说清楚。可按用户选择切换请求视角，不能把两种方向混成同一条无说明的箭头。

代理访问默认没有物理数据复制。服务底层库表只在提供方明确登记并授权时展开；没有落库任务不出现汇聚库、源数据库。调用日志能证明一次请求及结果，不能证明数据已持久化。服务版本、路由变更和缓存副本如需追溯，分别记录版本或独立对象，不按一个服务名称覆盖历史。

### 4. 统一领域模型

实体使用 `(tenantId, kind, id)` 身份。`kind` 建议包含 TABLE、FIELD、DATASOURCE、FILE、ARTIFACT、ENDPOINT、NODE、TASK、PIPELINE、SERVICE、APPLICATION；部门、网络、层域为归属 / 分组属性，可在展开时显示为容器，不能画成业务数据处理节点。

已登记对象直接使用权威 ID。FILE 对应上传原件，ARTIFACT 对应具体成品版本；ENDPOINT 表示未登记的手工连接或外部地址，按所属任务版本中的稳定节点标识引用，不能把连接字符串塞进 `datasourceId`。NODE 还要有 `nodeKind=NIFI/PUSH/SERVICE/REPORT`，避免不同节点表 ID 偶然相同而合并。示例 ID 与真实 ID 严格隔离。

节点最小响应字段为 `key、kind、id、name、code、ownerOrg、datasourceType、host、port、database、schema、table、networkCode、nodeKind、layer、domain、snapshotId、visibility`；按对象类型取子集。相同 IP 不是同一资产，相同表名也不是同一张表。一个数据库的库、Schema、表分别维护，不通过拼接名称猜关联。

关系建议包含 READS_FROM、WRITES_TO、TRANSFERS_TO、DERIVES_FROM、CALLS、RESPONDS_TO、ATTACHMENT_OF、HOSTED_BY、CONTAINS。数据流分析只遍历对应的数据关系；HOSTED_BY、CONTAINS、部门归属不参与上下游影响计算。代理视图按明确的请求或响应关系遍历。现有 TABLE → TABLE 逻辑边与新增物理路径分别投影，避免把同一关系按每个中间节点重复计为多条业务血缘。

每条边保存关系类型、源 / 目标、形成它的任务或服务版本、证据类型 / 引用、规则摘要、有效时间和状态。一个源目标可以由多个任务产生，不能只用 `source + target` 去重；建议自然键为“租户 + 所属快照 + 源类型及ID + 目标类型及ID + 关系类型 + 规则 / 证据引用”。多输入表达式保留每个明确来源字段，SQL 无法可靠解析时保留待确认规则，不按字段名称自动补边。

### 5. 关系型数据库存储设计

采用现有行业业务关系库保存邻接关系和版本快照，不引入图数据库，不新建第二套数据源、表、节点或任务主表。控制库 `baseline` 仍只保存共享页面 / Magic等控制面资源；行业血缘关系保存到当前租户实际业务库并保留 `tenant_id`。

以下是拟实施的字段演进，**本轮未执行 DDL，也不生成空增量 SQL**。实施时先核对真实结构、兼容现有万象血缘调用，更新所有行业库完整结构及各方言增量，再按仓库结构规范应用和验证。

#### 5.1 扩展现有 dwm_lineage_snapshot_t

现有字段包含 tid、tenant_id、pipeline_id、snapshot_kind、source_hash、captured_at、deployed_at、edge_count、unresolved_count、is_current。保留其含义与现有部署快照，不能让文件批次 ID 假装是 Pipeline ID。

| 拟扩展字段 | 建议类型 / 约束 | 用途 |
| --- | --- | --- |
| scope_kind | VARCHAR(16)，非空 | PIPELINE / TASK / REPORT / SERVICE，标明版本所属业务对象 |
| scope_id | VARCHAR(64)，非空 | 权威业务 ID；老数据回填 scope_kind=PIPELINE、scope_id=pipeline_id |
| pipeline_id | VARCHAR(64)，可空 | 只在实际关联 Pipeline 时填写；兼容原调用 |
| snapshot_kind | 保留 VARCHAR(16) | DESIGN / DEPLOYED / OBSERVED；OBSERVED不是成功的同义词 |
| model_version | INTEGER，非空 | 快照结构版本，控制历史反序列化兼容 |
| node_snapshot | MySQL LONGTEXT / 达梦 CLOB | 有界、脱敏的节点及端点快照，用于还原历史名称、IP、部门、网络、文件版本 |
| source_revision | VARCHAR(128) | 原业务配置或部署版本，不用页面更新时间推断版本 |
| valid_from / valid_to | 时间类型，可空 | 区分事件发生时间与捕获时间，允许迟到回执 |

JSON只保存有界快照展示及证据索引，不作为大规模图遍历的查询对象；当前图从结构化边表查邻接，再按类型批量读权威对象。节点快照限制180节点、360边关联范围、单份2 MiB；大文件只保存对象引用、版本和摘要，不保存业务行、二进制、令牌或原始连接配置。超过上限拆分业务范围，返回截断原因，不静默截断 JSON。

新增索引建议 `(tenant_id,scope_kind,scope_id,snapshot_kind,is_current)` 和 `(tenant_id,scope_kind,scope_id,captured_at,tid)`；保留现有 Pipeline 索引。更新当前版本时锁定所属业务对象，在事务中取消上一当前标记并插入新快照及边；不能仅凭应用层先查后写保证唯一。MySQL和达梦均采用明确事务约束，不依赖某一方言的部分唯一索引。

#### 5.2 扩展现有 dwm_lineage_edge_t

现有结构已有 tenant_id、snapshot_id、pipeline_id、source_kind / source_id、target_kind / target_id、evidence_kind / evidence_ref_id、rule_summary。保留现有 TABLE / FIELD 记录以及源向、目标向索引。

| 拟扩展字段 | 建议类型 / 约束 | 用途 |
| --- | --- | --- |
| relation_type | VARCHAR(32)，非空 | 明确读取、写入、文件传输、调用或响应等语义 |
| view_kind | VARCHAR(16)，非空 | LOGICAL / PHYSICAL，避免中间节点展开后逻辑边重复计数 |
| fact_level | VARCHAR(16)，非空 | CONFIGURED / DEPLOYED / OBSERVED，不将部署当作执行 |
| result_status | VARCHAR(16)，可空 | SUCCESS / FAILED / UNKNOWN；只描述对应证据的这一段 |
| evidence_json | MySQL TEXT / 达梦 CLOB | 最多20条脱敏证据引用，单边不超过32 KiB；完整证据按需详情读取 |
| valid_from / valid_to | 时间类型，可空 | 边在某个版本 / 时间窗口中的有效性 |
| pipeline_id | VARCHAR(64)，可空 | 非 Pipeline 业务不填伪造值 |

多种事实等级不是互相覆盖的单一成功状态。设计、部署及运行版本可以共存；失败运行也是 OBSERVED。通过某任务的一条目标写入回执，只确认该次任务边，不把整个 DAG 染绿。文件接收、文件投递、消息确认、写入提交、业务入库回执必须分别标明证据含义和覆盖范围。

源向 / 目标向索引继续使用 `(tenant_id,source_kind,source_id,snapshot_id)` 与反向等价索引，必要时增加 `(tenant_id,snapshot_id,view_kind,relation_type)`。查询先过滤已授权对象和所选快照，不按大 JSON 模糊查源目标。历史查询按 scope 和时间游标分页，默认20，最大100；不一次加载全部历史。

#### 5.3 文件与运行证据的引用

复用已有上传记录、上报 requestId / receipt、推送批次及既有任务运行记录；NiFi provenance具有保留期，只保存必要事件编号、组件、时间、结果和脱敏摘要，不能把外部短期日志当成永久唯一事实源。没有现用运行记录主表时，实施阶段先核对任务执行模型，再决定最小必要的运行证据持久化，不在前端原型中创建一套平行任务系统。

上报最终成品至少有 `artifactId、原fileId、登记tableId、规范版本、上报requestId、内容摘要、大小、行数、存储引用、生成时间`。内容摘要只是校验文件版本，不作为跨租户复用键。原件和成品生命周期分别配置，删除业务对象只使当前关系失效；审计所需的历史快照按保留策略处理，不能级联物理删除。到期内容清理后显示“文件内容已过保留期”，保留必要的历史结构和证据含义。

### 6. 采集、版本与一致性

登记保存形成 DESIGN；明确部署成功后形成 DEPLOYED；取得推送接收、上报投递或目标写入等运行证据后形成 OBSERVED。保存草稿不会自动覆盖已部署事实；部署失败保留旧的有效版本及本次失败信息。快照内容哈希仅用于幂等去重，包含真实租户、业务范围、配置版本和稳定引用。

注册、部署及执行提交后由现有业务回调 / 后台任务触发派生，不在图查询中反复连接来源数据库、读取全部 NiFi 历史或重建全租户血缘。外部服务调用不放进持有业务数据库锁的事务。采集失败不回滚已成功的业务投递，应记录失败并重试派生；使用业务版本幂等重建，不能因重试生成重复当前快照。后台补偿围绕有界变更窗口或明确 scope，禁止无界扫全租户。

回执可能迟到或乱序：以其业务版本和发生时间关联，不覆盖新的配置。节点改名、地址改变、默认节点切换、部门调整、任务停用后，当前视图按有效记录展示，历史视图按当时快照展示。对象已删除但保留历史证据时，展示“历史对象 / 已停用”，不能悄悄把同名新对象挂到旧链路。

### 8. 批量查询、性能与权限

授权顺序为：校验真实会话及 `tenantRuntime.id()` / TenantContext → 核对根表及数据源的现有 ALL/ORG/OWNER范围 → 有界查邻接 → 每层批量过滤端点的可见性 → 按对象种类批量补齐展示元数据 → 输出可见子图。请求中的 tenantId、部门或创建人只能缩小范围，不决定业务归属。边与快照读写同时加 tenant_id；从边表读出目标ID不代表已自动获得该对象权限。

跨权限边界只显示不含对象名称、IP、数量的“范围外链路”提示，不能利用未过滤统计、搜索、任务详情或历史快照侧漏；相关名称 / 地址按当前权限重新过滤，即使历史快照曾可见也不能直接返回。批量展开中含无权或外租户ID时按统一契约拒绝，不静默丢弃后返回扩大的子图。连接元信息沿用现有权限，禁止返回密码、用户名口令组合、完整含密钥URL；无需新增平台管理员或租户管理员字段。

图查询使用有界广度遍历，维护已访问的 `(kind,id)`，每层将本层全部ID作为有界集合查询，不能逐节点执行SELECT。分别利用源向 / 目标向索引查相邻关系；后续元数据按节点种类一次批量读取。相同深度、相同类型集合下，20和100节点均为1次首屏HTTP；SQL数量随深度和对象种类增长，不随节点数量线性增长。设计预算为 `Q ≤ Qauth + 2×depth + K + Qsnapshot`，授权固定不超过2次、批量节点类型K不超过9、快照选择1次，默认depth=3时预算最多18次SQL；正式实现需计数器验证，不能把这个预算写成已验收结果。

禁止页面 `nodes.map(fetchDetail)`、逐表查询节点配置、逐字段读映射、逐任务读取 NiFi。外部运行证据优先从本地已持久化记录批量读取；用户点击单个任务的实时详情可按单项请求处理。20/100节点及20/100条证据都需要请求数 / SQL数测试，混入跨租户和无权ID时必须在任何外部连接之前拒绝。对图上限之外的链路用“展开”或筛选缩小范围，不无限翻页预加载。

首次范围内图查询目标P95不超过2秒，明确展开 / 详情不超过3秒，作为后续压测目标；数据库规模、索引、真实外部服务和权限分布须纳入测量，本轮静态原型不宣称已达到生产性能指标。

### 9. 页面结构与交互

沿用详情页现有面包屑和 `u-tabs`，页签命名“数据血缘”。图内采用浅中性色、细边框和少量品牌蓝，当前表使用蓝色轮廓及“当前表”文字；数据库、执行节点、文件 / 目录、服务使用同一套系统图标和克制的类别底色。IP / 端口、部门和物理对象编码直接显示，长名称提供完整详情，不靠继续缩小字号容纳。

主视图从左到右安排来源、执行节点、真实中转和下游目标。多来源 / 多目标以分支和合流排列；所属网络作为区域带展示，部署在一个网络的节点不能仅因视觉位置被归到另一个网络。任务是关系产生者，紧凑视图可用边标签加下方任务摘要；展开后展示执行节点、调度、源目标和证据，不要求所有任务都变成同一种大卡片。

当前原型默认以数据推送展示六段链路：“电信预警程序 → 数据推送服务 → 互联网 FTP → 公安网 FTP → 电信预警原始库 → 电信预警汇聚库”。前3个节点属于互联网，后3个属于公安网，各有独立IP；原始库为当前关注对象，互联网FTP与公安网FTP之间明确标记跨网交换。分析控件依次为“完整链路 / 归因分析 / 影响分析”，分别展示全链路、突出来源路径、突出下游路径；其他接入方式仍可切换查看。

画布使用响应视口的平移 / 缩放变换，图内容尺寸按节点和任务布局计算，不限制用户只能在固定长宽内查看。按住鼠标拖动可向任意方向平移，滚轮以指针位置为中心缩放，缩放按钮以视口中心为锚点；缩放范围30%至180%，“适应画布”重新计算整个图的居中位置和比例。拖动超过阈值后抑制节点点击，避免拖完误开详情；仅点击或键盘激活节点时仍可正常查看详情。方向键平移，+ / -缩放，0适应画布；拖动取消、指针捕获释放和组件卸载均清理手势状态。

原型还提供名称 / IP / 部门查找、节点和任务右侧非模态详情以及窗口内全屏。全屏将画布区域展开到浏览器视口，不依赖原生全屏权限；展开时约束键盘焦点，Esc先关闭详情，再退出全屏并返回触发按钮。搜索保留全图上下文并高亮匹配项；无匹配时给出清除操作。详情Esc关闭并把焦点还给触发按钮。按钮保留focus-visible和disabled，尊重减少动态效果。普通详情是非模态面板，不伪装成必须完成的业务弹窗。

五种方式切换仅为本轮方案评审入口，真实功能上线后默认按当前表权威接入方式展示，不允许在详情中随意切换资产的业务接入方式。后续正式功能增加设计 / 部署 / 运行事实视角、历史版本和字段级展开，只有已接入真实能力后才显示相应可用操作；当前不放空的“导出”“创建任务”按钮。

大图只在画布内部滚动 / 缩放，不产生整个页面的横向溢出。常见桌面宽度1275 / 1440 / 1920分别检查工具栏、节点字体、地址完整性、详情面板、画布底部及返回上下文；短屏允许详情内容区纵向滚动，不裁掉任务和缩放工具。

## 异常任务静态原型与接入方案

菜单位于“数据接入 → 数据接入保障 → 异常任务”，路由 `/jr/exception-tasks`，低代码标识 `exception-tasks`，源码为 `lowcode/03.数据接入/异常任务(exception-tasks).vue`。组件保存在共享控制库 `baseline.ui_component_t` 的真实“03.数据接入”目录；当前菜单只在本机公安租户 `baseline_ga` 中新增，关联当前用户已有的任务监控角色，不复制其他行业菜单、不调整既有业务的数据范围。页面从异常概览开始，不显示顶部标题说明栏；六个合成任务支持部门、数据源、异常类型及关键词筛选，展示无效记录数、队列文件数、所属表及异常详情。详情上方为两种异常统一展示醒目的“错误原因”，下方保留字段级异常明细。数据源名称和记录样例保留示例标识；示例不包含真实业务内容，不调用异常队列接口，不操作 NiFi 流程、重试、清空或删除数据，也不新增业务表或数据库结构。

当前 `DslCompiler.buildJavaMapping` 将 `HaitongTransformRecord` 的 `invalid` 出口连到无下游的保留 Funnel，`failure/retry` 连回治理组件。治理组件将无效行写成 NDJSON 错误信封，已有原始行号、规则错误、计划摘要与原始记录快照；对应 FlowFile 带有 `record.count`。读取失败等异常保留原始输入，不能假定每个文件都已逐行校验。FlowFile 内容由 NiFi 内容仓库存储、队列引用由其 FlowFile 仓库管理，不在平台 MySQL 中。这是当前源码生成的拓扑；历史或人工修改过的部署是否一致，正式接入时须核对真实流程及连接关系。

建议先做只读接入：服务端依据当前租户、角色数据范围分页查询任务，批量关联来源数据源、数据表和部门，按受管 NiFi 节点批量读取状态快照，只接受当前任务映射内的处理组与连接；浏览器不直接访问 NiFi 或传入任意连接 ID。已存在 `invalid` 保留队列时，可读取队列文件数，并在用户主动打开详情后有界列举和预览单个 FlowFile 内容。NiFi 提供队列列举请求、状态查询和内容读取 API，见 [NiFi REST API](https://nifi.apache.org/nifi-docs/rest-api.html)。列举请求结束后释放该临时请求，不删除队列文件；预览限制文件大小、返回行数、解析时长并按字段脱敏，不逐行或逐文件自动补查。

队列文件数与无效记录条数必须分开：NiFi 队列状态的对象数统计 FlowFile，一个文件可能包含多条记录；精确无效记录总数不能直接从该对象数推算，也不能在每次打开列表时逐文件查属性或扫描内容。第一阶段建议先展示准确的队列文件数及按需样例，记录总数没有可靠汇总时显示“待统计”。如需页面原型中的精确全队列记录数、错误原因检索和历史留存，需另行确认有界后台汇总/异常采集投影方案，并验证去重、出队、重试、过期及流程重建的计数口径；届时再判断是否补充 NiFi 上报或扩展能力。历史上未保留、已被清空或已消费的内容无法通过当前队列恢复。

本轮仅编译发布该低代码组件、刷新两级缓存并回读及增加本机菜单，静态筛选与20/100分页选项不产生异常业务读请求或 SQL。正式接口的20/100真实任务固定读数、逐ID权限、跨租户隔离、NiFi超时与大队列预览边界，属于确认方案后的后端验收；不将本轮示例数据视为这些能力已经实现。运行材料放在忽略的 `logs/exception-tasks/`。
