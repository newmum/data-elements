## 低代码日志管理

日志管理已收口为一个菜单、一个共享低代码页面 `log-management`，顶部按权限显示登录日志、操作日志、接口日志、安全日志、导出日志、归档日志六个页签；日志策略为同一栏右侧的配置按钮，点击弹窗配置各类别的保留天数与成功请求采样比例。源码唯一位于根 `lowcode/09.系统管理/09.日志管理/日志管理(log-management).vue`，原八个入口/统计组件已核对引用并软删除，不保留第二份页面业务代码。页面仅含页签与配置入口、查询栏、表格和分页，无顶部标题或统计卡；表格以序号、人员、时间、功能路径与具体操作为先。页签复用节点配置所用 Element Plus 页签及系统主题；表格和分页直接使用接入任务相同的全局 DataTable、Pagination，搜索栏沿用接入任务输入框和查询按钮样式，不保留独立的字号、行高、表头及状态标签覆盖。

查询、排序、导出、归档、冻结与权限契约见[公共日志实现说明](data-elements.md#logging-design)。本机结构、所选 Magic 与低代码资源已发布，8088 已按授权换包启动并完成运行回读。真实行业会话隔离、平台/行业登录退出、CSV/JSONL 下载及归档状态往返已验证；实际权限和验证边界见公共说明，演示与生产尚未发布。

本文件是本工程唯一的持续维护说明。功能、接口、配置、部署和验证边界在对应章节原位更新；版本差异通过 Git 查看，不再新增按日期、版本或阶段命名的增量文档。仓库仅保留根目录 README 总入口。

仓库规则以 [AGENTS.md](../AGENTS.md) 为准；数据库现行完整结构见 [db/](data-elements.md#database-schema)。文中保留的设计背景与既往验证只说明当时范围，不代表新环境已验收，也不能覆盖现行租户与身份边界。历史截图、JSON 报告和旧版本评审材料不作为当前文档依赖。

## 工程概览与使用

`data-elements-chengtian` 是澄天数据中台的 Vue 前端工程，面向管理、配置、流程操作、低代码表单和数据要素业务场景，基于 Vue 3、Vite 7、TypeScript、Element Plus、Pinia、UnoCSS、VXE Table 和 form-create 构建。


<a id="overview--功能概览"></a>

### 功能概览

- 登录、权限、动态菜单和动态路由。
- 数据要素业务页面与后台管理页面。
- 动态组件与低代码表单运行能力。
- 字典、WebSocket、全局请求、文件上传、数据表格等基础能力。
- 支持本地代理后端接口和本地 Mock。

动态菜单仅使用后端返回的当前用户权限树，不再由前端补入布控引擎。布控引擎的总览、资源管理、通道布控、输出管理和画布入口已移除，对应静态页面、浏览器配置及专用请求模块一并清理。共享低代码源、控制库组件源码与编译产物，以及四行业租户菜单均已核查，无该模块页面或菜单记录。通用数据服务、NiFi 集成与接入监控继续使用各自现行入口。


### 接入任务与分发任务筛选

两个任务页将实时连接状态放在左侧树标题旁；右侧查询框前的数据源类型筛选与数据源管理共用 `datasource-type-filter`，统一图标、名称和数量角标；筛选名称精简为“全部类型”“人大金仓”“Elasticsearch”“其他类型”，任务页控件宽164px，状态页签保留在左侧；默认提示为“请选择数据源类型”。类型与搜索组成按内容占宽的右对齐筛选组，换行后同样贴右；任务表操作列宽98px，操作内容保持居中。切换树节点保留类型、任务状态和关键词，查询与类型清除均重置到第一页。

`/ods/dataAggPage`、`/ods/hiveTargetPage` 的表级分页支持 `datasourceType` 和 `includeDatasourceTypeStatistics=true`，同一响应返回 `datasourceTypeStatistics`。任务页角标按当前租户有效、已登记且属于本任务类别的数据表记录计数（unit=table），跟随树选择、表名关键词和任务状态，自身类型条件不参与角标计算；未选类型时“全部类型”与分页总数一致，选择类型后该类型角标与分页总数一致。数据源管理继续按数据源个数统计。接入任务排除 ODS 绑定库，分发任务只保留 ODS 绑定库。显式选择空部门或空业务系统返回零，不扩大到全部范围。统计与分页共用同一 SQL 条件，额外一次按数据源分组的 COUNT 聚合，归入各类型，不按表行或类型发起补查。兼容驱动别名及推送、上报、代理接入方式；失败显示未知统计并提供重试，过期响应不覆盖新筛选结果。原有当前租户、有效候选与任务关联校验保持生效。

<a id="overview--本地启动"></a>

### 本地启动

```bash
cd data-elements-chengtian
npm install -g pnpm
pnpm install --frozen-lockfile
pnpm run dev
```

默认端口由 `.env.development` 的 `VITE_APP_PORT` 控制，当前为 `3000`。


<a id="overview--构建命令"></a>

### 构建命令

```bash
# 常规生产构建
pnpm run build

# 严格类型检查 + 生产构建
pnpm run build:check

# 仅执行 Vite 构建
pnpm run build-only

# 单独执行类型检查
pnpm run type-check
```

说明：当前项目存在一批历史类型声明问题，因此日常部署建议使用 `pnpm run build`；需要集中治理类型问题时使用 `pnpm run build:check` 或 `pnpm run type-check`。


<a id="overview--常用环境变量"></a>

### 常用环境变量

```env
VITE_APP_PORT=3000
VITE_APP_BASE_API=/dev-api
VITE_APP_API_URL=http://192.168.175.86:8088
VITE_APP_WS_ENDPOINT=
VITE_MOCK_DEV_SERVER=false
```

- `VITE_APP_BASE_API`：前端请求代理前缀。
- `VITE_APP_API_URL`：后端服务地址，开发环境由 Vite 代理转发。
- `VITE_APP_WS_ENDPOINT`：WebSocket 地址，未配置时跳过 WebSocket 初始化。
- `VITE_MOCK_DEV_SERVER`：是否启用本地 Mock。

<a id="asset-workbench"></a>

## 数据资产工作台

共享 `my-workbench` 的概览、事项分页和导出入口分别为 `POST /dst/statistics/workbench/overview`、`/items`、`/export`，集中在 Magic 编辑器“数据盘点 / 盘点统计 / 工作台统计”分组。概览支持 `section=registration|governance|health|tasks|changes`，省略时保留完整响应以兼容已有调用。首屏固定并行读取这五个区域，各区域返回后立即更新自己的指标、骨架和错误状态，不等待全部完成；失败仅在所属区域提供重试。授权与采集差异查询复用通用函数 `workbenchData`、`workbenchChanges`，不新增 Java 统计业务服务。导出保持现有Excel列结构，复用概览的授权快照去重和接入任务范围，每批最多100个来源；原公共导出接口继续兼容其他调用方。

只有当前认证应用中有效的系统管理员角色 `admin` 可见、可调用全局视图。其他应用的同名角色不授予权限；警种管理员与登记员默认“我负责的”，继续遵循既有 `ORG` 或 `OWNER` 数据范围，角色范围为 `ALL` 的用户在“我负责的”进一步限制本人创建的数据源。租户来自认证上下文，前端不能传用户、部门或租户扩展权限。批量处理清单最多100个表ID，读取前整批核验，存在跨租户、失效或无权ID即拒绝。

标注和登记使用当前有效数据源、表快照，按数据源与不区分大小写的表名消重，优先保留标注及字段信息完整的记录。已标注为 `annotated=1`，登记完成为 `asset_status=2`，未登记完成包含其他状态。字典、业务和日志分类统计仅计算登记完成的表，与数据源管理卡片的“已纳入登记（状态大于0）”分开表达。五步进度分别统计已探查来源、已标注表、全部标注且字典配置已保存来源、全部标注且业务/日志配置已保存来源、结束登记来源；无该类型表不阻塞相应配置阶段。业务配置完成依据保存阶段标记或已完成登记，不能仅因配置JSON非空视为完成。

登记总数与业务类型通过同一条SQL复用消重快照，任务总数与前五项共用一次任务范围扫描。非登记区域使用同一授权条件的轻量CTE，不为统计无关字段反复解析治理JSON；不引入统计缓存，不连接来源库。

字段治理从已保存配置一次批量读取，统计统一格式字段、启用且具有翻译SQL的字典字段、已保存业务配置中时间戳覆盖率。单次上限20000份配置、64MiB；异常或超限显示明确的静态参考标识，不将缺失结果当成真实零值。连通和采集展示最近保存的检查/任务结果；未提供连接信息的数据源显示“未提供连接”，不按历史失败标志判为连接异常。接入任务沿用有效来源、目标、ODS分类及角色授权口径，运行状态来自平台最近保存的流程状态；有流程记录时优先采用流程状态，只有旧任务无流程记录时才回退历史任务状态。任务详情展示最近监控反馈、排队/输入/输出数据包（FlowFile）数量、线程、估算延迟及启动结束时间；数据包不当作表记录行数，缺少监控值时不填零。工作台打开和刷新均不连接来源数据库或逐表探查。

变更统计以授权有效表快照ID及来源建立白名单。新增数汇总每个授权来源最近一次成功探查的 `added_count`，明细按来源展示新增数并进入第二步办理；作业没有新增表关联明细时不能按创建时间猜测具体表。源端缺失清单来自同一成功作业的 `deleted_detail`，逐ID及来源核验；源端未匹配不等于已经确认物理删除。新增汇总行和逐表复核行统一搜索、稳定排序后服务端分页，因此分页记录数与涉及表总数含义不同，抽屉内明确说明。单次最多60000个有效快照、10000个缺失表，每页最多100条；差异记录格式异常或超限时显示明确原因与静态参考标识，不冒充真实零值。本组统计不依赖ES，不主动探查来源数据库。

结构修改差异目前仅保存在一次探查的用户临时视图中，没有完整持久化记录，也没有现用流程持续维护的全局修改投影，不能把检索空结果当作修改数为零。修改数按用户要求保留静态参考；卡片标记“部分静态”，主数仅统计已记录新增与源端缺失，不把静态修改数混入真实总量，修改明细页说明限制。

登记异常必改完整结论及占比、驳回后的待整改表与来源/历史清单、综合健康评分、智能建议置信度尚无完整持久化依据或评分算法，保留原型静态参考并就近标识。导出的独立登记完成时间尚未记录，继续留空，不能用更新时间代替。问题示例不冒充工单；其入口先选择真实授权来源，再进入登记审查。待标注处理清单为本次临时选择，逐项办理使用现有登记工作台，不伪造后台处理成功。视图切换无顶部提示；查询失败在对应区域提供重试，旧响应不能覆盖新视图。

工作台标题下不再展示额外的任务状态口径说明行及口径弹框入口。首次读取、刷新和切换范围时，各区域独立显示并移除骨架屏；已完成的卡片可直接操作，字段治理与业务类型分布分别加载，静态参考在可信范围确认后显示，占位沿用卡片结构并尊重减少动态效果设置；不再用整页加载遮罩遮挡标题和操作区。“数据表标注情况”跳转 `/datasource-manage/index?filter=unannotated`，“数据表登记情况”跳转同页 `filter=incomplete&metric=tableIssues`，分别选中既有“待标注”“未完成”筛选及对应卡片。数据源管理在初次进入和路由参数变化时仅接受既有筛选白名单；筛选不改变服务端租户及角色范围，也不新增请求或逐行补查。

数据源管理搜索框前提供可搜索、可清空的“选择数据源类型”下拉，不增加前置标题。选项、选中值和卡片共用类型图标及配色：推送绿色、上报紫色、代理/API及通用图标蓝色，品牌SVG保持其自身颜色。MySQL、Oracle、人大金仓等使用统一类型别名，推送、上报、代理按卡片的接入方式单列，保留未知实际类型及标准零数量选项。动态选项只从服务端已归类的 typeCounts 统计桶生成，原始 dbTypes 用于补充未知类型的名称；原始 receive 等内部标识已计入“数据推送方式”时，不再重复生成 receive（0），不以隐藏全部零值选项代替归类。选择类型只裁剪列表，切换后收起展开项并恢复首批呈现；清空类型保留其他条件。

本页左侧组织树、总数徽标和类型角标使用 `/dst/database/treeStatistics` 的 `mode=facets` 全量聚合，直接以当前租户有效主表及 ALL/ORG/OWNER 为准入范围，沿用列表对历史校验源名称的排除规则。常规条件用一条分组SQL返回组织、应用、类型及状态数量，不读取完整数据源明细，不受概要1000条、ES候选10000条、列表页数或首屏24张呈现限制。类型角标按当前部门（含子部门）或业务系统、已提交搜索词和状态条件联动，类型自身不进入角标筛选。组织树初始读取同一接口的未筛选全集；其他调用方原有统计契约保留。加载显示省略号，失败显示不可用标识与重试入口，不回退为概要计数或错误的零。

“有变更”使用ES表投影的 composite 聚合游标遍历全部来源桶，每页最多500个ID，再以同一租户、角色及其他筛选条件在主库批量聚合；失效、外租户及无权投影不计入统计。ES超时、分片失败或无效游标整次失败，不返回截断的成功结果。部门/状态/搜索变化合并为150ms后的一个统计请求，过期响应不得覆盖当前条件；仅切换数据源类型不追加统计请求。

### 接入目标与运行状态

复制的接入任务初始为未启动配置；复制的 NiFi 加工图初始为 `SAVED`，公安的流程组标识、部署结果、队列和运行计数全部清除。

已关联的目标表在 `ct_police_copy_targets` 中创建，目标连接属于澄天。加工图的 JDBC 写入节点重绑这些独立目标，不能通过复制结果停止、重部署或写入公安原任务的目标。原目标表也是下一段接入的来源时，下一段来源连接一并指向对应的实验表。

下一段来源迁入MySQL实验库时，`registeredDatasourceId`、`selectedDatabaseId`、`sourceDbId`必须一起指向实验数据源；物理表名和`sourceTableName`一起更新，来源组件采用`source.mysql`，移除旧厂商驱动及owner等连接属性。保留节点标识、位置、连线、过滤及增量配置。仅更新可见连接选项会留下旧达梦/Oracle来源标识，组合链路会因画布与任务记录不一致退回单任务视图，不能把该提示解释成NiFi断线或物理数据丢失。

对原目录中缺少挂接目标的有效表目录，预览指向已有来源表；任务缺少来源目录时补齐来源目录和数据项。数据源、表、目录和属性表中的关联采用同一组新标识。

“复制配置”不代表外部 Oracle、FTP、API、Hive 等网络环境均已恢复连接，也不把旧租户的运行成功复制为新租户成功。启动任务前仍需使用现行页面核对连接、字段映射、调度和实验目标；原有已验证的澄天合成接入任务不受影响。


<a id="police-import-target-schema"></a>

### 公安资源迁入的实验目标结构

`ct_police_copy_targets` 是澄天复制公安接入任务时使用的独立 MySQL 实验目标库，不属于公安业务库或四行业统一的平台业务表。公安原流程组、原写入目标和运行历史不直接复用。

目标表按原登记字段构造；Oracle、达梦、金仓等来源的类型只在这些新实验表中转换为可承载原值的 MySQL 类型。主键列在实验目标中强制非空；未提供精度的 NUMBER 以文本保留原值，过宽的非主键字符串采用 LONGTEXT，避免截断或超过 MySQL 行长度限制。两个 VARCHAR(800) 的完整业务键超过 MySQL 索引长度上限，保留原字段长度，并使用生成的 SHA256 二进制列建立唯一索引；写入的业务键仍为原 ROWKEY，不截断业务值。原数据库及原登记定义不因此修改。

`init.sql` 在实验目标创建后由根工具 `tools/export-db.py` 的 `mysql_export / SHOW CREATE` 完整导出；文件包含完整表、字段、主键、索引及注释，不包含业务记录、连接口令或账号授权。不得对已有运行库执行初始化文件。

维护入口为 `tools/copy-police-resources.py`。复制源快照和回退材料包含受限连接配置，仅存放在仓库外私有目录；运行计划、计数及验收报告位于忽略的 `logs/police-copy/`。

<a id="police-resource-import--工具与验证"></a>

### 工具与验证

维护工具为根目录 `tools/copy-police-resources.py`，默认只读计划；通用连接能力由 `tools/chengtian-maintenance.py` 提供。准备迁入前必须已有独立目标连接，工具不再从合成数据源复制配置。分阶段入口为 `plan`、`menu`、`prepare`、`apply`、`index` 和 `verify`；`reprepare` 仅从仓库外已准备快照重新生成候选内容，写入前仍须重新比较来源配置。

已迁入批次的来源兼容使用`repair-chain`只读规划，再以`repair-chain --apply`执行所选批次；`--pipeline-id`可重复指定当前核对的画布，所选ID必须属于受限复制快照。只处理至多100个明确画布，批量读取当前任务/登记关联并一次校验全部数据源的当前角色范围。仅当画布仍与原复制快照一致、保持SAVED且没有部署痕迹时补齐来源绑定；人工修改、已部署、跨租户、失效或无权引用均拒绝覆盖。执行前保存仓库外受限备份，按原DSL、版本时间及当前任务/登记关联进行原子并发比较，任一冲突整批回退。此操作不重建表、不写来源数据、不操作NiFi，也不在打开画布时隐式修复。

读取采用固定租户及每页 1,000 条的游标，限制单表和本批总记录数。关联预取后在内存中逐 ID 校验；写入按有限批次执行，不按列表行补查。首次写入前保存受限回退材料，目标 ID 已存在时不覆盖；中断后只允许核对并复用本批定义一致、仍为空的实验表。

ES 资产投影从当前澄天主表及白名单属性重新生成，按每批 200 条写入澄天独立索引。连接口令、令牌、连接池设置及治理快照不进入 ES；已退役的合成目录和业务明细不再进入索引。

日期属性统一转换为带时区的标准日期；无法解析的日期只从检索投影省略，数据库原值保留。登记、标注和连接状态沿用实际主表，不统一标记成功。资产投影不再附加合成业务索引和模拟标记。

超市列表直接使用现有 `tenantEs` 查询租户索引，不再先通过另一套客户端额外检查索引存在性；索引不存在时仍返回空列表，其余查询错误继续报告。收藏、购物车和申请状态保持按租户批量关联，页面不按行补查。

验收包括菜单位置与页面、真实澄天会话、导入资源关联、空的独立实验目标、未启动的新任务、20/100 行的请求与 SQL 数，以及无权或异租户 ID 的拒绝。运行材料位于根目录 `logs/police-copy/`，不提交 Git。


## 数据服务登记与代理访问

数据源卡片的蓝色主操作、编辑与删除按钮使用 Element Plus 的原生图标位置，加载时在同一位置替换为转圈图标。图标固定为14px方框，SVG不再设置偏移边距，保持旋转中心和文字位置稳定。代理访问卡片底部只显示“数据服务 N 个”和“接入方式：代理访问”，数量来自同一概要响应的 `serviceCount`；无服务时显示0。

`departmentDataSources` 先按当前租户及数据源菜单范围确定有效父数据源，再将其中代理访问的ID一次传入聚合查询，最多1000个。服务计数按服务列表使用的 `DATA_SOURCE` 角色范围再次过滤，不继承可能更宽的数据源菜单范围；排除其他租户、已删除服务和未关联服务。20/100个代理数据源均为4次业务SQL和2次ES请求，普通非代理概要仍为3次业务SQL，角色计算固定开销另计。`ProxyDatasourceCardCountsMagicTest` 覆盖ALL/ORG/OWNER、菜单ALL但服务OWNER、零服务及跨租户/软删除/孤立服务，不能逐卡片请求服务列表。

数据源登记中的“代理访问”以当前数据源为归属保存数据服务。新建且尚未保存的数据源的服务表为空，不请求全部门服务；先显式保存基本信息，再点击“登记服务”或“下一步”打开当前数据源的服务登记工作台。数据源主记录沿用 `db_datasource_t`，`pool_cfg.accessMode=proxy`，不要求物理连接或数据库表元数据。服务以 `api_info_t.datasource_id` 关联该主记录，保持 `resource_id` 的既有含义；该字段可以为空，历史未关联服务继续在数据服务管理中保留，不按部门或名称自动归属。

登记页标题为“当前数据源已登记服务”，支持服务端分页、名称与更新时间排序、名称／编码／地址搜索。工作台的列表、用户点选详情、新增草稿和保存都带同一数据源标识；“保存并新增”保留归属，成功关闭后刷新当前数据源的服务表，不跳到全局列表。登记弹框复用外层已授权的数据源摘要清单，其他入口使用既有 `mode=summary` 轻量查询，不重复拉取完整表元数据清单；代理源不初始化数据库表元数据，也不计入直连失败统计。服务列表接口先核验父数据源的认证租户及角色范围，再叠加服务自己的 ALL／ORG／OWNER 范围。保存接口校验父源存在、未删除、可访问且为代理访问；租户、创建人和部门来自服务端，普通编辑不能转移既有服务的数据源关联，省略字段时保留原关联。

外部数据源卡片展示“接入方式：代理访问”，主操作为“登记服务”，不展示数据库表标注指标。点击源名称或卡片复用登记第五步 `register-confirm`，上方使用公共数据源信息区并展示“代理访问”，下方仅列出当前源已登记服务的分页表格。第一步保存源信息、登记服务后，“下一步”跳过第二至四步进入同一个第五步；返回时直接回第一步。原共享 `detail-page` 中的代理专用分支、查询和样式已移除，不新增低代码详情页。未保存新源不请求服务；20／100行均为1次服务分页请求，后端SQL数固定为4次，且同时校验父源和服务自己的当前租户、ALL／ORG／OWNER范围。结束登记重新核验已登记服务，按当前角色服务范围一次聚合并在原子更新中再次校验存在性；20／100项完成核验均为2次读取，不读取物理表元数据。

数据服务页使用同一部门范围，主登记入口称为“登记数据服务”。列表保留服务状态和关键词筛选，不再提供请求方式筛选；与代理访问服务列表统一展示服务名称、请求方式、服务地址、状态及更新时间，并保留操作列。操作按钮组撑满单元格，编排、编辑、删除均匀排布，首尾按钮到左右边界采用相同内边距。服务编码显示在名称下方，不再按窗口宽度隐藏核心列，必要时在表格容器内横向滚动。服务分组节点的编辑、删除操作使用透明背景，与树节点悬停和选中背景保持一致。代理跳转使用 `register=1` 标识本次登记意图，关闭登记框后再移除，不在打开时清理，以兼容按完整地址重建的页面。服务登记采用动态表单与低代码组合：`api-register-content` 通过 `$form.loadDefinition("登记API服务")`，按当前租户及 `$setting.systemCode` 从 `sym_form.form_json` 读取完整规则；`api-register-modal` 负责多条登记、草稿切换、部门服务分页和保存流程。表单配置不再与登记页各维护一套字段规则，详情查看与编辑也复用这一配置。

当前公安租户的“登记API服务”包含12个数据字段，分为基本信息、访问配置、服务参数及请求/响应示例页签。两个入口复用 `api-register-modal`，标题统一为“服务登记”，数据源入口仍按当前数据源筛选和保存关联。访问配置依次为整行服务地址、整行请求方式、并列的访问协议与返回格式；不再显示发布路径、共享类型、更新频率和资源分类区域。已有服务保留这些隐藏字段的历史值，新服务的发布路径由服务地址生成。校验错误在单元格内占位，不覆盖下一行。

字段标题、顺序、分栏、必填/只读、字典、默认值、请求方式选项及间距、参数表列与工具栏、请求/响应页签及编辑器均在规则数组中定义。参数表使用通用 `FormTable` 适配现有 `VTable`，把新增、编辑、导入、移除后的行同步到 `publishParams`；参数校验由该字段的数组/对象校验规则声明。服务参数标题与导入、导出、新增按钮同一行，按钮靠右，参数表不再增加外层表单边框和说明文字；示例仅保留页签，不再显示“调用示例”标题。`CodeEditor` 作为原生动态表单字段使用，两个示例分别绑定 `requestExample` 和 `responseExample`。稳定字段名对应现有保存接口，新增业务字段的持久化仍须扩展接口契约，不能只增加一个输入框就视为后端已支持。

访问协议和返回格式继续使用当前租户的 `accessProtocol`、`returnType` 字典。常用选项源见 `docs/assets/data-elements-chengtian/dictionaries/服务登记.json`：协议补充 HTTP、HTTPS，返回格式包含 JSON、XML、纯文本、HTML、CSV、文件（二进制），保留既有 `restful` 等自定义项与记录标识。字典项是登记的接口元数据；不会因此启用新的传输协议实现。当前精简表单及补充字典发布到本机实际绑定的公安库 `baseline_ga`，其他行业既有表单、环境和字典保持独立维护，不能用模板覆盖其自定义配置。

可审阅的初始规则模板见 `docs/assets/data-elements-chengtian/forms/登记API服务.js`，运行时仅消费租户表单配置，不从该模板或低代码内置字段列表回退。共享页面改造时分别迁移四行业租户中 `env=公安`、仍为原始两项规则的默认记录，保留各自记录标识、租户、环境和 `form_config`；广电库已有的另一份 `env=海渔` 配置保持原样。后续按各租户实际配置分别维护，不能用模板全量覆盖自定义表单。每次打开登记工作台读取一次最新定义，切换草稿复用已加载定义；缺失、空规则、重复同名记录或语法错误时显示错误并禁止保存，支持重试。

动态表单渲染器的 `responsive` 能力按实际容器宽度调整分栏：不足820px时单列，不足480px时标签置顶。服务登记内容和数据源基本信息启用此能力，保留原动态规则、必填校验和字段值；输入框不超出容器，单选和复选选项自动换行。服务登记弹窗挂载到body，使用视口高度、固定头尾与独立内容滚动；小屏将服务草稿列表放在表单上方，避免嵌套弹窗裁切或保存按钮被挤出视口。

数据抓取中的API配置支持HTTP/REST与WebService两种协议，继续复用`api`数据源和`apiPullItems`扩展配置。WebService支持SOAP 1.1/1.2、WSDL 1.1本地绑定操作解析、手工服务地址和XML请求体，复用现有Basic/Bearer/API Key/OAuth2测试认证。读取WSDL仅提供操作、地址、版本及SOAPAction，不代表业务调用成功，不更新已登记数据源的连通状态；导入的WSDL/XSD不自动联网加载，可手工填写相应SOAP请求。实际连通测试按所选SOAP版本发送POST/XML，并从SOAP Body推断字段及记录集合，提取路径使用去除命名空间前缀后的元素名；SOAP Fault即使返回HTTP200也判定失败并显示原因。请求中的DTD和外部实体被拒绝，XML响应最多5MiB、40层、20000个元素。请求协议、XML、SOAPAction与响应字段配置随登记保存，认证秘密继续仅供当前测试使用，后续任务使用凭据标识。

登记三步引导仅用于数据抽取的无连接状态、数据推送和数据上报，统一复用 `AccessOnboarding`。推送的模板下载、上传操作与引导标题同行靠右；抽取的连接选择和“切换其他类型”位于左侧，导入操作位于同一工具栏右侧。步骤标题为 16px、说明为 14px，窄容器自然换行，不通过缩小字号适配。API 抓取直接展开首条可填写配置，已有定义继续回填；代理访问使用服务列表的简洁空状态。数据上报支持 CSV、Excel、TXT、JSON，规范编辑后统一生成单表 UTF-8 CSV 投递；格式规则见 [海通上报工作台](data-elements-haitong.md#data-report)。

表单配置页使用与运行页相同的规则解析器，保存前检查数组结构、组件类型和嵌套字段重名，并重新读取所选记录核对规则是否已被其他编辑者更新。保存与重命名携带完整的 `tid/formName/formJson/env/formConfig`，保留辅助配置；保存期间阻止重复提交，保存后清理旧缓存，重新打开业务表单即可生效。多条登记的权限校验、接口载荷与保存事务留在现有低代码和服务端，不在表单表达式中重复实现业务后端。

当前渲染包为 `@form-create/element-ui@3.2.31`，可视化设计器为 `@form-create/designer@3.3.1`。本次不升级依赖：现版已经覆盖所需的原生组件、事件、嵌套布局、自定义组件和数组校验，并已完成实际登记验证。官方 Vue 3 渲染器已有 [3.3.5](https://www.form-create.com/v3/guide/update/3.3.5)，后续升级须对现有各类表单单独回归；不要直接安装该包的 `latest` 标签，当前该标签仍指向 Vue 2 分支。升级渲染器也不能替代部门范围、草稿状态和服务保存等业务流程。

登记弹框左侧提供本次登记列表及本部门已登记服务的分页搜索，右侧编辑选中的一条服务。支持添加多条待登记项、切换时保留各条未保存的字段/参数/示例，以及“保存”和“保存并新增”；保存后保留真实服务ID，继续修改不会重复创建。关闭或移除含未保存内容的草稿须确认，已保存的服务不提供草稿移除按钮。暂存内容仅在本次弹框会话中保留，不跨刷新保存；同一会话最多同时编辑100条。已有服务列表每页20条、最大100条，只读列表摘要，用户主动选择时才请求单条详情；列表使用 `serviceCreateType=api` 收窄为直接登记的服务，编排生成的服务继续由编排页面维护。

登记内容按基本信息、接口信息、参数信息与调用示例组织，省去重复的顶部介绍；请求方式独占一行，选项之间保留间距并允许换行。参数表的自动高度按全部行自然撑开，不在表内增加纵向滚动，编辑区统一滚动；宽参数表仍可在自身容器横向滚动。调用示例页签占满表单编辑区宽度，请求示例默认可编辑，初始规则模板中的请求和响应编辑区高度为280px；请求与响应分别保存，参数可为空，保存失败保留填写内容。左侧“服务列表”旁的角标统计当前页实际列出的服务和草稿，已打开服务去重，不再显示“本次登记”及初始空列表说明。服务描述默认显示三行；底部“保存”保留保存图标，“保存并新增”使用文档新增图标。服务地址支持 HTTP(S) 地址或已有服务的相对路径；登记操作只保存服务定义，不调用该上游服务。

服务登记左侧列表直接复用数据源登记的 `left-select` 组件，使用同样的单行布局、选中底色和实心状态图标。工作区自行控制选中项与分页，搜索和列表刷新不自动切换正在编辑的服务；草稿移除、未保存修改和切换保留机制继续有效。

服务参数在序号后通过“参数类型”选择入参或出参，原字符串、数字等类型列改称“数据类型”。方向沿用现有 `paramScope=request/response` 与 `api_param_t.param_scope`，兼容 `res` 标记；同一张表支持登记、导入和导出两种方向，缺少方向的旧格式默认入参，非法方向阻止保存。导入替换前提示影响数量；CSV 中的 JSON 引号、逗号、换行和前导零按文本保留，表格原生导入继续负责字段校验和载入，其他已支持格式保持原导入方式。

“是否必填”在服务参数中统一使用字符串 `1/0` 保存、以“是/否”显示，不直接套用值为 `true/false` 的通用字典。读取、导入和保存兼容布尔值、字符串 `true/false` 及“必填/可选”等旧值，避免下拉选择为是却误存为否；修复值域映射，不批量改写既有业务记录。

请求示例只取入参，响应示例只取出参，优先使用示例值，其次默认值，并按数据类型生成 JSON 值。已有参数且示例尚未初始化时首次自动生成；新服务首次进入对应示例编辑区或页签时生成一次。随后参数变化不会覆盖示例，页签栏最右侧统一提供一个“自动生成”按钮，仅重新生成当前选中的请求或响应示例，替换已有内容前须确认。一次生成状态随服务扩展信息保存，手工清空、保存或切换后不会反复补回示例。

服务列表、分组计数、详情与保存均从当前会话取得租户和角色范围；部门列表再按登录账号的实际部门收窄。客户端不能通过传入组织或租户标识扩大范围，新服务的所属部门和登记人由服务端赋值。现有服务修改仍须逐对象校验角色范围。共享低代码和 Magic 的唯一版本源分别为根目录 `lowcode/`、`magic/`，发布到控制库 `baseline`，业务定义保存在实际租户库，不创建第二套服务登记后端。

维护验证使用 `tools/tests/service-registration-ui.test.mjs` 与 `tools/tests/ServiceRegistrationMagicTest.java`。20/100 条列表均为一次分页请求、3 次业务 SQL 和一次批量脚本关联查询；分组计数均为2次 SQL，更新20/100个参数均为2次前置读取，详情均为4次读取，角色计算固定开销另计。异租户、无权对象及伪造部门均有拒绝或排除验证。

## 节点配置

后台管理的“节点配置”统一使用 `#/node-config`。原 `#/register/nifi-node-config` 和 `#/register/node-config` 保留跳转，菜单权限与低代码组件标识 `nifi-node-config` 不变。

抽取、推送节点的行内保留连通检测及适用的同步配置操作，编辑和删除收进“更多”，不提供复制菜单。推送节点不展示底层工程名称，编辑说明、连通检测与同步提示使用中文业务名称。

页面分为数据抽取节点、数据推送节点和数据服务节点。抽取节点继续使用 `nifi_node_t`；推送节点使用独立的 `push_node_t`，按当前租户的所属网络字典分组，不混入 NiFi 任务的节点选项。三个网络的示例地址仅供配置参考；没有部署的节点应停用，启用前先替换真实服务地址并执行连通检测。

登记数据源的“数据推送方式”将“推送频率”和“推送地址”放在同一行，频率在前，默认“非实时（10MB–1GB）”，另一选项为“实时（100KB–10MB）”；大小范围随频率一起保存，不另设大小下拉。已有实时配置回显为实时。推送地址与节点管理共用 `POST /ods/nifi-node/page` 的 `nodeType=push` 配置，按当前所属网络选择已启用的默认节点，或该网络唯一启用节点，拼接 `/api/v1/data-push`。未配置、加载失败或多个节点未指定默认时显示明确提示，不回退到演示地址或抽取节点地址。节点配置在登记组件初始化时只读取一次，切换数据源和网络只在已取得的配置中匹配；节点列表 20/100 项仍为一次请求、2 次业务 SQL，租户条件覆盖整批节点。

推送节点左侧图标显示最近一次连通检测结果：绿色可连通、红色不可连通、灰色尚未检测。鼠标悬停或键盘聚焦会显示状态说明、检测时间和耗时。检测由用户点击触发，列表不自动逐节点探测；推送节点检测结果保存在当前后端进程缓存，刷新页面可回显，服务重启或节点地址变更后恢复灰色。启用开关与连通状态分别显示，启用不等于可连通。

推送节点的“同步配置”打开清单弹窗，简短询问“确认将以下配置同步到某节点？”。清单按数据源列出数据表、字段数、节点实际状态和最近同步时间，状态分为未同步、已同步、待更新、未确认；表名同时展示中文和英文。清单每页20行，本地切页不补查；未纳入的来源单独列出原因。预览从所选节点的实际镜像取状态，不用平台发布时间或节点最近成功时间推断。读取失败显示未确认，可刷新清单后同步。确认会同步清单内全部有效配置，包含已经同步的表，保持完整快照语义，不提供截断快照的逐表勾选。同步成功后保留同一清单，逐表展示成功结果及汇总；失败或保存回执不完整时不展示成功。弹窗适应窗口高度，内容滚动，底部操作始终可见。

`POST /dst/database/push/sync` 的清单请求为 `{all:true,nodeId,preview:true}`，响应包含 `rows`、`sources`、`skipped`、`planHash`、`requestPath`、`targetUrl`。预览只读，批量读取当前可信租户的登记配置，并向节点发送一次 `REGISTRY_SYNC / STATUS` 请求。确认请求为 `{all:true,nodeId,planHash}`；服务端重新计算规范化清单摘要，源、表、字段、版本或目标变化返回409，要求刷新后重新确认，避免确认范围漂移。原 `{all:true,nodeId}`、单源 `datasourceId` 及本地只读 `dryRun:true` 保持兼容；`dryRun` 不调用节点。上限100源、1000表（每源100张）、10000字段和1MiB，超限整体拒绝。身份、当前行业库、可信租户和逐ID源/表/节点有效关联校验保留；按照登记业务约定，不叠加菜单 ALL/ORG/OWNER 范围。

接口地址在清单和结果中显示：平台发起 `POST /dst/database/push/sync`，当前本机后端完整地址为 `http://127.0.0.1:8088/dst/database/push/sync`；所选本机节点接收 `POST http://127.0.0.1:18083/api/v1/data-push`。后者统一使用 `deliveryType=REGISTRY_SYNC`；预览附加 `registryAction=STATUS` 和批量表引用，正式同步提交完整 `datasources`。目标始终取已保存且启用的当前租户节点，不接受请求指定租户、目标地址或服务凭据。同步只传登记配置，不发送业务记录或签发业务密钥。

20/100张表的页面预览均为1次请求，确认加1次提交及1次节点列表刷新，切页为0请求；平台预览为固定9次业务SELECT和1次节点请求，正式同步固定10次SELECT和1次节点请求。接收端状态查询固定2次镜像SELECT，另有HTTP审计固定开销；不写同步账本或镜像。测试覆盖真实指纹匹配、单表待更新、过期清单在写入/外发前拒绝、远端额外ID拒绝、跨租户节点/来源拒绝及完整回执校验。


## 数据文件上报登记

数据源登记第一步选择“数据上报方式”后，始终展示“选择数据源并上传文件 → 规范数据表登记信息 → 选择数据表并上报数据”的三步图示引导，不执行文件上传、解析或字段编辑。顶部保留完整五步导航；点击“下一步”先保存基本信息，再关闭登记弹框并进入海通 `#/report?datasourceId=...`。新数据源及没有上传记录的数据源只展示引导；已有记录时在引导下方使用共享 DataTable 展示序号、数据文件名称、字段数、数据量、状态及最近上报时间，表格按当前页实际行数自适应高度，保留服务端分页和排序。字段数累加文件内各表的实际字段数量，缺少字段列表的历史条目才回退到已存字段数，不能用表数代替。文件读取失败保留引导并提供重试，旧源迟到结果不能覆盖当前源。外层数据源卡片通过同一概要查询中的 `reportFileCount` 判断是否已有文件，已有文件时标题、卡片及“数据上报”按钮直接进入对应源的工作台；编辑仍打开引导、只读结果与基本信息。三个入口均传递去除认证参数的返回地址，工作台的正常返回与错误页返回都回到进入前的页面。

文件上传、区域识别、规范整理和投递统一在[海通数据上报工作台](data-elements-haitong.md#data-report)完成。已有文件、登记表和字段沿用 `file_upload_t`、`db_table_t`、`db_table_column_t` 及 `pool_cfg.reportRegistration`，不新增物理表。普通基本信息保存保留服务端已有清单，上传清单使用版本校验和短事务防止并发覆盖。登记流程中为上报增加的跳过步骤、文件校验前置条件和审查豁免已移除；非结构化文件登记的独立流程继续保留。

`POST /dst/database/metadata/report-registration` 的 `history` 动作提供只读服务端分页和白名单排序，`receipts` 分页读取真实上报回执。20/100份文件结果均为一次页面请求、一次租户限定 SQL；外层20/100卡片仍使用固定查询数，不逐数据源读取文件列表。上传工作台所用 `list`、`parse`、`save` 与提交接口均核验可信租户及每个文件、表和数据源关联，传入外源 ID 整批拒绝。运行及权限回归见 `ReportRegistrationMagicTest`、`ReportSubmitMagicTest`、`DatasourceCardTypeCountsMagicTest`、`tools/tests/report-registration.test.mjs`。

## 登记第一步的密码查看

第一步的连接密码和密钥输入框在新建草稿、尚未首次保存时保留眼睛按钮。是否已登记以当前记录的持久化主键判断，草稿展示编码不算已保存；保存成功后立即隐藏眼睛，再次进入已有数据源也不显示。鼠标停在对应输入框内按住 Ctrl 可临时查看，先按 Ctrl 再移入同样有效；键盘聚焦输入框后也可按住 Ctrl 查看。松开 Ctrl、移开鼠标、输入框失焦、离开窗口或标签页、关闭登记窗口、切换数据源或连接类型都会恢复隐藏。API 抓取存在多个接口时，临时查看状态按接口及字段隔离，不会同时显示其他接口的密钥。

此交互只改变当前输入框的显示类型，不发起密码读取接口、不改密码值及保存协议。新建转已保存、切换数据源或连接类型时重建密码输入框，以清除输入组件自身的眼睛开关状态；卸载时移除键盘和页面事件监听。验证入口为 `tools/tests/registration-password.test.mjs`。

## 登记审查中的推送规范

第一步的数据推送方式使用与数据上报相同的 `AccessOnboarding`。非结构化数据展示“登记文件信息 → 查看推送规范 → 推送文件数据”，先登记文件定义，再查看文件集合、分片上传与认证要求，最后推送实际文件；结构化数据展示“登记数据信息 → 查看推送规范 → 推送业务数据”，三步标题统一为六个字，先登记数据表和字段，再查看接口地址、字段约束与认证要求，最后提交数据。两类引导在导入前后均保留，下载和上传按钮位于引导标题右侧。非结构化引导不再显示常驻的下一步提示及模板必填项说明，真实导入错误与未保存提示继续显示。结果框与上方引导保持20px间距，文件定义及结构化导入结果表按当前记录自然撑高，列宽自适应并允许长内容换行，避免结果区内部滚动。

数据源登记顶部始终保留“登记数据源、探查数据表、登记字典表、登记业务/日志表、登记内容审查”五步导航。非结构化推送与代理访问仍在实际执行时跳过中间三步，导航继续显示第五步的原编号；跳过项不作为可点击的返回目标。左侧数据源列表预留固定滚动条空间，使有无滚动条时状态对勾的横向位置一致。推送信息条统一使用六字标签“推送数据类型”“推送数据地址”，地址框最大宽度360px，空间不足时缩小并截断显示，悬停保留完整地址。

第五步“数据表信息”统一使用与文件登记审查相同的 `DataTable` 紧凑表格，保留标题、搜索框、筛选和标题到表格的间距。中文名称、英文表名、对象类型、业务类型、字段数、登记检查、接入状态、同步频率、接入数据量及各项同步时间分别展示；行内不堆叠多行说明，不再提供行展开。字段数保留用户主动打开字段预览的入口，编辑、接入申请和同步管理操作仍按原权限执行。宽表仅在表格内横向滚动，操作列固定在右侧。

列表继续使用既有服务端排序分页与当前页批量接入摘要；`DataTable` 分页插槽沿用当前查询状态，只展示已经取得的一页，不增加逐表读取。结构化推送规范的表折叠项使用正常内容容器承载 JSON 示例和字段约束，不能用没有指令的 HTML `template` 包裹默认内容。`push-contract-review.test.mjs` 通过实际 Vue 编译和渲染验证展开内容中存在可见 JSON 示例，避免仅验证示例生成函数而漏掉页面空白。

第五步的数据表审查不限制数据源总表数，列表每页最多100张。完整范围向 `/dst/database/metadata/tables/review-order` 传 `allTables=true`，由数据库去重、排序及分页，不再随每次翻页上传整份表名清单。搜索和问题筛选保留精确表名范围，服务端用一次前向只读游标核对当前租户、当前数据源内的每个名称，只保留当前页及待校验集合；不存在、其他数据源或跨租户名称整批拒绝，不使用巨大IN或逐表查询。完整范围与名称范围不能同时传入。两种模式均先按数据源管理的ALL/ORG/OWNER范围校验所属数据源，不能通过扩大审查范围越权。20/100行的排序分页均为1次请求，完整范围均3次业务SQL，筛选范围均2次，角色解析的固定开销另计；本页接入任务仍使用一次批量摘要请求。`TableMetadataCollectionPagingTest`和`tools/tests/registration-review-paging.test.mjs`覆盖3万张表、1.5万张筛选、首尾页、排序、空结果、过期响应及租户/角色边界。元数据快照未就绪时不发起排序请求，空筛选清除旧错误，真实读取失败保留就地重试。

第五步进入后即可主动获取当前数据源的 X-Api-Key，无须先结束登记。查看规范本身不签发或轮换密钥。获取或轮换时，平台按当前租户校验数据源及推送方式，发布其中已登记表的字段规范，同步海通镜像和调用方授权，再签发密钥；不修改数据源总体登记状态。暂无已登记表时也可签发数据源密钥，空表镜像不授予任何表访问权限。首次签发只回显一次明文，重复获取只返回状态，显式轮换使旧密钥失效。认证区域依次展示 Content-Type、X-Api-Key、Idempotency-Key；表数据为application/json，附件原始字节为application/octet-stream。请求体参数完整展开，移除schemaVersion和occurredAt，版本由服务端维护。网络、权限或响应归属错误原位显示；无已发布表时展示登记字段，不编造规范版本。

第一步推送模板的“数据字段”增加“是否关联附件”“附件大小上限(MB)”“附件格式”三列。旧模板缺少这些列时按无附件处理；关联附件时要求字符串字段，长度至少36，大小上限为1至1048576的整数MB（1MB=1048576字节），格式为jpg/jpeg/png/pdf/docx的非空集合。扩展名不区分大小写、允许前导点及中英文分隔符；服务端仍校验整数字节上限和格式白名单，不能绕过Excel检查。附件字段保存fileId，不填写Base64或文件原文。

附件限制保存在已有 `db_table_t.field_governance_config.attachmentFields`，后续第三、四步治理保存保留该段，以第一步重新导入更新为准。发布时限制纳入规范摘要和版本，并保存到 `data_push_schema_t.delivery_config.attachmentFields`；节点批量同步与单独发布使用相同属性顺序，不能丢失配置或生成不同摘要。无需新增物理列。

登记审查按当前数据源已保存的推送类型展示规范，结构化与非结构化统一使用“数据推送接口规范”标题，已发布状态统一为绿色“已发布接口规范”；草稿、读取中和读取失败按实际状态展示。结构化请求使用 application/json，展示 deliveryType、datasourceId、tableName、可选 batchId、records 及登记表字段和 JSON 示例；示例使用 FTP，已配置并获授权的 Kafka 通道可使用 KAFKA。密钥区展示当前数据源凭据的同步状态和轮换入口，明文仅首次生成时展示。

非结构化上方“文件推送接口”统一为 PUT /api/v1/data-push，multipart/form-data，默认普通文件single模式，也支持 /api/v1/data-push/single 别名。页面使用相连的分段组件切换“普通文件”和“大文件（分片续传）”，模式说明显示在“文件推送步骤与请求参数”标题右侧并随选择更新，切换组件与第一步采用紧凑间距：普通文件仅展示一次性上传并提交、查询投递结果两类接口；大文件展示初始化、分片、完成并提交、查询结果，断点续传作为可选项。公共请求头集中展示，multipart的boundary由客户端自动生成。文件类别参数统一使用fileCode；原始fileName、大小和摘要在普通模式由服务端从文件取得，分片初始化才需另填fileName、size和可选sha256。候选类别来自当前授权快照，不逐文件向节点探测。文件推送各接口请求示例统一按HTTP请求报文展示，普通文件展示multipart表单分段，大文件按实际接口展示JSON或二进制请求体。请求示例默认展开，使用灰色静态标题，与右侧“复制请求示例”按钮水平对齐，不重复显示步骤名称；结构化推送复用同一示例标题栏。

大文件初始化的sha256仍为可选整文件摘要，分片X-Part-SHA256必填；普通文件无需填写大小或摘要，服务端流式计算并校验。页面保留大文件摘要说明及Linux/PowerShell获取示例。

登记模板新增必填“文件英文名”（fileCode），小写字母开头，仅小写字母、数字及下划线，最多80位，同一数据源内唯一。文件名称仍为展示名，文件说明保留业务说明。旧模板可继续读取；已有集合编码及上传记录不改写，旧记录可补充一次英文别名，已设置的英文别名保持稳定。别名保存在现有field_governance_config.fileRegistration.fileCode，节点配置file-code映射至原collection-id；新文件默认以fileCode作为集合编码。保存前统一批量校验当前租户、角色范围及关联ID，不新增物理表或列。

第一步文件模板结果仅保留已登记文件数量、下载/上传操作及真实错误、未保存状态，移除“文件登记模板导入结果”小标题和上次成功保存快照等描述。内容审查中的文件表与结构化表共用 review-workbench、data-table-information-card、data-table-toolbar、data-table-section-content 和 DataTable 样式，统一卡片内边距、标题间距、表头、边框和行高。

新分片接口位于/api/v1/data-push/uploads：POST初始化，PUT写入指定片，POST /{id}/complete同时请求合并和提交业务意图，GET /{id}查询最终投递结果；GET /{id}/parts只在断点续传时使用。202表示受理，READY表示文件可用，均不能代替deliveryStatus=SUCCEEDED。旧file-uploads及表/附件字段single接口继续兼容。文件集合策略仍由节点自身配置，平台登记不自动下发FILE策略或扩大密钥权限。

当前公安演示推送源保留四张表，其中 `police_person_info.portrait_file_id` 为可选的人员照片文件编号（varchar(64)，10MB，jpg/jpeg/png），`police_case_record.case_document_file_id` 为可选的案件文档文件编号（varchar(64)，20MB，pdf/docx）。对应集合编号为“表名.字段名”，已在本地节点配置这两个集合及该数据源调用方；其他字段定义与表数量保持不变。附件原文先上传到READY，表记录仅携带文件编号。

针对性验证见 `tools/tests/push-contract-review.test.mjs`、`tools/tests/PushContractColumnScopeTest.java` 及 `DataPushSchemaRegistrationStatusTest`：20/100表均为1次规范读取，不自动创建密钥；无已发布表时字段快照按最多50表一批读取（1/2请求）。主动获取密钥后固定追加1次规范刷新。20/100张已登记表的签发前快照均为8次业务SQL读取，不混入外租户、未登记表或外租户字段。字段接口20/100表单批均为3次业务SQL读取（权限计算固定开销另计），逐ID验证租户及角色数据源范围，混入外租户或无权来源时整批拒绝。文件说明不向节点逐项探测。 20/100张表在数据与附件模式之间反复切换时均不增加读取请求；附件列表仅从同一已授权快照筛选，预览字段异步到达后重建列表并保留有效示例选择。

附件模板验证使用 `tools/tests/push-attachment-template.test.mjs`（真实工作簿生成及校验）、`tools/tests/MetadataImportAttachmentMagicTest.java`（实际Magic脚本H2执行）。导入主流程20/100张表均为4次读取（角色计算和登记状态刷新固定开销另计），写前批量预取旧字段；越权或外租户来源、非法附件配置在写前拒绝。一次最多100表、10000字段。

## 数据表详情与 Hive 预览

动态表单详情统一使用表单布局骨架屏：系统、数据库、数据表、资源目录、文件目录共用 `base-detail`，在表单配置与详情数据并行读取、表单值完成回填后显示内容；服务详情的记录读取与登记表单配置初始化、申请单只读查看也使用同一视觉。加载失败显示错误与重新加载入口；切换记录或离开页面后忽略旧请求结果，不将旧数据写回详情状态。骨架屏复用 `LoadingState` 的 `form` 类型，保留标签和值的分栏、长文本占位，窄容器自动单列，遵循减少动态效果设置。加载反馈不改写租户表单配置，不增加逐字段请求；20/100 个字段均为一次配置读取与一次详情读取，命中现有配置缓存时不重复请求配置。

数据源详情的“数据表信息”只读取已保存表快照，不在进入页签、分页或筛选时探查来源库。与登记第二步共用 `/dst/database/metadata/tables`，详情以 `paged=true、allSnapshots=true、includeGovernance=false` 分页展示全部标注状态；登记第二步默认仅已标注列表的契约保持不变。列表提供“是否标注”、业务类型筛选和删除快照；点击表名查看样例，点击字段数查看字段结构，预览复用登记第二步的字段和样例接口，按用户选中的单表读取。删除需确认，仅清理平台快照及关联配置，不删除来源物理表或记录。

“重新探查”显式启动登记第二步同一后台采集任务，保留已标注快照并纳入新增表；展示真实进度，失败可重试，离页停止轮询。“登记数据资源”使用当前来源打开五步登记的第二步“探查数据表”，继续按同一份快照显示待标注与已标注表，退出登记后刷新详情状态。`datasource-table-snapshot.test.mjs` 覆盖20/100行均为3次初始读取（来源、现有任务状态、快照页），后续翻页仅1次请求，无逐行字段查询；`TableSnapshotListMagicTest` 执行实际脚本，20/100项均为4次业务SQL读取（来源、分页计数与记录、业务分类汇总，角色计算固定开销另计），验证同名快照优先已标注、默认已标注兼容、业务分类及跨租户/角色拒绝。

“数据表字段”页签复用登记第三、四步的 `register-dbTable-catalog` 编辑器，按当前表 ID 读取登记快照。字段中文名、主键、时间属性、字典翻译及统一格式与登记流程读写同一份配置；详情模式使用独立状态，不改动进行中的登记会话，也不自动查询来源库预览。登记表格显示“是否为空”，按已采集的可空性展示“是 / 否 / 未知”；详情业务字段表仅对非空字段显示勾选，其余留白，不据此修改物理数据库结构。

详情页使用独立的简洁表格布局：顶部仅保留“同步字段、导出、保存、同步变更”操作，不显示登记工作台标题、统计说明或多层卡片。表格填满详情区域的剩余高度，底部保留16px间距；长表在表格内部滚动，窄屏下宽表在自身容器内横向滚动。业务字段的名称、注释、类型、长度分列展示，其中“长度”列固定72px；详情字段表与登记数据预览共用14px横纵滚动条、加深的悬停滑块及最小拖动尺寸。主键沿用登记时字段名称旁的钥匙图标；“非空”排在最后，仅非空字段显示勾选，空值、未知及缺失长度均留白。字典翻译、统一格式及时间属性仍复用登记流程的配置逻辑。

详情页提供“保存”和“导出”。导出为带中文表头的 UTF-8 CSV，可用 Excel 打开，包含当前表全部字段及当前编辑值、可空性、主键、字典翻译、格式和时间属性，不受选中行或滚动位置影响，并处理电子表格公式注入。保存复用 `/dst/database/table/governance/save` 的 `editMode=fields`，按当前租户和角色校验数据源，再一次预取字段并逐 ID 校验表归属；只更新字段治理属性，保留原登记、审批状态、登记完成标记、物理类型、可空性及模板维护的附件限制。所有归属校验在事务写入前完成，`dryRun` 同样校验但不写入。

“保存”写入平台租户库的字段快照和治理配置，不会对来源数据库执行DDL，也不会直接转换来源记录。“同步字段”从数据库重新采集快照；“同步变更”方向相反，将已保存快照的字段新增、删除、类型/长度、非空、注释和主键定义同步到来源数据库。未保存的编辑需用户先确认“保存并比较”。结构比较复用同一路由的 `schemaAction=compare`，执行使用 `schemaAction=apply`；客户端仅发送表ID、比较指纹、完整表名及确认标志，不接受客户端连接配置、字段定义或SQL。`dryRun=true`仅比较，绝不执行DDL。

比较先校验当前认证租户及数据源角色范围，再读取本表至多2000个已保存字段；四次业务读取（表、来源、字段计数、字段页）及一次连接配置读取均固定，与20/100个字段无关。物理适配器一次`SHOW CREATE TABLE`获取原生结构，在内存逐字段比较。差异每页20项展示当前值、目标值和影响，服务端生成的DDL直接显示，不再折叠。点击“确认覆盖表结构”即提交当前比较计划，不再要求额外勾选或手工输入表名；客户端沿用接口确认标志与服务端返回的表名，仍保留指纹、权限、范围和重复提交校验。执行重新读取权限、快照及物理定义，指纹变化即拒绝，要求重新比较；结构备份成功后才执行一个`ALTER TABLE`，并重新读取结构核验结果。结构备份默认放根`logs/backend/schema-sync/`，不含连接凭据或业务记录，不构成字段数据备份。

当前物理同步支持MySQL/MariaDB普通表；执行要求MySQL8.0+或MariaDB10.6+的InnoDB表，其他来源明确提示使用原生工具维护。已有默认值、自增、字符集、排序规则、生成表达式及非主键索引等属性沿用完整原生列定义；不从不完整字段快照重建外键或普通索引，生成列的类型/可空性调整及不完整新增生成列需人工处理。变更可能因现有空值、重复值、外键或索引约束被数据库拒绝；删除列会丢失其数据，数据备份由操作者确认。采用单条DDL及严格模式，避免多条DDL部分完成或类型截断；数据库行为见[MySQL ALTER TABLE](https://dev.mysql.com/doc/refman/8.4/en/alter-table.html)和[MariaDB ALTER TABLE](https://mariadb.com/docs/server/reference/sql-statements/data-definition/alter/alter-table)。`TableSchemaSyncTest`覆盖结构属性保留、并发指纹、类型注入和固定读取；`TableSchemaSyncDatabaseTest`可在受限配置指定的验证来源创建临时表，验证真实比较、过期拒绝、确认DDL及数据/索引/默认值保留，结束后清理该临时表。

详情读取使用当前表、所属数据源、字段快照和字典表分页四类请求，不按字段逐行补查。字典候选限定当前数据源、每页最多 100 张；已有字典字段快照按最多 50 张一批读取，与业务字段行数无关，超过 100 张时明确提示维护入口。`tools/tests/test_table_detail_fields.mjs` 覆盖 20/100 个字段均为 4 次基础请求，以及完整导出、可空值与公式保护；`TableDetailFieldSaveMagicTest` 执行实际 Magic 脚本，20/100 个字段保存均为 3 次 SQL 读取（角色计算固定开销另计），覆盖跨租户、角色不可见、外表字段 ID 拒绝及登记/审批/附件信息保留。字段更新属于写入，写入量随实际修改字段数增长。

Elasticsearch数据源使用已登记的HTTP/HTTPS Endpoint和认证配置；`es`、`elastic`统一识别为`elasticsearch`。索引范围保存在连接配置的`database`（可空或通配表达式），不得用数据源中文显示名代替。一个普通索引对应一张登记表，mapping的对象路径展开为字段；隐藏/系统索引不进入采集。第二步沿用现有后台采集、分页快照和按需字段采集流程，完整索引清单不按500条截断，超过10000个时须缩小范围。

ES技术适配器负责HTTP、mapping和DSL转换，不执行SQL或平台业务表读写。索引分页只批量读取当前页mapping；20/100个普通短名称索引均为一次索引清单请求和一次批量mapping请求。单批至多100个且路径长度有界，长名称按路径预算分批；字段批量入口最多500个索引，任一索引超出登记范围时在远端请求前拒绝。租户和角色范围仍由原Magic入口及登记主表校验，ES连接凭据只保存到服务端连接配置，不进入检索投影。

普通数据预览复用原接口，以原生`_search`进行过滤、排序和from/size分页，20/100条均为一次mapping和一次search，不逐文档补查；`track_total_hits=true`返回精确总数，超过默认10000条窗口时需缩小筛选范围。text字段的精确筛选与排序使用已有keyword子字段，缺少时返回明确提示；索引、mapping或分片查询失败不伪报成功。ES不使用JDBC/SQL，不提供本接口的字典类别分组。现有索引只读验证不创建测试索引或业务文档。

共享详情组件 `table-preview` 通过一次 `POST /dst/database/metadata/table/preview-data` 请求取得当前页、字段及中文表头。详情页传 `countMode=none`：服务端托管 MRS Hive 仅执行一次 DESCRIBE 和一次带上限的分页查询，多读取一条判断下一页，向页面返回不超过pageSize条记录及 `total=null、totalKnown=false、hasMore`。页面显示当前页、本页记录数、每页20/50/100条与上一页/下一页，不展示推测的总条数或总页数；失败保留真实错误和重试入口，同表及跨表迟到响应不能覆盖新请求。

该可选模式只改变托管Hive详情预览；其他数据库仍使用原有精确总数分页。接口省略countMode或传exact时保留原精确统计行为，字典分组和其他登记调用不受影响；无效计数模式直接拒绝。`hiveConnectionMode` 为可选连接属性，缺失或为空时仍根据 `metadataAccessMode=server-managed-mrs` 或已登记的 `hiveProfile` 判断托管连接；显式 `open-source` 始终使用该数据源自己的 JDBC 连接，不能因可选属性缺失而发生空值异常。Hive库表仍由当前租户登记和角色数据范围确定，字段、过滤和排序继续使用实际字段白名单。空页不会冒充总数为零，连接/认证/字段/数据查询失败不降级为成功。

首尾页、空表、条件查询与排序均有回归；分页SQL保持兼容旧Hive的ROW_NUMBER方式，不使用需要Hive 2.0+的LIMIT offset, rows，详见[Hive SELECT说明](https://hive.apache.org/docs/latest/language/languagemanual-select/)。结果传输及应用内存有界，不等于Hive引擎无需扫描或排序；大表深分页耗时仍由集群与物理数据布局决定。

验证入口为 `TableDetailPreviewTest` 与 `tools/tests/test_table_detail_preview.mjs`。20/100行详情模式均为1次页面请求、测试中5次固定元数据SQL和2次Hive查询（连接配置及角色计算固定开销另计），返回最多20/100行（Hive最多额外取1行）；精确统计模式仍为3次Hive查询。无权来源、外租户表和越界库名在Hive执行前拒绝。本机开发环境没有MRS客户端配置，真实Hive仅部署于生产；开发回归采用合成结果和查询边界验证，生产连接、授权和大表耗时需在生产发布时验收。
