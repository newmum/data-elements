海通数据集成中心 ARM / 无 Nacos / MySQL 增量升级

适用原 haitong-deployment-linux-aarch64-no-nacos.zip 已安装实例。
将本增量包解压到安装目录之外，进入增量包目录，使用原海通运行账号执行：
  bash upgrade.sh check /原海通安装目录
  bash upgrade.sh apply /原海通安装目录
例如原目录 /home/linewell/haitong-deployment-linux-aarch64-no-nacos。
要求 Linux aarch64、原实例使用的 Python3.10+，并先用原方式启动 MySQL、缓存、NiFi。
默认读取原 data/local/mysql-root.cnf；现场使用其他受限客户端配置时，加 --mysql-defaults /受限配置文件。

check 只做校验，不写数据库、不换包、不启停服务。
apply 校验原 JAR、包内摘要、数据库和所选 Magic 的内容版本；冲突时停止。
随后短时停止本实例网页与后端，备份所选 Magic 和旧前后端，执行差异 SQL，安装新扩展并重新启动应用。
不会重新执行旧 db/01-control.sql 或 db/02-tenant.sql，不重建库，也不生成新账号、密码或密钥。
config、data/local、生产库连接、生产目标、NiFi 流程及队列保留，MySQL、缓存及 NiFi 不重启。
新 NAR 并存放入原 extensions 自动加载目录，旧版保留供原流程引用；已有流程不会自动重新部署。
安装按父扩展在前、子扩展在后的顺序进行，并核对原 NiFi 自带父 NAR 的版本坐标。
新增 TIMESTAMP9 公共编解码服务；已有同名服务若格式不同则停止，不覆盖它。
JDBC 驱动放在新子目录，只对本包原内置 NiFi 节点补充缺少的路径键，已有路径及外部节点配置保留。
开源 Hive 来源与 Oracle 厂商类型需要兼容适配 JAR；已有对应键缺少该 JAR 时只追加兼容文件，保留原生客户端路径。
这些文件路径属于 NiFi 执行主机。外部 NiFi 节点的驱动、扩展与公共服务须在该节点另外部署。

数据库升级顺序：
  db/01-tenant-structure.mysql.sql（新表、节点健康列、字段注释扩容及落湖索引升级）
  db/02-magic-resources.mysql.sql（仅本包所选资源；须由升级入口先做冲突校验及备份）
  db/03-portable-templates.mysql.sql（可移植模板草稿，不覆盖已有模板）
结构 SQL 可重复执行，原件与逐项计划在 db/structure-plan.json。
本批控制库没有结构差异，因此不生成空的控制库结构增量脚本。
不要跳过预检单独覆盖 Magic SQL；生产在线修改与原包不同的资源必须先人工合并。
原包中的空资源行ID按原路径与摘要识别并保留，更新使用批量关联写入，不依赖原表不存在的唯一键。
正式写入前在事务中锁定并校验资源摘要，重复升级不会再插入同一份接口。

模板功能：
本包带本机当前已发布模板的可移植定义，包括目标类型、治理节点、写入策略与拓扑。
开发环境的目标数据库 ID、连接目录、HDFS 目录、原生快照与凭据不导入生产。
因此导入为 DRAFT 草稿，不自动更换生产默认模板。
升级后进入“模板管理”，为需要使用的草稿选择生产目标库，补充必要现场目录，发布后按需设为默认。
原有生产模板、默认模板与任务绑定均保留，不覆盖或复制开发业务资产。

回退：
  bash upgrade.sh rollback /原海通安装目录
备份在原 data/local/upgrades/<发布标识>/，权限按受限文件保存，不能放到网页目录或对外发送。
回退恢复旧前后端和所选 Magic；新增字段、表、模板与驱动/NAR保留以保护升级后的记录和流程引用。
数据库 DDL 在 MySQL 中并非整批事务；若升级中断，先检查受限备份的错误信息，再回退应用。
不要清空 runtime、data、数据库或 NiFi 仓库来重试。未完成备份存在时再次 apply 会停止。
回退后若要重新执行同版升级，先另行归档该受限备份目录；脚本不会覆盖已有恢复材料。
升级完成后再次 apply 仅核验，不重复导入。正常启停仍使用原 start.sh、stop.sh、status.sh。
仅需重启应用时请安排维护窗口；原 stop.sh 会连同原实例 NiFi、缓存和数据库一起停止。

本包为差异升级，不重复携带 JDK、NiFi 发行版、MySQL、缓存、Caddy 等运行组件。
完整后端 JAR 与前端构建从本次本机源编译；NAR 的 SDK 为 NiFi2.9，字段治理版本与后端一致。
