# 3.2.0 · 模块视觉与数据源体验改造说明

## 本轮边界

仅修改前端。保留 3.1 本地工作区、业务流程、全屏 ER、浅深主题与品牌立方体。本次不增加后端、真实数据采集或生产权限；不是用截图替换原页面。

## 导航偏左的修复

原菜单仍由组件库的 inline-collapsed 结构控制，隐藏的标题节点与内边距可能参与布局，仅补 justify-content 无法稳定消除影响。本次将业务导航替换为 ProductNavigation：收起后按钮只包含一个 SVG 图标，没有隐藏文字占位，没有组件库缩进；按钮自身在侧栏内居中。

展开保留左侧选中竖线，收起不创建竖线伪元素。原路由、safeNavigate、全屏来源页面与离开保护不变。所有19个功能分别配置独立图形，键盘操作与 Tooltip 没有删掉。

## 数据源工作台

操作顺序为：页头定位与登记 → 工作区统计 → 采集情况筛选 → 丰富来源表格 → 分布/覆盖/后续建模入口。

表格：名称与命名空间、数据库类型、地址/代码/环境、业务域与责任方、对象/字段数量、最近采集、配置状态、采集与更多操作。数量按实际本地实体计算；未采集的新来源为0，不把结构模板数量冒充已采集数量。

业务属性写入本地工作区并纳入备份。仅修改说明和责任方不会让原配置检查失效；改变连接登记信息则回到草稿并清除原检查时间。停用来源在编辑后仍保持停用，不自动启用。批量检查展示逐项失败，停用来源跳过，不以一个成功消息掩盖部分失败。

详情提供概览、对象、采集历史三个页签；已采集数量跳转按来源过滤的元数据目录。新建/编辑用分组抽屉，保留未保存提醒与错误状态。采集选择沿用实际 Mock 服务，未选择的对象不会被误删除。

## 字号和响应式

页标题24px，小屏22px；区块标题16px；菜单、主正文和表单14px；紧凑表格13—14px，辅助说明12px；极小的类别标识/计数徽标11px。普通控件32px，小按钮28px，图标菜单点击目标44×42px。没有 CSS zoom 或缩放整页。

1920/1670/1440/1366 桌面保持完整页头和多列布局；768宽度减少辅助装饰；390宽度优先文字和动作，侧栏隐藏为覆盖入口，表格在自身容器内滚动，表单换行。源码 DOM 检查不覆盖所有真实组件内部结构，仍需联网构建后回归。

## 业务页头文案

下列文案由 `src/design/moduleVisuals.ts` 统一维护。18个常规页面实际使用；ER保留全屏，文案用于功能定位配置，不额外占据画布。

### 治理总览

汇聚多源结构、统一业务标准，让数据资产的关联、质量与治理进度清晰可见。

**治理有序 · 数据有为** · 多源资产全景 / 治理进度可视 / 问题任务直达

### 数据源管理

统一登记关系型与非关系型数据源，让分散的库、表与集合成为可管理、可建模的数据资产。

**连接数据 · 洞察价值** · 多源统一管理 / 按需采集结构 / 跨库关联建模

### 元数据采集

按来源和范围整理表、字段与约束，以可追溯的采集任务和结构快照沉淀元数据。

**结构有源 · 采集有序** · 范围精确选择 / 执行过程可追踪 / 结构版本留存

### 元数据目录

从数据源找到表，从字段理解业务；在统一目录中检索、查看结构，并直达全屏关系建模。

**资产可找 · 结构可读** · 表字段统一检索 / 来源路径清晰 / 一键加入模型

### 数据模型

围绕业务主题组织不同来源的数据表，用可视化模型呈现结构与关系，持续完善业务全貌。

**以模型 · 连接业务** · 跨来源选表 / 业务主题组织 / 全屏可视化设计

### ER 关系图

在一张画布中连接不同库的字段，保留关系来源、复合映射与推荐依据，让关联看得见、说得清。

**关联可视 · 依据可查** · 字段级拖拽连线 / 复合关系维护 / 推荐依据可解释

### 元数据对标

将业务字段与数据标准、质量规则逐一对应，沉淀可解释、可维护的治理关系。

**字段有据 · 标准有依** · 字段精准匹配 / 标准版本绑定 / 治理关系留痕

### 数据血缘

串联来源字段、加工过程与目标数据，沿链路理解数据去向，为问题追溯与变更评估提供依据。

**循源而行 · 见微知著** · 加工链路可视 / 来源去向可追溯 / 独立全屏画布

### 数据元

统一业务术语、字段定义和取值要求，让跨系统的数据有共同语言、有明确依据。

**统一语言 · 沉淀规范** · 业务定义统一 / 修订状态清晰 / 发布引用可追溯

### 数据元审核

围绕提交版本核对定义与约束，明确审核意见和发布结论，让每一次标准变更都有据可查。

**审有所据 · 发有所依** · 审核版本冻结 / 申请审核分离 / 意见结论可追溯

### 标准落地

将已发布标准落实到具体字段，持续识别已覆盖与待对标范围，让标准从定义走向应用。

**从规范 · 到每个字段** · 字段覆盖可视 / 落地范围清晰 / 对标入口直达

### 标准代码

集中管理业务分类、状态和枚举值，以版本化代码集减少不同系统之间的口径差异。

**同一代码 · 同一含义** · 枚举口径统一 / 层级条目维护 / 发布版本留存

### 编码标准

用清晰的分段规则规范业务编码，校验字符与长度，让标识可理解、可检验、可复用。

**编码有章 · 规则可验** · 编码分段定义 / 字符长度约束 / 格式即时校验

### 数据质量探查

从空值、不同值与字段分布了解数据现状，带着明确的观测范围发现值得优先治理的问题。

**洞察现状 · 发现问题** · 字段统计观测 / 范围预算可控 / 问题线索沉淀

### 探查报告

集中阅读字段统计与观测结果，明确样本范围、分析时间和异常线索，为规则设计提供依据。

**让数据现状 · 有据可查** · 观测指标可读 / 方法范围明确 / 历史结果保留

### 数据质量规则

将质量要求转化为可执行规则，覆盖完整性、唯一性、值域与引用关系，明确什么是合格数据。

**定义好数据 · 守住质量** · 质量模板复用 / 作用字段明确 / 执行修订可追溯

### 质检方案与任务

围绕业务范围编排具体规则，统一管理执行任务与检查预算，让质量要求落到每一次检查。

**规则成章 · 检查有序** · 规则组合编排 / 执行状态可视 / 结果问题联动

### 质量报告

集中呈现已执行规则、覆盖范围与违例结果，区分数据问题和执行异常，支撑治理优先级判断。

**质量可见 · 行动有据** · 检查结果透明 / 问题范围可追溯 / 工单整改联动

### 质检工单

从问题分派到整改复检，用清晰的责任、过程和验证结果推动质量问题形成处理闭环。

**问题有主 · 整改有果** · 责任分派明确 / 整改过程留痕 / 复检通过关单

## 资产与代码定位

`src/app/ProductNavigation.tsx`：收起/展开、键盘导航。  
`src/design/iconPaths.ts`、`ModuleIcon.tsx`：19套本地路径。  
`moduleVisuals.ts`、`heroAssets.ts`：业务文案、显式本地图片映射。  
`src/assets/heroes/`：浅深色独立模块插画；总览继续使用原 landscape 资产。  
`src/assets/databases/`、`Visuals.tsx`：8种数据库识别图形及统一使用入口。  
`SourcesPage.tsx`：列表、筛选、详情、登记、批量操作。  
`src/mocks/sourceAnnotations.ts`、`shared/sourcePresentation.ts`：种子属性补全及结构统计。  
`src/styles/studio-polish.css`：本轮最后导入的精确样式层。

数据库图形采用本地识别性绘制，不声称官方授权标志或数据库认证。代码和SVG无需远程加载；不包含字体文件。
