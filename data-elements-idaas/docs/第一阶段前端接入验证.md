# 第一阶段前端接入与验证

日期：2026-09-27。目标工程：`data-elements-idaas`。本次实际连接已发布的共享后端和 `baseline` / `baseline_ga_old`，同时保留隔离的前端契约验证。数据库发布清单与 Java 改动见 [第一阶段后端实施说明](./backend-phase1-implementation.md)。

## 运行期数据来源

React 通过 `src/services/http.ts`、`src/services/workspace.ts` 访问共享后端。`src/mock/store.ts` 仅保留旧导入路径，实际已绑定真实服务。旧 `src/mock/database.ts` 与种子保留给隔离单元测试。运行期不会把浏览器旧数据上传，也不会在接口失败时回退种子。

本地 `/api` 代理目标默认为 `http://localhost:8088`，请求头使用后端已有的 `token` 名称。认证凭据保存在当前标签页，重新加载时先访问 `/idaas/session/me`，再获取 `/idaas/workspace/bootstrap`；两者成功后才显示工作区。

## 接口契约

| 请求 | 用途 |
| --- | --- |
| GET `/sym/tenant/login-options` | 获取登录租户，登录时显式提交所选租户 |
| POST `/idaas/auth/login` | 提交用户名、密码、政企身份域与租户，建立服务端会话 |
| GET `/idaas/session/me` | 验证并恢复当前会话 |
| GET `/idaas/workspace/bootstrap` | 获取权限过滤后的工作区数据 |
| POST `/idaas/{users,orgs,applications,roles,resources}/save` | 提交记录、动作、明确的 `creating` 标志与请求号 |
| POST `/idaas/{users,orgs,applications,roles,resources}/remove` | 提交 ID、版本与请求号 |
| POST `/idaas/auth/logout` | 退出服务端会话 |
| GET `/idaas/users/operations` | 当前操作者在当前租户的未完成人员操作 |
| POST `/idaas/users/retry` | 仅凭原请求号恢复服务器保存的安全操作资料 |

修改成功后重新加载服务端数据。相同内容的写请求失败后重试沿用内存中的请求号，成功后才清除。请求号索引使用请求内容摘要，不把密码或请求体持久化到浏览器。

## 页面行为

- 登录增加明确租户选择，保留 44px 输入控件和至少 48px 主按钮。
- 新建用户明确选择“创建新账号”或“关联已有账号”；后者不提交初始密码，不修改共享姓名。普通新建要求初始密码，任职 DTO 包含主职和兼任机构。
- 编辑已有人员只展示可维护的租户档案字段，共享账号与姓名为只读。
- 权限按钮读取服务端 `editableTables`；应用读取 `allowedAppIds`，机构读取 `orgIds` 与显式 `scopeMode`。空机构范围不会自动放大为全租户。
- 应用新建完成基本登记；认证接入与安全页签保留业务状态“尚未开通”。
- 后续授权、同步、公众认证、密码找回等入口保留未开通状态，不生成假的成功记录。
- 总览状态表达已读取的工作区数据，不将浏览器数据读取宣称为全系统健康监控。
- 未开通的应用授权数量显示“—”，详情页和人员档案明确显示授权服务尚未开通；二次认证不再显示为已支持但未配置。
- 当前真实组织较多，组织树使用局部纵向滚动，避免把右侧用户列表推到页面底部；390px 页面保持可操作的移动布局。
- 登录密码错误保留具体错误提示；已登录请求返回认证失效时才清除当前卓鉴会话，不清除其他系统的浏览器存储。
- 修正共用编辑抽屉初次挂载时默认值未呈现的问题，确保主职、状态等已提供的初始值正确显示。
- 人员页仅在当前账号可编辑用户时读取恢复清单；没有待恢复操作时不增加页面卡片。读取失败保留已有清单与人员表，重试只提交原请求号，成功后重新加载工作区。开户或移除失败后主动更新恢复清单，不要求重新输入密码或开户资料。
