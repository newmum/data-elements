# 卓鉴统一身份管理平台：第二阶段接口下发实施说明

> 历史记录：2026-09-28 用户已要求撤回租户端改造并优先开发卓鉴。本文所述公安本地账号、接收接口和新增租户结构已回退，下发已暂停；控制库中央目录保留。当前状态与回退验证见 [租户改造回退与平台优先开发说明](租户改造回退与平台优先开发说明.md)，不要按本文重新安装租户资源。

日期：2026-09-28。工程：`data-elements-idaas`；共享后端：`data-elements`。控制库 `baseline`，本轮安装和实测的公安业务库 `baseline_ga_old`，租户 ID `2084109831682699264`。

## 本轮实际实现

本轮将先前的共享账号方案调整为两个登录域，并实现 HTTP 下发闭环。卓鉴操作账号留在控制库 `rm_user_t`；中央人员目录是控制库业务档案；公安业务账号存在公安库 `rm_user_t`。平台登录不再选择行业租户，也不以公安角色授予平台权限。平台 token、租户 token 和接收服务签名分别验证。

业务校验、中央目录维护、接入配置、任务创建、执行、重试、租户接收、基础用户保存及本地密码设置都在 Magic API。中央执行器只调用已配置的 HTTP 接收地址，不直接写目标业务表。接收端用自己的数据库事务写基础用户、机构和任职，并保存回执。

当前卓鉴页面可以维护中央人员/机构，在“同步管理 → 同步配置”填写目标租户、完整接收地址、密钥标识、接入密钥、超时和启停；可以测试接收接口，选择对象，查看逐条任务结果并继续执行或重试。接入密钥加密保存，编辑时不回显；留空保留原值。

已建立本地“公安元数据管理平台”配置，地址为 `http://localhost:8088/sym/identity/provision/apply`。该 HTTP 地址仅用于显式允许 localhost 的开发环境；正式接收地址使用 HTTPS。

## 数据库变化（已经应用）

控制库新增 6 张表：

| 表 | 用途 |
| --- | --- |
| `iam_subject_t` | 中央人员目录，保存拟用业务账号及资料，没有登录密码 |
| `iam_directory_org_t` | 中央机构目录与上级关系 |
| `iam_operator_permission_t` | 平台功能权限及可下发目标范围；无管理员布尔字段 |
| `iam_receiver_config_t` | 接收系统地址、密钥标识、加密密钥、超时及配置版本 |
| `iam_provision_task_t` | 持久下发任务、目标、请求幂等标识、配置版本、执行租约 |
| `iam_provision_item_t` | 每个对象的固定事件、数据快照、结果及尝试次数 |

公安库新增 **2 张表**：`rm_user_t`（基础本地账号）和 `sys_identity_event_t`（接收事件和持久回执）。不会为每类基础身份属性继续新增 IAM 扩展表。

公安新用户表的来源字段为 `identity_origin`、`central_subject_id`、`source_issuer`、`source_version`、`source_enabled`；另有本地密码、启停、删除、版本、失败次数与临时锁定字段。`source_enabled` 与本地 `status` 分开：两者都允许，账号才可登录。登录名按租户唯一，中央人员映射按租户/来源/中央 ID 唯一。

原 `rm_org_t` 增加 `identity_origin`、`central_org_id`、`source_issuer`、`source_version`、`source_enabled` 以及中央映射唯一索引。原 `rm_user_org_rela_t` 增加 `identity_origin`、`source_issuer`、`post_name`。

已有第一阶段 8 张公安 IAM 表保留，尚未做历史归档或删除。新下发链路使用基本 `rm_*`、既有 `sym_config_t` 和新回执表。DDL 的完整字段、类型、索引以共享后端两份 `V20260928_*__idaas_provision.*.mysql.sql` 为准。新增表明确使用 `utf8mb4_general_ci`，不转换原业务表字符集。

导入中央目录的是原公安 113 个有效机构、5 个人员的资料，不是新增 5 个平台操作账号。为保留旧业务引用，本地账号保留既有人员 ID；这只是迁移映射，不共享密码或会话。已建立明确的原数据映射，首次下发不会再复制相同机构。来源版本初始为 0，中央资料首次下发后才成为中央来源。编码缺失/重复的中央导入记录补为 `GA-原ID`；没有改写原机构编码。

上述 113 为业务机构数量；公安原 `ROOT/全部机构` 辅助根节点仍保留，因此原本地有效机构物理行数还包含该根节点。

原平台密码没有复制到公安。公安本地 `manager` 已生成独立维护密码，保存在本机用户目录的私有交付文件，正文不展示密码。其余导入本地账号尚未设置本地密码，需授权人员通过本地密码接口设置。平台 `manager` 继续使用原平台密码。

## Magic API 入口

中央接口放在 **13.统一身份管理**：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/idaas/auth/login`、`/idaas/auth/logout` | 独立平台登录/退出 |
| GET | `/idaas/session/me`、`/idaas/workspace/bootstrap` | 平台会话/中央目录工作区 |
| GET / POST | `/idaas/users/list`、`save`、`remove` | 人员目录读取、保存、归档 |
| GET / POST | `/idaas/orgs/list`、`save`、`remove` | 机构目录读取、保存、归档 |
| GET | `/idaas/provision/options`、`configs`、`tasks` | 目标、接入配置、任务明细 |
| POST | `/idaas/provision/save-config` | 创建/修改接入配置，密钥只写 |
| POST | `/idaas/provision/test` | 发送签名 PING 并校验协议和目标 |
| POST | `/idaas/provision/create` | 固化对象版本和快照；重复请求返回原任务 |
| POST | `/idaas/provision/execute` | 执行/继续/重试，已成功项保留 |

租户接口放在 **09.系统管理 → 10.身份下发**：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/sym/identity/provision/apply` | 标准用户、机构接收；只接受服务签名 |
| POST | `/sym/identity/provision/credentials` | 租户本地授权人员登记/轮换/停用接收密钥 |
| POST | `/sym/identity/local/login` | 本地独立账号登录（明文密码请求，正式环境必须 HTTPS） |
| GET | `/sym/identity/local/users` | 基础用户列表 |
| POST | `/sym/identity/local/save`、`password`、`delete` | 基础用户保存、独立密码设置、删除 |

原 `/portal/login` 已改用本地账号校验，保持原前端 SM3 请求格式，**没有控制库密码回退**。原 `/sym/user/me`、用户列表/分页/兼容查询/保存/删除、用户角色查询/保存已适配本地表。租户本地会话不能通过租户切换接口切到另一个租户；需要在目标租户另行登录。

本轮只在公安库安装。其他租户应先安装基础结构并建立自己的维护账号和接收授权；未安装时返回未开通，不能为了兼容而恢复控制库账号登录。这一点会影响旧共享账号登录方式，切换前应先完成目标租户迁移。广电达梦库需要单独适配 DDL。本轮没有写入广电、海渔业务数据，也没有声称已完成其验收。

## 下发执行行为

任务创建先固化目录版本、事件 ID 和资料快照。选中人员时自动补齐其任职机构及上级机构。机构按上级在前排序，人员随后执行。单批任务最多 500 项；选中对象最多 200 项，较大目录需要分批。

每次执行最多处理 5 项。页面持续请求后续批次并显示进度；某批出现失败就停止自动继续，保留成功回执。页面关闭或网络中断不会撤销已保存任务；可在“同步任务”继续执行。这里是持久任务和手动恢复，**尚未实现后台定时调度、实时事件推送或自动重试队列**。

同一接收事件 ID 与相同内容返回原结果；改用同一事件 ID 发送不同内容返回冲突；旧版本不会覆盖新版本。数据库写入与回执在同一租户事务内完成。网络失败后的原事件重试不会重复开户。任务使用执行租约并逐项续租，已成功项不会被另一轮失败结果覆盖。

配置固定目标与密钥标识。修改地址、密钥或超时会增加配置版本；原任务发现配置变化时拒绝继续，需按新配置创建任务。这样不会把原任务悄悄发送到另一个接收端。新任务携带相同人员版本时，接收端按版本忽略重复资料。

用户的中央资料更新保留本地密码、本地启停和本地角色。只替换中央来源的任职，本地来源关系保留。中央停用/归档使用来源开关停用本地账号，并撤销本地会话；本地启用无法覆盖中央停用。机构使用中央编码作为 `dept_code`，本地层级编码按既有 4 位段规则生成；移动/改名按真实上级关系重算后代路径。

同名本地账号或相同机构编码不会按姓名/手机号自动合并，返回冲突。显式绑定、解除中央管理、冲突处理页面属于后续工作。

## Java 框架变化

- `PlatformSessionMagicModule`：独立 `idaas-platform` 会话命名空间，不写账号业务逻辑。
- `IdentityTransportMagicModule`：HMAC-SHA256、AES-GCM 密钥存储、HTTPS/localhost 校验、HTTP 超时/不跟随重定向/响应大小限制。
- `IdentityRuntimeMagicModule.inTenant`：为已经完成登录或签名验证的 Magic 闭包选择显式绑定的数据源，禁止事务内切库。
- `GlobalInterceptor`、`CustomJsonValueProvider`：按平台路径选择对应登录域，包括正式环境开启 token 校验时的 Magic 响应检查。
- `TenantWebInterceptor`、`TenantLocalSessionGuard`：平台走控制库；本地账号按自己的租户和启停/来源状态验证，旧共享会话不能进入已迁移租户。
- `TenantController`：本地会话只返回本租户并禁止跨租户切换。
- `WhiteListProp`：只公开精确登录/签名接收路径，接收业务仍由 Magic 严格认证。
- `start-data-elements.ps1`：从仓库外加载开发密钥；只有 `dev` 显式开启 localhost HTTP。

服务端密钥使用外部环境变量 `IDAAS_TRANSPORT_KEY`（32 字节 Base64）。本地生成文件位于用户私有目录，重启需保留。生产需单独配置并做好备份；多个后端节点需使用同一部署密钥。没有密钥时配置保存失败，不降级为明文存储。

## 仍未完成的工作

本轮完成“独立账号基础 + 中央 HTTP 用户机构下发”的公安闭环，尚不是全部 IAM 功能完成。后续按以下顺序推进：

1. 租户基础管理收尾：本地密码设置和接收凭据配置的完整租户页面、显式人员/机构绑定及脱管、中央来源机构编辑边界、审批候选人等仍引用控制库用户的消费者改造。当前下发账号的登录、基础用户和角色接口已验证，不能据此声称全部审批/应用流程已迁移。
2. 多租户上线：海渔 MySQL 与广电达梦各自迁移、独立维护账号/接收密钥、目标范围授权与各自数据验收；跨部署系统按 IDAAS/1 实现接收接口并配置正式 HTTPS 地址。
3. 可靠性及历史收尾：后台调度、退避重试、批量导入、对账/差异、业务审计页面、接入密钥轮换流程；第一阶段 8 张公安 IAM 表的历史归档、引用清理和最终收敛。

OIDC/SSO、MFA、公众身份、自动密码激活、角色/应用授权统一下发仍未开通，不把本次人员机构资料接口当作这些能力。
