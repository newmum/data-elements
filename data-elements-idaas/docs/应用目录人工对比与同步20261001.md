# 应用目录人工对比与同步

应用详情新增“资料同步”页签。点击“查看差异”时才通过已核验的运行绑定读取应用租户库的 `rm_user_t`、`rm_org_t` 和关联数据，同时读取控制库本应用已分配的中央人员与机构。姓名相同不自动视为同一人；已有公安一次性导入依正式分配及同 ID 识别，后续手动导入依显式映射表识别。分别列出仅租户有、仅平台有和资料不一致的记录。

“租户 → 平台”只对选中的人员、机构执行。所选人员依赖的机构和上级机构按需补齐；新人员获得中央人员主档与应用资料分配，机构获得应用资料分配。导入不创建平台操作账号或认证账号，不复制租户密码、本地角色及授权。已映射记录只允许人工确认后更新名称、状态和该应用的人员拟用账号；当前版本保留既有中央人员任职、机构父子关系，不自动覆盖，以免误改跨应用共享结构。导入前校验预览版本；数据变化须重新查看差异。`iam_tenant_directory_link_t` 记录应用、本地 ID 与中央 ID，避免跨租户同名或同 ID 错误合并。

“平台 → 租户”复用已存在的 `iam_sync_config_t`、接收端 Magic API 和显式下发任务。只有配置接收地址、测试连接并启用后，才能选中差异下发。界面配置仍通过现有 `push-portal-config` 手动下发，入口移至详情页。没有后台轮询、自动回流或自动下发。

控制库新增表：`baseline.iam_tenant_directory_link_t`，迁移文件为 `V20261001_04__idaas_tenant_directory_link.control.mysql.sql`。四个租户库没有新增或修改表。广电达梦库的本地现状查询改用跨数据库支持的 `current_timestamp`；四个应用的运行绑定已经人工核验，当前本地人员／机构／授权用户数分别为公安 5／113／3、广电 2／30／2、海渔 32／80／1、澄天 34／81／2。当前四个应用都尚未建立启用且测试通过的接收配置，所以下发人员与机构按钮保持不可用，直到操作员完成接收配置。此次没有实际导入或下发任何租户资料。
