## 1. 修订目标与实际修改

保留compact算法、小尺寸控件与紧凑布局，修复“菜单小于正文、卡片标题小于描述、字号在不同页失衡”的问题。

| 文本对象 | V2.2规范 |
| --- | --- |
| 页面标题、资料主对象名 | 24px / 34px，600字重 |
| 抽屉与弹窗标题 | 18px / 28px |
| 卡片与分组标题 | 16px / 24px |
| 主导航、正文、字段、按钮、表格 | 14px / 22px |
| 描述、帮助、次级文本 | 13px / 20px |
| 标签、时间、图表辅助标注 | 12px，普通行高18px |
| 主指标 / 小统计 | 28px / 24px |

集中定义在 `src/app/typography.ts`，CSS变量自动生成。全局Token、small组件Token与页面语义样式均按上述角色设置，不再只修改一个全局字号。

修复应用标题Button内部嵌套Text重新降字号；卡片标题内部Typography继承标题角色；显式设置原生正文基准；SVG趋势图改为实测宽度，窄图减少刻度而不缩小字；环图中心改用HTML文字层。设置保存条改为文档流，避免压住输入。权限组编辑的移动端行布局补齐单列断点。

导入页面残留“请使用虚构数据”之类说明改成字段校验说明，CSV模板改为只有表头，不附带测试人员记录。

## 4. 独立HTML检查具体做了什么

7个代表页面（总览、用户、应用、授权、审计、设置、登录）和3个浮层（身份档案、授权编辑、日志详情），分别按1920、1600、1440、1280、1024、768、390px检查，共70个页面/浮层尺寸组合。

本轮不仅检查水平溢出，还读取计算字号，核对菜单14px、页面标题24px、卡片标题16px、正文14px、描述13px、指标28px、浮层标题18px；检查图表经SVG变换后的实际文字至少约12px，检查保存条不遮住输入。未发现字号契约偏差、页面水平溢出、超宽浮层或脚本异常。

已视觉复看1440px全部7个页面与3个浮层，并查看390px对应截图。发现窄屏设置保存条遮挡字段后已修订为文档流，复测覆盖检查为0。

这些截图明确放在 `companion-screenshots/`。辅助文件复用产品CSS，但DOM和交互不是React/Ant Design，所以**不能据此证明真实React组件的运行期布局、交互、API兼容性全部正确**。不存在真实React截图，也未将生成式效果图作为验收证据。

实际React/Ant Design依赖未安装，因此全项目真实依赖类型检查、Vite构建、React全路由浏览器回归未执行。多浏览器、读屏与200%缩放也未验收。交付没有node_modules、dist或未经安装生成的锁文件。

拿到依赖后的检查顺序：

```bash
npm install
npm run tokens:check
npm run syntaxcheck
npm run audit:ui
npm run audit:typography
npm test
npm run typecheck
npm run build
npx playwright install chromium
npm run test:typography
npm run test:compact
```

Windows可运行根目录 `检查页面排版.cmd`。任一步失败即停止，不能将后续未执行的步骤算为通过。截图和字号测量通过后仍须人工复看对齐、主次层级与长文本，尤其是表头、输入框校验、抽屉底栏和小图表。
