## 1. 第一阶段范围

第一阶段实现政企身份域 `workforce` 的真实工作区：登录、可信会话、人员档案与多任职、组织机构、应用登记、角色资源维护、操作审计，以及跨库人员操作的恢复。

账号继续使用控制库 `rm_user_t`，成员资格继续使用 `rm_user_tenant_rela_t`；机构、任职、角色和资源继续使用当前租户的 `rm_*` 表。新表只补充现有结构缺少的档案、版本、审计和恢复信息。

以下能力不属于本阶段：OIDC/OAuth 认证客户端与协议服务端、MFA、上游身份源、真实外部同步、多来源授权计算、公众注册与实名核验、密码找回。前端对应入口保持未开通，不返回模拟成功。

### 3.1 控制库 `baseline`

已有表 `rm_user_t` 增加 **1 个生成字段和 1 个唯一索引**：

| 对象 | 定义与目的 |
| --- | --- |
| `iam_active_login_name varchar(50)` | STORED 生成字段；账号未删除时取 `lower(trim(user_name))`，已删除时取 `NULL` |
| `uk_iam_active_login_name` | 对上述生成字段建立唯一索引，防止并发创建同名有效账号，同时保留软删除历史 |

该 DDL 需要发布器先检查列是否已存在，以及有效账号按 `lower(trim(user_name))` 归一化后是否有重复。不能直接反复执行 `ALTER TABLE`，也不能未经核对改名或删除历史账号以使索引通过。

控制库新增 **3 张表**：

| 表 | 主要字段 | 作用 |
| --- | --- | --- |
| `iam_account_security_t` | `user_id` 主键，`failed_count`、`locked_until`、`version`、`updated_time` | 账号认证失败计数与临时锁定；不复制密码 |
| `iam_auth_event_t` | `id` 主键，可信 `tenant_id`/`user_id` 可空，`account_fingerprint`、`result`、`reason_code`、`ip`、`trace_id`、时间 | 认证最终结果，包括尚未确定可信租户的失败请求 |
| `iam_identity_operation_t` | `id` 请求号主键，`tenant_id`、`user_id`、`operator_id`、`operation_type`、`request_hash`、`status`、`safe_payload`、`error_code`、时间 | 跨控制库与租户库的人员开通、移除和恢复记录 |

`iam_application_t` 另外约束当前租户、身份域内的应用编码唯一，以及业务资产引用唯一。业务应用的名称、描述和主页从原资产读取；身份登记不另复制整套业务应用台账。平台自身应用可使用 `PLATFORM` 类型。

本阶段不向租户的既有 `rm_*` 表增加或改变字段类型。机构、角色、资源和任职的业务变更仍写其原表，扩展表保存新增属性。

11 张新表均使用 `utf8mb4_general_ci`，与当前旧表的排序规则兼容。首次发布发现 MySQL 默认 `utf8mb4_0900_ai_ci` 与旧表跨表比较冲突，种子及 Magic 写入事务回滚；修正显式排序规则后，仅转换了本次新建且为空的扩展表，未转换旧表或带数据的表。

### 3.3 当前库的兼容事实

`baseline_ga_old` 没有 `rm_user_t`；账号访问必须进入控制库。机构、角色等关系表的 `tenant_id` 已属于复合主键。`sym_application_t` 在同一物理库中包含多个租户的记录，因此“已经选中公安库”不能替代应用 SQL 中的租户条件。

现有 `ROOT` 是虚拟机构节点，不作为可维护、可任职的真实机构。历史机构编号有重复，也有编号与真实父节点不一致的记录；后代必须依据 `parent_id` 判断，不可用编号或名称路径前缀代替父子关系。

## 4. Java 中仅增加的框架能力

新增 `platform/tenant/api/IdentityRuntimeMagicModule.java`，在 Magic 中导入 `identityRuntime` 使用：

| 方法 | 框架职责 |
| --- | --- |
| `strict()` | 在业务事务前验证登录、token 租户与线程上下文一致、有效成员、共享账号启用状态、显式租户数据源绑定，返回 `tenantId/userId` |
| `control(Supplier)` | 暂时进入控制库执行 Magic 闭包，结束或异常时恢复原上下文；拒绝在已开启的租户事务中换库 |
| `requireTenantBinding(tenantId)` | 验证显式数据源绑定，拒绝默认回退及控制库绑定；不改变上下文 |
| `hasTable(table)` | 通过当前租户数据源元数据检查指定表，限制合法表名，不允许外部数据库路由 |

同时对既有框架作两项窄调整：

1. `WhiteListProp` 只增加精确匿名路径 `/idaas/auth/login`。
2. `TenantWebInterceptor` 对该登录路径先进入控制库上下文，避免旧 token 触发兼容自动绑定；其他 `/idaas/**` 请求缺少 token 租户时拒绝，结束时清理上下文。

Java 没有新增人员、应用、角色、机构的业务 CRUD，没有把字段校验、功能权限映射或审计 SQL 移入 Java。这些框架变更需要重新编译并重启共享后端；后续 Magic 业务规则修改按资源发布流程生效。

## 5. 身份、权限与登录审计

租户业务只从 `tenantRuntime.id()` 获取归属。登录可以接收所选租户，但必须先验证账号的有效成员关系。不会给无成员账号自动补公安关系，也不会根据客户端填写的租户切换业务库。

卓鉴功能权限从已有平台角色与资源关联读取，且在第一阶段仅承接明确的 `ALL` 范围；`ORG/OWNER` 不扩展为全租户。页面上的 `admin/auditor` 标签不承担授权。没有新增或恢复平台管理员、租户管理员标志字段。

每次卓鉴登录使用 `deviceType=idaas`、`isConcurrent=true`、`isShare=false` 创建独立 token，并将租户、政企身份域和应用标识放在 TokenSession 中；不改写其他系统使用的账号级 Session 内容。

第一阶段沿用现有加盐 SM3 凭据校验，未进行密码算法迁移。失败计数与暂时锁定保存在控制库，不从前端的演示安全设置读取策略。

通过账号、密码长度和政企身份域输入校验后，每个接受的登录尝试分配一个认证事件 ID。认证结果统一在 `finally` 写入，覆盖凭据错误、限流、账号锁定、租户成员拒绝、数据源未绑定、未初始化、身份或功能权限拒绝及运行失败。错误凭据的账号失败计数只在校验事务中增加一次；最终审计重试使用同一事件 ID，不增加第二条失败事件。

成功流程先完成租户工作和会话 DTO，再保存控制库最终成功记录。最终审计失败时，尝试把已经写入的租户登录记录标为失败，并撤销新 token；持续数据库故障下无法保证审计落库，接口会报错而不会返回登录成功。Magic 的 `exit` 会绕过普通 `catch`，所以会话撤销放在 `finally` 中。

## 6. 事务、版本与跨库恢复

机构、应用、角色、资源及普通人员档案编辑采用一个租户事务：请求回执、业务数据与操作审计一起提交；遇到版本冲突或校验失败一起回滚。相同请求号与相同内容重试读取已保存的结果，不再执行业务回调；不同内容或不同操作者复用请求号会被拒绝。

创建或关联共享账号、开通租户身份涉及两个数据源，使用可恢复操作记录：

1. 校验租户档案和任职，在控制库准备账号、非启用成员关系及 `PENDING` 操作。
2. 在租户事务中保存档案、任职与审计，生成幂等结果。
3. 在控制库激活成员关系，并把操作标为 `COMPLETED`。
4. 中途失败保留安全恢复资料；重试只提交原请求号，且只能恢复本人在当前租户发起的操作。

移除租户身份按相同方式清理当前租户任职、角色关系及档案，再停用成员关系。不会因为账号不再属于某个租户而自动删除共享账号。租户普通编辑也不修改其他租户共用的登录名和凭据。

移除同时撤销该账号明确绑定当前租户的 token；其他租户会话不受此次移除影响。通过真实旧门户登录验证了被移除成员的当前租户 token 失效，同时原操作人员的门户与卓鉴会话保持有效。

恢复入口采用请求内执行与人工继续处理，没有后台自动 outbox 工作者。临时数据库故障解除后，可以仅凭原请求号完成原操作；如果之后目标机构被删除或其他前置条件永久失效，需要人工核查原操作资料，第一阶段不提供自动取消或改写恢复资料的接口。

版本控制覆盖本次 `/idaas/**` 写入口。现有旧 `/sym/**` 写入口尚未统一维护新增扩展版本；若旧系统同时修改相同对象，不能把本阶段版本检查解释为跨所有旧入口的并发保护。后续需要统一这些写入口或补充兼容投影。
