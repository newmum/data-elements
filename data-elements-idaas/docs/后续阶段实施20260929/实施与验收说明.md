# 卓鉴统一身份管理平台后续阶段实施记录

> 本文记录 2026-09-29 的实施和当时验收。2026-10-01 已按用户要求退役定时工作者、自动事件处理和自动下游同步；以下涉及 `IdentityWorkerMagicModule`、自动下发及其验收的段落仅为历史记录，不代表当前行为。现行行为与验收见 [手动同步实施记录](../同步改为手动执行20261001.md)。

**最终状态：已完成确认设计的功能开发、旧共享模型退役和本地验收。21份通过证据已核对并汇总于 [最终验收汇总](最终验收汇总.json)。真实实名服务、通知渠道及正式部署地址仍须接入配置，不能用本地验收服务代替生产服务。**

平台操作账号只通过 `iam_operator_t` 和独立 IAM 凭据登录卓鉴。人员主档 `iam_subject_t` 默认不含登录凭据。公众/统一认证账号使用 `iam_auth_account_t`；应用本地账号使用各自库中的 `rm_user_t`。平台令牌、统一认证令牌和本地令牌不能互换。登记应用、同步目录和取得应用权限是三个独立动作。

公安、广电、海渔和澄天的应用登记均保留 `auth_mode=LOCAL`、`provisioning_mode=OFF`。真实协议和下发验收使用有明确路由的临时QA应用，不因完成代码就替所有业务应用开启中央管理或SSO。

## Magic API与Java分工

新业务接口和函数在 Magic API 的 **`13.统一身份管理`**，源文件位于 `data-elements/db/migrations/resources/idaas-foundation-20260928`。应用、人员机构、字典字段、授权、投影、同步任务、接收处理、公众身份、经办关系、策略、幂等和审计规则都可在Magic编辑器查看修改，增量发布后刷新资源即时生效。应用本地用户、角色、登录适配位于 `@/tenant-account/*`；接收端位于 `@/idaas/receiver-*`，通过部署固定路由取得数据库上下文。

完整119个HTTP接口、52个共享函数及其源码链接见 [Magic接口目录](Magic接口目录.md)。目录由实际发布清单生成，后续修改业务代码可据此定位。

Java仅提供框架能力：

- `IdentityRuntimeMagicModule`：控制库/显式租户边界、实际数据源核验、固定接收路由。
- `PlatformSessionMagicModule`、`AuthAccountSessionMagicModule`、租户会话及拦截器：三类会话隔离和安全版本。
- `IamSecurityMagicModule`、`IamMfaMagicModule`、`IdentityTransportMagicModule`：密码、有限TTL挑战、TOTP、一次性消费、AES-GCM、签名及受控HTTP。
- `IdentityWorkerMagicModule`：定时唤醒与可信调用；事件租约、任务编排和失败状态在Magic。
- `platform/tenant/protocol/*`：Spring Authorization Server协议、PKCE、JWT、加密状态序列化及可信Magic桥接；客户端、授权、当前权限和撤销决策仍在Magic。
- `IdentityApiMagicModule`：验证真实JWT和当前权限，提供IP/CIDR匹配及Redis原子配额；实际业务策略在Magic。
- 租户框架查询适配：使用所属应用本地账号；旧共享账号兼容开关默认关闭，未配置本地来源明确拒绝，不根据同名或同ID账号推断身份。

令牌、下发密钥、MFA密钥及核验凭据不保存在普通设置JSON或公共验收文件中。协议访问令牌撤销会同步撤销持久会话；授权码正常消费不会被当成整会话撤销。广电的密码列使用显式返回别名，避免达梦保留字的列名大小写影响Magic取值。

工作区初次加载曾因相同权限上下文重复查询而超过页面登录等待时间。`bootstrap.ms` 现仅在本次只读加载闭包内保存权限快照，`context.ms` 为每个调用复制独立的鉴权元字段，退出后清理请求属性；普通业务读写及下一HTTP请求仍实时重新检查账号、安全版本、角色和范围。该优化完全在Magic，新增4项实际脚本执行测试验证查询复用、不同操作者隔离、后续请求撤销和异常退出清理。

最终真实后端页面回归的390、1440、1920px三项全部通过，30张React截图保存在 `界面验收`，覆盖总览、应用、人员机构、应用授权、同步任务、SSO、字段保护、API策略、平台操作账号及统一认证登录。已逐页检查标题比例、表格滚动、空结果、手机堆叠及设置保存条；页面没有全局横向溢出和未处理脚本错误。见 [界面最终验收](界面最终验收.json)。

本地前端为 `http://localhost:3005`，共享后端为 `http://localhost:8088`。测试过程中共享运行包有替换，Nacos登录请求超时、数据库/Redis连接也有短暂中断；受影响的回归需要在服务恢复后重新完成，历史通过记录不能证明最后一次运行全部成功。每次启动按进程ID记录独立日志，避免多个启动失败残留进程的日志互相覆盖。

最终完整运行包的 `identitySigningKeys` 启动检查通过。运行日志仍有此前也存在的 NiFi `BulletinPoller` SQL结构警告，本轮未改造NiFi业务表；它不阻塞IAM启动及本记录中的实际验收。

外部真实实名服务和密码恢复通知渠道尚未配置。核验契约测试使用有明确标识的本地签名服务，只证明请求、验签、状态和授权边界正确，不能作为真实身份核验。未配置渠道时不会显示已发送、已实名或已获应用权限。协议Cookie在本地开发允许HTTP，生产应配置HTTPS、稳定密钥和正式接入地址。

MySQL UTC时钟与应用主机存在约数分钟差异。中央业务有效期以数据库UTC判断，协议令牌和TOTP以协议框架时钟判断；生产部署需要校准时钟。测试未修改数据库服务器时钟。

## 第6阶段的切换和恢复

澄天实际路由已由 JDBC metadata 核实，并完成本地闭环36项真实测试。Nacos仅增加 `chengtian` 数据源及其固定租户绑定，保留其余配置和注释；改动前后完整配置保存在私有备份。本次没有凭库名提示猜测路由，也没有修改其它数据源。

旧共享账号接口使用 `retire_idaas_control_resources.py` 切换，源码位于 `resources/idaas-local-retirement-20260929/apis`。保留接口ID、路径和用户分页的本地机构角色信息，移除控制库账号和成员关系分支。原成员关联接口明确提示使用本地用户管理；不会以删除共享成员的方式删除另一应用账号。框架兼容开关 `idaas.legacy-control-accounts.enabled` 默认 false，并有测试证明在没有旧表时也不会触发旧查询或自动绑定。

共享旧账号表通过 `archive_idaas_control_accounts.py` 原子归档，先核验全部实际数据源、LOCAL配置、每个应用的真实本地闭环、零活跃Magic依赖及外键消费者。归档已经完成，不丢弃任何原账号字段或凭据，不给历史账号自动增加卓鉴操作权限。实际数量与摘要见 `第六阶段共享账号归档验收.json`。达梦实际schema从JDBC SQL schema取得，MySQL从catalog取得，不依据租户JSON中的旧schema提示猜测运行库。

所有DDL、完整私有备份、摘要和迁移映射均保留。不要重复运行历史完整安装器或把控制库旧账号表直接恢复覆盖当前IAM业务；回滚前须冻结相关写入并核对新增数据。具体检查点见 [恢复与回滚说明](恢复与回滚说明.md)。当前增量接口发布使用 `publish_idaas_foundation.py`，本地账号适配使用 `publish_ga_self_loop.py`。

用户提出的 `identitySigningKeys` 启动异常已修正环境变量映射、稳定默认目录和错误密钥提示；本机复用原 RSA 密钥，重启不生成新密钥。配置和恢复步骤见 [启动配置与持久密钥](启动配置与持久密钥.md)。
