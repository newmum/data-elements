## 恢复顺序

1. 暂停卓鉴 `/idaas/**` 写入和用户操作，记录正在处理的请求；其它应用自身登录和业务入口仍保持其原路径。先完整导出当前 15 张目标表、此阶段 Magic 资源及本地源代码/构建结果，保存第一阶段以后新增的账号和配置。
2. 审核期间其它并行发布。运行包只涉及本阶段的 4 个 Java 类及其源文件；如果期间有其它改动，按类恢复，不能把整个旧 jar 无条件覆盖到共享服务。确知没有其它变更时才能使用已保存的原运行包，并按本地既有启动器重启。
3. 在控制库事务中停用本阶段 `13.统一身份管理` 活动资源，按 `magic-before.json` 的原 tid、路径、内容和元数据恢复旧 41 条资源，保留现有其它 API 命名空间。不可运行历史租户安装器。恢复目录记录及 group.json，否则旧编辑器可能只剩脚本没有目录结构。
4. 旧 Magic 读取旧安全结构前，将当前新 `iam_account_security_t` 先改名归档，再将 `archive_iam_security_20260928_t` 恢复为原名。MySQL RENAME 自动提交；执行前确认两个最终表名和备份真实存在，避免同名覆盖。其它 14 张新表先保留停用，按已导出新数据逐项处理后再安排退役，不直接 DROP。
5. 前端需要与恢复后的 API 一致。若已有本阶段前发布包，恢复对应包；本次私有备份重点覆盖数据库、Magic 和后端运行包，不能声称含有完整旧前端包。没有旧包时，依据本阶段源变更清单撤销平台管理、工作区/设置/个人中心适配并重建，期间保持卓鉴入口维护，不让新界面继续调用旧 API。
6. 使用共享 Magic 资源刷新或冷启动加载，检查旧平台登录、工作区、公开租户登录设置、公安本地账号/机构/角色和其它 CONTROL 租户登录。逐行核对 `rm_user_t`、成员关系、`sym_tenant_t` 和公安 8 表；不能靠整库备份覆盖来消除差异。

本阶段之后产生的新 IAM 操作账号和 PBKDF2 凭据不应自动倒写到旧共享账号表，也不能生成或推送本地应用密码。回退必须先评估这些新对象的保留及再启用方式。

## 常规维护

修改业务脚本后用 `publish_idaas_foundation.py` 比较、备份和增量发布，再刷新资源及验证对应接口。无源变化时预检应为 0 条变更。`deploy_idaas_foundation.py --apply` 只用于第一次初始化，在当前库重复执行会拒绝。

测试和回退文件中存储的令牌、账号数据及密码摘要都属于私有资料。公开验收 JSON 只包含检查名称、结果、字段定义和数量，不含凭据、秘密或完整个人行数据。
