# 卓鉴第一阶段：平台自身底座

实施范围为用户确认的整体设计第 1 阶段。数据库迁移于 2026-09-28 执行，联调及验收延续至 2026-09-29。英文工程名 `data-elements-idaas`，中文产品名“卓鉴”，系统名“统一身份管理平台”。

IAM 是 **Identity and Access Management（身份与访问管理）**。本工程的 `iam_` 表属于卓鉴自身业务。业务应用仍保留各自本地账号与权限模型。

## 1. 已落地能力

| 能力 | 实际行为 |
| --- | --- |
| 平台独立登录 | 读取 `iam_operator_t`、`iam_credential_t`、`iam_account_security_t`；不再从控制库 `rm_user_t` 校验平台账号，也不要求公安成员资格。使用独立 `idaas-platform` 会话命名空间，对外会话 `realm=platform`，没有 tenantId。 |
| 操作账号管理 | 新建、编辑姓名、启停、软删除、重置密码、解锁；账号名创建后稳定；新账号按平台策略首次改密。停用、删除、改密及重置提升安全版本，旧会话在下一次请求时拒绝访问。 |
| 平台角色与范围 | 仅维护 INTERNAL 容器中的卓鉴功能角色。每个角色分配单独设置 ALL 或 APPLICATION 范围、身份域和有效期；功能与范围必须来自同一分配。服务端即时查询，不用客户端 admin 角色名称放行。 |
| 权限管理保护 | 逐项验证可转授的功能和范围；拒绝提升自身权限；移除最后一个有效全局授权管理入口时整批回滚。 |
| 应用与分组 | 4 个原行业租户登记为 BUSINESS 应用，沿用原 tid/code；支持创建、编辑、启停、分组和引用校验。登记应用不会建 schema，也不会开通统一认证。 |
| 运行绑定核验 | 从现有技术租户取得显式数据源，核对实际数据库和本地菜单 app_id；只读检查应用库。拒绝重复绑定、直接切换现有绑定及无效本地权限标识。核验写入 IAM 绑定记录和应用版本，不改共享框架路由配置。 |
| 平台安全策略 | 密码最小长度、密码黑名单、失败锁定阈值和时长、首次改密；服务端真正执行。未开通的 MFA、SSO、字段加密等配置不接受写入。 |
| 品牌与个人资料 | 平台品牌配置、公开登录品牌读取、当前操作账号姓名修改与原密码验证后的改密。 |
| 审计 | 真实认证、重要变更、权限拒绝及进入 Magic 业务层的接口调用记录。操作日志、登录日志、API 日志使用服务端分页、关键词与结果筛选；接口不保存请求原文、密码、密钥、Authorization 或令牌。 |
| 幂等及并发 | 写接口要求 requestId、已有记录 version；同一请求回放相同结果，同号不同内容 409。控制库同库事务包含业务变更、成功审计和回执，失败回滚。 |
| 前端权限状态 | 服务端返回 globalPermissions、appWriteIds、appBindIds；单应用写权限不使其他应用的编辑按钮可用。未完成初始改密时只开放个人中心。 |

界面入口：`http://localhost:3005/#/login`。账号使用原已登记的平台操作账号；没有公开新增测试账号或密码。现有操作账号只迁入 **1 个**，其他 48 个旧控制库账号没有转成卓鉴操作账号。迁入账号保留原 ID 和可验证的旧密码摘要，后续改密独立写 IAM 凭据表。

第一阶段给这一个初始操作账号建立显式平台管理角色及以下 **14 个**功能资源：

```text
workspace:read
apps:read / apps:write / apps:bind
operators:read / operators:write / operators:grant
platform-roles:read / platform-roles:write
settings:read / settings:write
audit:read / users:read / orgs:read
```

这个清单由本次第一阶段初始化明确写入和审计，不按旧账号管理标志推定无限权限，不包含中央目录写入、业务应用授权、下发或统一认证权限。

## 2. 数据库实际变更

只在控制库 `baseline` 实施 **15 张目标表：14 张新建，1 张重构**。完整、实际使用的 DDL 在 [第一阶段控制库迁移 SQL](../../../data-elements/db/migrations/V20260928_03__idaas_foundation.control.mysql.sql)，实际列定义与数据核对见 [数据库实际核验](数据库实际核验.json)。整体设计的 40 表 SQL 仍是完整目标，不能一次直接执行代替本阶段迁移。

| 目标表 | 用途及关键字段 |
| --- | --- |
| `iam_application_group_t` | 分组 code/name/sort_no/is_del；编码唯一。 |
| `iam_application_t` | 行业应用 id/code/name/kind/group_id/owner_operator_id/status/auth_mode/provisioning_mode；另有一个 INTERNAL 容器，不当作第 5 个行业应用。 |
| `iam_application_runtime_t` | app_id/runtime_tenant_id/local_permission_app_id/binding_status/verified_time；应用和运行租户均唯一绑定。 |
| `iam_operator_t` | 独立登录 username/display_name/status/must_change_password/last_login_time；有效规范账号名生成列唯一。 |
| `iam_operator_role_rela_t` | operator_id/role_id/status/valid_from/valid_until；每人每角色单一分配。 |
| `iam_operator_scope_t` | assignment_id/identity_domain/scope_kind/app_id；机构范围字段留待第 2 阶段，不开放 ORG 写入。 |
| `iam_role_t` | app_id/code/name/identity_domain/status；本阶段只开放 INTERNAL 平台角色。 |
| `iam_resource_t` | app_id/code/name/resource_type/path/method/status；初始化固定平台功能资源。 |
| `iam_role_resource_rela_t` | role_id/resource_id/app_id；角色和资源同属平台容器。 |
| `iam_account_security_t` | principal_kind/principal_id/failed_count/locked_until/security_version/password_changed_time；替换旧单一 user_id 模型。 |
| `iam_credential_t` | owner_kind/owner_id/type/slot/revision/algorithm/secret_hash/status/有效期；不把存储密码放入账号 DTO。 |
| `iam_setting_t` | scope_kind/scope_key/category/config_key/value_json；本阶段仅 SECURITY/password 和 BRANDING/brand。 |
| `iam_audit_event_t` | event_type/actor/action/object/result/reason/trace/请求路径/方法/耗时/脱敏摘要。 |
| `iam_request_receipt_t` | operator_id/operation_code/request_id/request_hash/result_json；操作人、动作、请求号联合唯一。 |
| `iam_migration_map_t` | batch_id/source_schema/source_table/source_id/target_type/target_id/source_hash/state；记录已有操作账号迁入对应。 |

公共字段包含 id、created_by、created_time、updated_by、updated_time、version；软删除只用于需要生命周期管理的表。IAM 默认时间使用 `UTC_TIMESTAMP(6)`，写入、角色生效及锁定判断用数据库 UTC 时间；对外时间明确带 Z。没有修改共享连接池的全局时区，避免影响其他系统。

旧 `iam_account_security_t` 的 **2 条**记录整表保留到 `archive_iam_security_20260928_t`，然后创建新结构；这不是删除旧安全记录。既有 `iam_subject_t`、`iam_directory_org_t` 等旧中央目录暂只读，保留 5 人员、113 机构供第 2 阶段迁移。

控制库 `rm_user_t`、`rm_user_tenant_rela_t` 及 `sym_tenant_t` 原结构和内容完全保留。广电、海渔、澄天仍依赖原 CONTROL 账号模式；这些兼容性依赖按已确认第 6 阶段逐个退役，不能仅改表名前缀使其他应用失去登录能力。

公安 `baseline_ga_old` 没有新增 IAM 表或字段，也没有改其账号、机构、角色、菜单、关联记录、登录配置和路由。读取菜单仅用于绑定核验；本地账号闭环继续有效。

## 4. Magic API 与 Java 的实际职责

资源位置是 `baseline.api_file_t` 中 **`13.统一身份管理`**。本地 [Magic 源码与清单](../../../data-elements/db/migrations/resources/idaas-foundation-20260928/manifest.json) 对应 **45 个 HTTP 接口、15 个公共函数、13 个 API 子分组**，完整活动目录及元数据共 **90 条**，三个共用根目录不计入此数。

| 对外路径 | 功能 |
| --- | --- |
| `/idaas/auth/*`、`/idaas/session/me` | 平台登录、退出、匿名品牌和当前会话。 |
| `/idaas/workspace/bootstrap` | 按真实权限返回工作区及功能、全局/应用写范围。 |
| `/idaas/applications/*`、`/idaas/application-groups/*` | 登记、编辑、启停、删除、分组及运行绑定核验。 |
| `/idaas/operators/*` | 平台操作账号生命周期、改名、重置和解锁。 |
| `/idaas/platform-roles/*` | 平台角色、资源读取、当前角色分配及角色/范围/时间授权。 |
| `/idaas/settings/*`、`/idaas/profile/*` | 平台安全和品牌、自己的资料与密码。 |
| `/idaas/audit/list` | type/page/size/q/result 服务端分页筛选。 |
| `/idaas/users/list`、`/idaas/orgs/list` | 原中央目录有界只读及分页。 |
| 原中央目录写入及 `/idaas/provision/*` | 兼容路由明确返回 503，等待对应阶段，不能伪造成功。 |

45 接口包含尚未开通的兼容入口，并不表示 45 项功能全部开放。新增业务校验、权限计算、密码策略、SQL、事务、幂等、审计、目录读取和绑定业务都在 Magic，编辑后按共享资源刷新流程生效。原命名空间 41 条活动资源先备份再退役，当前只有一套活动实现，不改 `09.系统管理` 及其它命名空间。

本阶段 Java 只改动以下框架入口，已经编译并进入本地运行 jar：

| Java 文件 | 改动 |
| --- | --- |
| `IamSecurityMagicModule.java`（新增） | `iamSecurity.hash/verify` 密码原语，新增/改密用独立随机盐的 PBKDF2-HMAC-SHA256（600,000 次）；旧 LEGACY_SM3_SALT 按原算法校验。无账号 SQL 或业务策略。 |
| `PlatformSessionMagicModule.java` | 独立平台会话指定 TTL 及同会话域撤销方法；业务安全版本和权限判断在 Magic。 |
| `IdentityRuntimeMagicModule.java` | 显式租户绑定的非秘密数据源/数据库核验方法；本地菜单业务核对仍在 Magic，不更新路由。 |
| `WhiteListProp.java` | 精确放行 `/idaas/auth/public-settings` 匿名品牌接口；没有放开 `/idaas/**`。 |

加密参数参考 [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。平台密码修改不会同步到公安或其他应用。

首阶段平台规模较小，IAM 写操作用 INTERNAL 记录锁串行核对权限、引用和最后管理入口；以后规模扩大再按对象拆分锁。本阶段不开放机构授权范围、目录写入、业务授权、HTTP 下发或协议 SSO。

## 5. 发布及验证入口

| 文件 | 用法与边界 |
| --- | --- |
| `data-elements/scripts/deploy_idaas_foundation.py` | 默认只读预检，`--apply` 才迁移、初始化和发布本阶段；已有目标表时拒绝重复安装。密码只从环境取得。 |
| `data-elements/scripts/publish_idaas_foundation.py` | 默认比较资源差异，`--apply` 只更新或增加本阶段资源；修改前私有备份、旧内容比对；没有源变化时 0 条变更。不会重装租户或重放初始化。 |
| `data-elements/scripts/verify_idaas_foundation.py` | 真实接口及并发、范围、有效期、安全、隔离和原数据一致性验收；随机测试对象先记录精确创建意图，按所属 ID/编码清理。 |
| `data-elements/scripts/verify_idaas_foundation_readiness.py` | 发布后/冷启动核验，服务端搜索分页、策略类型、黑名单、品牌及个人资料；临时安全策略在 finally 恢复原内容。 |
| `data-elements-idaas/scripts/verify-foundation-live.mjs` | Edge 真实浏览器，完全不拦截接口、不使用契约种子；环境变量传凭据。检查 390/1440/1920px 页面、账号表单、角色范围和公安绑定。 |

发布器写入数据库后，调用已有 `/sym/node-config/magic-resource/refresh` 激活资源，再检查实际接口与 Magic 编辑器资源完整性。完整初始化脚本不能用作日常发布。历史租户 IAM 安装/完整发布脚本仍禁止重新运行。

## 7. 后续阶段

第 2 阶段迁移中央人员、机构、主兼任、字典和扩展字段，建立应用资料分配并开通机构管理范围；第 3 阶段完成应用角色资源及业务授权；第 4 阶段才重新接入标准 HTTP 下发与经过后续确认的应用 Magic 接收端。第 5 阶段的统一认证及公众能力仍单独安排。其它应用本地账号闭环及旧控制库 `rm_` 退役属于第 6 阶段，不提前切断兼容性。
