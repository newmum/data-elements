## 报错原因与恢复方式

`GET /sym/tenant/login-settings` 的 `403 / 请使用租户本地账号重新登录` 来自前一轮新增的 `TenantLocalSessionGuard`。该校验在租户请求拦截器中执行，旧共享会话会被判定为非本地账号，公开登录页设置接口也因此被拦截。

本次移除该 Java 校验类及其调用，移除租户控制器对本地会话的特殊限制，恢复按控制库成员关系列举、切换租户。公开的登录、租户选项和登录设置路径直接进入控制库上下文，不读取旧 token 的成员资格；登录设置仍校验目标租户有效性，正式业务请求继续沿用原认证及租户边界。卓鉴 `/idaas/**` 继续使用单独的平台会话。

从 2026-09-28 15:42 改造前的实际 Magic 资源备份恢复 10 个接口：登录，当前用户，用户列表、分页、兼容分页、应用用户查询、保存、删除、角色查询和角色保存。用户和密码恢复从 `baseline.rm_user_t` 读取，成员关系恢复从 `baseline.rm_user_tenant_rela_t` 读取；机构、任职、角色、菜单仍在所属租户库中。用户保存及角色保存恢复原模块和原业务脚本。

其中旧兼容分页脚本有三条不带大括号的条件语句，Magic Script 1.9 无法解析。本次只补齐大括号，不改变查询和过滤逻辑。保留它的历史完整路由 `/sym/user/user/compat-page`，应用用户查询同样保留 `/sym/user/user/application-list`；当前用户管理主页面使用正常 `/sym/user/page` 路由。

源数据管理平台应使用改造前的账号密码。前一轮生成的“公安本地维护密码”不再用于该平台登录；没有将该密码写回原控制库账号。

## 卓鉴保留内容和暂停边界

控制库的中央人员、机构、操作权限、接入配置和任务历史保留。仍能通过 `13.统一身份管理` 中的 Magic API 登录卓鉴、读取中央目录。控制库现存中央人员 5 条、机构 113 条，目录维护接口保留。

控制库接收配置已全部停用。接入配置保存、创建任务、测试连接、执行/重试四个写入或发送入口在 Magic 中明确返回 `503 / 租户接入已暂停，当前只维护平台中央目录`，不会调用租户接收系统。已有配置和历史的读取保留。

“09.系统管理 → 10.身份下发”及其 7 个租户端接口已从活动 Magic 资源中撤下；5 个租户专用函数也已撤下。框架公开白名单中的租户独立登录和签名接收路径已移除。资源刷新同时更新冷启动快照，后端已用清理重打包后的 JAR 重启，确认不再包含 `TenantLocalSessionGuard`。

原 `deploy_idaas_phase1.py`、`deploy_idaas_provision.py` 的写入模式已禁用，完整第二阶段发布脚本也已禁用，避免重新创建租户表或覆盖原登录接口。旧 SQL 和资源包标注为历史资料，不作为当前安装入口。

此时源数据管理平台恢复的是**原共享账号模型**：其登录仍读取控制库用户表。卓鉴平台 token 与原业务 token 分别校验，实测不能互换。下一轮仅做卓鉴时，应在控制库内完善卓鉴专用操作账号及权限，避免修改或复用原租户系统用户保存、登录接口；“两个账号实体完全分离”仍需在平台侧单独落地，不能将本次回退描述为已完成租户独立账号改造。
