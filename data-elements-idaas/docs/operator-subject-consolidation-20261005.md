# 平台操作员与人员主档统一来源复核（2026-10-05）

## 原因与业务边界

平台操作员 `iam_operator_t` 保存平台登录名、状态和角色授权主体；人员主档 `iam_subject_t` 保存中央人员身份及姓名。凭据由 `iam_credential_t` 单独保存；`iam_auth_account_t` 是另一个统一认证账号域。人员主档本身不会获得平台或应用登录权。

早期迁移将旧 `rm_user_t` 的同一 ID 分别作为平台操作员和中央人员的 `tid`，但未设置 `iam_operator_t.subject_id`。因此此前平台列表和会话读 `display_name`，人员分配读 `name`，两处可独立变更。迁移记录分别证明了这两个目标的来源，不能仅凭 ID 相同去自动关联其他记录。

## 本次实际合并

- 控制库中平台操作员 1 条、中央人员 5 条；唯一相同 `tid` 的跨主表记录是 `1995681734511165441`。两条记录经迁移来源和当前姓名核验后，已设置显式 `subject_id`。
- 这名操作员的 `display_name`、`phone`、`email` 为空，姓名以 `iam_subject_t.name` 为唯一存储。`iam_operator_profile_v` 在一条 SQL 内取得平台账号和关联人员资料，供管理员列表、会话、应用负责人、审计展示及找回申请读取。
- `uk_iam_operator_subject_id` 保证一个人员至多关联一个平台账号；`fk_iam_operator_subject_id` 保证人员存在；`ck_iam_operator_profile_source` 禁止已关联操作员重复保存姓名和联系方式。独立平台账号在没有人员主档时使用自身 `display_name`。
- 管理员管理和个人中心的姓名写入共用 `operator-name` Magic 函数。其他管理员改名需要 `users:write` 及目标人员的中央机构范围；本人修改自己姓名保持原个人资料权限。人员版本检查阻止旧页面覆盖新姓名。姓名变更只增加人工下发期望版本，不自动下发。
- 只对所选的 19 个 Magic 资源进行增量发布，并调用本机 `/sym/node-config/magic-resource/refresh` 激活运行缓存。没有运行历史完整迁移或覆盖行业资源。
