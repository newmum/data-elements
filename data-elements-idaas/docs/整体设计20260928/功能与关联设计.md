## 2. 关键业务流程

### 登录、注册与凭据恢复

现有认证页面也纳入设计，不只覆盖控制台菜单：

| 现有页面 | 目标行为与依赖 | 实施阶段 |
| --- | --- | --- |
| `/login` | 独立operator登录；账号状态、密码和锁定策略有效后建立平台会话，不要求选择行业租户 | 1 |
| `/auth/workforce/forgot` | 平台操作账号找回；真实通知渠道和一次性验证通过后更新对应凭据、安全版本及审计 | 1有渠道才开放；无渠道使用有权限管理员重置 |
| `/auth/workforce/mfa` | 平台会话MFA挑战；绑定当前登录流程和主体，不能直接访问页面就视为已完成 | 5 |
| `/auth/public/login` | 公众auth_account登录，拒绝拿该会话进入operator控制台 | 5 |
| `/auth/public/register/person` | 建立public域人员及待激活认证账号；实名另有真实核验流程，注册不等于已实名或已获应用资格 | 5 |
| `/auth/public/register/company` | 建立待核验法人及申请人关系；核验后才启用法人办理上下文 | 5 |
| `/auth/public/forgot` | 仅恢复对应公众认证账号，不按同名重置平台或本地应用账号 | 5 |
| `/auth/public/mfa` | 公众认证流程的独立MFA挑战和凭据 | 5 |

密码摘要保留算法及必要的盐/参数格式，旧账号迁入不能只复制一个缺少算法上下文的摘要。一次性验证码、改密令牌和MFA挑战使用框架有限TTL存储，并绑定用途、主体、流程、尝试次数和消费状态；数据库不保存可直接使用的明文令牌。渠道提供方配置只保存非秘密引用，服务密钥交给部署的秘密管理。未联通真实渠道时不显示发送或验证成功。凭据重置成功后令原会话失效，不改变其他身份域或业务应用的密码。

### 新应用接入

登记应用→选择/核对原运行租户→确认正确数据源与旧本地菜单app_id→登记中央人员/机构范围→配置需要的角色与权限→配置接收URL及独立服务认证→测试固定应用和实例→预览差异→执行→核对本地回执。仅注册应用不自动建schema，也不自动开启统一认证。

### 入职和应用分配

新增人员→绑定有效主职/可选兼任→选择提供资料的应用→明确授予应用角色或只同步目录→计算来源并集→生成应用期望版本→下发机构、人员、关联→接收方创建或核准关联本地账号→本地凭据激活→界面按实际回执显示结果。中央创建操作账号是另一条独立流程，不包含在入职默认步骤中。

### 调岗和离职

同库事务结束旧任职并建立新任职→重算原机构与新机构来源权限→保留直接授权或其他组来源仍然有效的权限→生成必要撤权/新增事件。离职按明确动作停用中央人员并撤销中央授予的应用资格，等待应用确认后标记已撤销；不因为远端暂不可达就显示已经全部生效。

### 平台账号停用

停用平台operator→提升安全版本并撤销其管理会话→以后无法操作卓鉴。它关联的人员档案和各应用本地账号不会因同名被一起删除。若同时要办理人员离职，必须发起人员生命周期动作并记录对应审计。

### 本地独立运行与脱管

应用保持原本地登录、机构、用户和角色维护。当中央接入停用或不可用时，不要求用户每次登录请求卓鉴。已经由中央管理的对象需明确脱管，完成字段和关系责任转移后才能全部由本地修改；不物理删除业务引用，也不隐式接管未映射的本地用户。

## 3. API及Magic编辑器结构

建议目录如下；路径为设计草案，正式开发时对照当前路由做兼容适配，不产生两个同路径活动实现。

| `13.统一身份管理` 分组 | 建议对外路径 | 业务归属与约束 |
| --- | --- | --- |
| `01.认证会话` | `/idaas/auth/login`、`/idaas/auth/logout`、`/idaas/session/me`、`/idaas/workspace/bootstrap` | 独立平台会话，无行业租户登录前置；bootstrap返回权限和分页入口 |
| `02.应用管理` | `/idaas/applications/*`、`/idaas/application-groups/*`、`/idaas/applications/runtime-binding/*` | IAM应用业务、分组、已验证运行绑定 |
| `03.人员机构` | `/idaas/subjects/*`、`/idaas/orgs/*`、`/idaas/appointments/*` | 中央目录；旧`/idaas/users/*`只做明确过渡适配 |
| `04.目录配置` | `/idaas/dictionaries/*`、`/idaas/field-definitions/*` | 岗位、条线、资料扩展 |
| `05.应用角色资源` | `/idaas/roles/*`、`/idaas/resources/*` | 同应用引用校验，平台INTERNAL只能走平台授权入口 |
| `06.授权与分配` | `/idaas/grants/*`、`/idaas/permission-groups/*`、`/idaas/assignments/*`、`/idaas/access/explain` | 授权来源、实际计算解释、应用资料分配 |
| `07.同步管理` | `/idaas/sync/configs/*`、`/idaas/sync/tasks/*`、`/idaas/sync/links/*` | 配置与任务分开；预览、执行、取消、重试、对账独立动作 |
| `08.平台账号权限` | `/idaas/operators/*`、`/idaas/platform-roles/*`、`/idaas/operator-scopes/*` | operator及卓鉴自身功能、角色分配与范围 |
| `09.平台配置` | `/idaas/settings/*`、`/idaas/security/unlock` | 仅IAM配置，不写其他应用sym_config |
| `10.审计统计` | `/idaas/audit/*`、`/idaas/statistics/*` | 分页、脱敏、按当前操作者范围过滤 |
| `11.统一认证接入` | `/idaas/clients/*` 等管理接口；协议地址由认证框架提供 | 登记与协议启用分开，业务配置仍可在Magic维护 |
| `12.公众身份` | `/idaas/public/persons/*`、`/idaas/public/entities/*`、`/idaas/public/verifications/*` | 公众身份管理与公众认证会话分开校验 |

新写接口接受请求号与expectedVersion，成功后在同事务写幂等回执和审计。`appId`是被操作对象的选择条件，服务端必须以平台会话的功能权限与对象范围核验，不能把它直接送入租户数据源上下文。平台目录查询始终使用控制数据源。

应用范围的管理员只能修改应用自己的配置、权限与分配，不能凭这一范围改写跨应用共用的人员主档或机构树；中央资料修改另行校验机构范围。授权管理接口还需验证可授出的权限上限，防止操作者通过转授角色扩大自己的权限。批量操作逐项检查目标，任一项不合规则整批拒绝。

各应用接收接口业务仍写在该应用的 Magic API。服务认证通过后，由框架固定接收配置取得可信应用及运行租户上下文，业务只使用这个上下文。调用方提供的tenantId/schema不构成数据访问授权。

## 4. Java与Magic职责清单

| 项目 | 放置位置 | 原因 |
| --- | --- | --- |
| 应用、目录、任职、字典、角色、授权增删改与业务校验 | Magic | 便于查看和实时调整业务规则 |
| 权限来源并集、到期过滤、应用分配投影、解释结果 | Magic公共函数 | 同一规则供查询、下发和接口授权调用 |
| 任务创建、预览、状态迁移、幂等与回执处理 | Magic | 业务状态机集中可维护 |
| 接收的用户机构写入和来源处理 | 应用Magic | 满足每个应用接收接口可维护要求 |
| 平台/本地/可选统一认证会话区分，数据源与事务上下文 | Java框架 | 防止脚本或客户端随意选择数据库和主体域 |
| 密码摘要、秘密加解密、签名验签、精确目标校验、受控HTTP传输 | Java安全组件 | 算法和秘密生命周期不散布在业务脚本 |
| 定时唤醒、并发租约执行原语、调用Magic任务逻辑 | Java调度框架 + Magic任务规则 | 支持可靠后台执行与热调整规则 |
| OIDC/OAuth协议端点、令牌、PKCE与回调验证 | 认证框架；Magic管理配置 | 使用协议实现，不在业务脚本里手写完整协议栈 |

## 5. 功能关联验收样例

| 场景 | 必须验证的结果 |
| --- | --- |
| 操作账号有公安写权限及广电只读权限 | 可以维护公安；不能通过范围并集获得广电写权限 |
| 操作账号只有公安应用管理范围 | 可维护公安应用分配；不能因此改写共用人员姓名、联系方式或任职 |
| 平台账号试图分配超出其可授权上限的角色 | 整批拒绝并审计，不因已具备一般编辑权限而放行 |
| 机构授权和直接授权授予同一角色 | 删除机构来源后直接来源仍有效，解释结果只保留有效来源 |
| 同时人工分配目录并授予应用权限，之后撤销全部授权 | 目录分配保留，中央访问资格撤销；不会将人工来源一并删除 |
| 某人调岗到另一机构 | 主职唯一，相关机构来源授权重算；其他独立来源权限保留 |
| 授权已过期但定时任务尚未运行 | 中央实时鉴权已拒绝；应用下发状态显示待确认，不显示已撤销成功 |
| 应用A的角色传给应用B的授权接口 | 在任何写入之前拒绝，旧关联保持完整 |
| 被管理人员尝试使用平台登录入口 | 不查询其应用本地密码；必须有独立operator及平台凭据 |
| 修改平台账号密码 | 撤销对应平台会话；不修改同名应用本地账号 |
| 发送同事件两次、第一次已提交但回执丢失 | 接收方返回同一稳定本地ID与回执，不重复开户 |
| 同一事件ID但报文内容不同 | 拒绝冲突，不覆盖原事件结果 |
| 新版先到旧版后到 | 本地拒绝旧版本覆盖，中央不倒退ack_version |
| 应用已有同名本地账号 | 返回冲突或进入显式核准关联，不自动接管 |
| 撤销中央授予角色 | 只撤销中央拥有的来源，本地独立授予关系保留 |
| 接收接口返回HTTP200但业务码失败或appId不符 | 任务失败/冲突，不计成功 |
| 任务创建后接收地址或实例变化 | 旧任务暂停并重新核验；不会静默改投新地址或沿用旧实例回执 |
| 关闭卓鉴接入 | 应用仍能本地登录与维护；既有受管数据经显式脱管后移交 |
| 法人经办关系过期 | 相应法人上下文不可用，个人自身其他合法权限保持 |

以上是设计验收条件，本轮没有声称这些未来功能已经通过测试。
