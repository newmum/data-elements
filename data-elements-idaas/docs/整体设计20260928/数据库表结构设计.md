# IAM数据库完整表结构设计（已确认，分阶段实施）

本文件描述40表完整目标结构。全部40张目标业务表已分阶段部署，额外实际列及归档变更见 [后续阶段数据库实施记录](../后续阶段实施20260929/实施与验收说明.md)。配套 [完整目标DDL](./目标表结构.mysql.sql) 不用于直接覆盖当前 baseline；实际迁移使用已核验的分阶段增量脚本，时间默认值沿用首阶段数据库UTC约定。

完整长期设计共40张中央表，分阶段落地；不向业务schema复制这些表。旧9张IAM表有复用、重构与归档，不是在现有9张之上机械追加40张。

## 统一约定

- ID使用varchar(32)，保留已有可复用ID；请求号与外部引用按各字段扩展长度。所有业务关系都是明确字段，不靠JSON隐式关联。
- 以下每表共有：`id`主键、`created_by`、`created_time`、`updated_by`、`updated_time`、`version`。时间统一UTC datetime(6)，现有本地时间按明确来源时区转换，不能直接改解释。
- 状态机通过有名字符串表达，不混用旧0/1含义；旧用户status=0映射ACTIVE须逐表确认。业务编码按说明保留不复用；账号的软删除唯一性使用生成列，避免(code,is_del)只允许一条删除历史的问题。
- JSON仅保留扩展资料、非秘密配置、不可变任务快照及脱敏审计；用户、机构、任职、角色、授权范围拆成列或关系表。
- 项目沿用逻辑外键，不跨schema加物理外键。Magic在同库事务中验证、锁定相关主记录后写入；归档也获取相同引用锁。迁移和定期核查检查孤儿、跨应用与跨域关联。
- SQL中的CHECK和唯一索引覆盖可在单行/同表约束的条件；多表身份域、应用归属和权限限制必须由服务端校验。不能把DDL存在当作授权逻辑已实现。

- 表采用utf8mb4_bin；业务编码按已登记的精确值匹配。新编码统一先trim、限制字符集并确定大小写规则，查询和写入采用相同规范；不按名称或电话猜测同一对象。
- 分期启用引用：阶段1的operator.subject_id保持空，ORG范围等到阶段2启用；其他指向未来阶段的逻辑引用同理。阶段2/3不查询尚未建设的同步事件表，阶段4接入前生成完整基线并启用同事务事件。
- 阶段1平台会话沿用已有独立认证框架与有限TTL存储，由security_version完成失效；阶段5的auth_session持久索引不作为阶段1登录的前置依赖。
- 对被引用的应用、角色、资源、机构和字典，先停用或显式迁移引用再归档；必须使相关有效授权立即失效并重算下发，不能留下仍被鉴权采用的软删除对象。

## 04. `iam_operator_t` — 卓鉴平台操作账号

实施阶段：1。

| 字段 | SQL类型与默认值 | 含义 |
| --- | --- | --- |

| `display_name` | `varchar(100) NOT NULL` | 姓名或显示名 |
| `phone` | `varchar(256) NULL` | 联系方式，可按策略加密 |
| `email` | `varchar(512) NULL` | 邮箱，可按策略加密 |

| `last_login_time` | `datetime(6) NULL` | 最近平台登录时间 |

## 11. `iam_credential_t` — 分用途凭据与密钥版本

实施阶段：1。

| 字段 | SQL类型与默认值 | 含义 |
| --- | --- | --- |
| `owner_kind` | `varchar(24) NOT NULL` | OPERATOR/AUTH_ACCOUNT/CLIENT/SYNC_CONFIG |
| `owner_id` | `varchar(32) NOT NULL` | 归属账号或配置ID |
| `credential_type` | `varchar(24) NOT NULL` | PASSWORD/TOTP/WEBAUTHN/CLIENT_SECRET/HMAC_KEY/RECOVERY_CODE |
| `slot` | `varchar(100) NOT NULL DEFAULT 'primary'` | 密码固定primary；设备或轮换密钥使用独立槽 |
| `revision` | `int unsigned NOT NULL DEFAULT 1` | 凭据版本 |
| `algorithm` | `varchar(64) NOT NULL` | 明确算法和编码版本 |
| `secret_hash` | `varchar(2048) NULL` | 密码、恢复码、客户端验证密钥的单向摘要 |
| `secret_cipher` | `text NULL` | 需要恢复使用的TOTP种子或签名密钥的密文 |
| `key_ref` | `varchar(200) NULL` | 外部加密主密钥引用；不存主密钥值 |
| `public_data` | `json NULL` | 公开公钥及非敏感参数，不放密码 |
| `status` | `varchar(16) NOT NULL DEFAULT 'PENDING'` | PENDING/ACTIVE/RETIRED/REVOKED |
| `not_before` | `datetime(6) NULL` | 可用起点 |
| `expires_at` | `datetime(6) NULL` | 失效时间 |
| `active_slot` | `varchar(160) GENERATED ALWAYS AS (CASE WHEN status='ACTIVE' THEN concat(credential_type,':',slot) ELSE NULL END) STORED` | 防止同凭据槽多个活动版本 |

唯一约束：`(owner_kind,owner_id,credential_type,slot,revision)`；`(owner_kind,owner_id,active_slot)`。
查询索引：主键及上述唯一索引。

关联：按 owner_kind 分别引用 iam_operator_t、iam_auth_account_t、iam_auth_client_t、iam_sync_config_t。

业务约束：密码只存单向摘要；HMAC/TOTP采用受控加密。按用途严格校验所有者，API永不返回已存秘密。旧密码可标记旧算法兼容读取，在重新设置密码时升级。秘密不能进入任务JSON或审计。

单表检查：`credential_type<>'PASSWORD' OR slot='primary'`；`secret_hash IS NULL OR secret_cipher IS NULL`。
