# 统一身份管理平台 · 设计与前端实施规范

> 版本：2.2.0 · Aurora Blue Readable Compact。管理工作区保持清晰的信息结构，表格与表单采用舒展间距；认证页面使用同一品牌和文字层级下的舒展表单。
> 本文件是后续开发的设计基线。新增或修改页面前先阅读本文件，再阅读 `AGENTS.md` 与相关业务代码。
> 设计规范是工程文档，不是产品功能。不得为本文档创建页面、菜单、路由、搜索结果、帮助链接或快捷入口。

## 1. 产品与设计目标

工程标识 `data-elements-idaas` 仅用于内部目录、构建和文档；用户可见的系统名称统一为“统一身份管理平台”。默认页面品牌、浏览器标题、帮助与页脚都使用系统名称，运行期由 `src/domain/branding.ts` 统一维护。政企与公众身份域共用这一系统名称。旧后端品牌配置若含工程名或旧产品名，展示时归一为系统名称；无关的用户自定义标题保留，业务资料与审计记录不改写。

左上角系统切换入口固定显示短名称“统一身份管理”及下箭头；桌面折叠时保留可点击图标，手机导航抽屉保留完整切换入口。切换列表沿用其他系统的五组分类，本系统归入“平台支撑”，列表项使用完整系统名称“统一身份管理平台”。登录、页面标题与帮助中涉及系统名称时均使用这一名称；登录品牌区的页脚另展示“一个身份。连接每一份信任。”。各系统使用当前标签页跳转，开发地址使用 localhost 和独立端口，生产地址通过环境变量覆盖。

平台统一管理组织、人员、应用、角色、授权、同步、认证配置与审计。后台采用统一管理入口，“公众身份”作为业务菜单提供自然人、法人、认证账号、核验及公众应用功能；身份域、操作权限和数据范围仍需隔离，不将两类人员资料或权限合并为一个数据集合。

保留已确认的视觉方向：深海蓝侧栏、浅蓝灰工作区、白色分层卡片、蓝紫色品牌强调、低对比边框和克制阴影。信息密度更高，但不能通过缩小整页、压扁文字或隐藏字段实现紧凑。

管理工作区使用统一密度，不提供标准／紧凑切换，也不读取旧版密度偏好。表格行、筛选区和编辑表单参考万象与海通的可读间距，保留当前的信息层级与组件类型。登录、公众认证、注册和密码流程继续使用独立的舒展表单尺寸。

优先级：业务信息清楚 > 操作正确 > 对齐与可读性 > 视觉装饰。保留必要的分组留白，而不是把所有间距清零。

## 3. 必须保持的全局配置

```tsx
<ConfigProvider
  {...compactComponents}
  locale={zhCN}
  componentSize="small"
  theme={appTheme}
>
  <AntApp>{/* 路由与页面 */}</AntApp>
</ConfigProvider>
```

管理工作区的 `appTheme.algorithm` 必须是 `theme.compactAlgorithm`。管理端 `Card`、`Table`、`Form`、`Tabs` 在使用处明确写 `size="small"`，避免它们自己的默认值和嵌套上下文产生密度差异。认证页面由 `AuthFrame` 内的 `ConfigProvider` 使用 `authTheme`、`theme.defaultAlgorithm` 和 `componentSize="large"`；认证 Form 与 Tabs 明确使用 `size="large"`，品牌颜色与文字角色继承管理端主题。

紧凑算法保留，但**完整覆盖文字 Token**。不能只设置 `fontSize`，却让派生标题字号、组件小尺寸字号或页面原生文本继续使用另一套比例。`theme.ts` 从 `typography.ts` 读取正文、全部标题与行高，并明确设置 Menu、Card、Table、Button、Input、Tabs、Form 等组件的文字角色。

管理端其他支持尺寸的控件继承 `componentSize="small"`。不得写 `size="middle"` 或 `size="large"` 来扩大日常表单、筛选、按钮与列表。认证页控件继承局部 Provider 的 large 尺寸，Steps 的 small 表示步骤展示样式，验证码输入框内的文字链接按钮可保留 small。

抽屉的数值 `size={560}` 是面板宽度，不是组件密度；不能机械替换成 `"small"`。图标、头像尺寸也需要按语义判断，不能全局字符串替换。

消息、确认弹窗使用 `App.useApp()` 获取实例，保留主题上下文。不要在页面调用脱离上下文的静态 `Modal.confirm` 或独立渲染一套 Provider。

## 5. 字体与信息层级：紧凑间距，可读文字

**紧凑是空间密度，不是把所有字号降一级。** 菜单是主要导航，不是小字备注；卡片标题必须高于正文；描述不得抢过标题。不能靠整体缩放、隐藏文字或所有元素统一字号实现视觉一致。

系统字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", Arial, sans-serif`。不依赖外部字体服务，不把字体文件打入交付包。正文默认值必须同时覆盖原生 HTML 与 Ant Design App，避免原生段落回退到浏览器的 16px。

### 5.1 全站文字角色

| 角色 | 字号 / 行高 | 字重 | 适用对象 |
| --- | --- | --- | --- |
| `display` 品牌标题预留 | 32 / 42px | 600 | 当前登录页不使用；不用于日常列表 |
| `page` 页面标题 | 24 / 34px | 600 | 页面名称、应用详情对象名称、用户资料主名称、认证表单标题 |
| `panel` 面板标题 | 18 / 28px | 600 | 抽屉、弹窗标题与日志详情对象标题 |
| `section` 分组标题 | 16 / 24px | 600 | 卡片标题、列表工具栏标题、设置分组、详情分节、应用卡片名称 |
| `navigation` 导航 | 14 / 22px | 500 | 一级/二级菜单、面包屑；不能小于正文 |
| `body` 正文与操作 | 14 / 22px | 400；强调为 500 | 表格主值、表单标签与输入、按钮、页签、筛选、树节点主名称 |
| `secondary` 次级说明 | 13 / 20px | 400 | 页面描述、卡片描述、字段帮助、设置项说明、账号第二行 |
| `caption` 辅助标注 | 12 / 18px | 400 | 状态标签、时间、版本、键盘提示、图表刻度；不得用于导航或主操作 |
| `statistic` 主要指标 | 28 / 36px | 600 | 顶部指标数值；所有同组数值使用相同字号 |
| `statisticSmall` 次要指标 | 24 / 32px | 600 | 应用卡片小统计、环图中心数值 |

标题的显著性由字号、600 字重、深色和位置共同形成。不要使用不必要的 650/750 等非标准字重制造跨系统差异。**指标大数字是独立语义角色，不能用“标题必须大于一切”把卡片标题也放大到 28px。**

数字使用 `font-variant-numeric: tabular-nums`；主文本不要靠减少字间距硬塞入一行。

### 5.2 Token 与 CSS 规则

1. 文字数值只改 `src/app/typography.ts`；随后运行 `npm run tokens:generate`。`tokens:check` 防止 CSS 变量与主题数值漂移。
2. `theme.ts` 显式设置全局正文及 `fontSizeHeading1`～`fontSizeHeading5`、对应行高、`fontSizeSM/LG/XL`。小尺寸控件的文字仍按语义设置，不让 compact 算法自行压低主字号。
3. Card 的 `headerFontSize` 与 `headerFontSizeSM` 均取 `section`。Table 的小尺寸正文、Button 的 `contentFontSizeSM`、Input 的 `inputFontSizeSM` 均取 `body`。
4. `src/styles/typography.css` 最后加载，处理业务类名与少量稳定组件语义类。禁止使用哈希类名、全局 `span {font-size:...}` 或给所有 `.ant-typography` 同时强制一个字号。
5. 本工程 `Typography.Text/Paragraph type="secondary"` 使用 13/20px。卡片标题里的嵌套 Typography 必须继承外层标题字号与字重，不能重新变成正文或说明字号。
6. 应用卡片标题按钮使用 `application-title` 与原生 `application-title-text`，不要在 16px Button 内再套回默认 14px Text。
7. 内联字号只用于确有必要的图标、头像和 SVG 标注；普通业务文本使用语义类或 Token。组件的 `size="small"` 不得用于推断其文字一定是小号。

### 5.3 文本组合的固定比例

- 页面：标题 24/34 → 描述 13/20，间隔 4px。
- 卡片：标题 16/24 → 主要正文 14/22 → 描述 13/20。
- 指标：标签 14/22 → 数值 28/36 → 注释 13/20；不要把标签当成 11px 脚注。
- 列表：姓名/应用名称 14/22 → 账号、部门或说明 13/20；状态标签 12/20。
- 设置：分组标题 16/24 → 设置项名称 14/22、500字重 → 解释 13/20。
- 详情：抽屉标题 18/28 → 分节 16/24 → 属性名 13/20、属性值 14/22。
- 顶栏：面包屑、当前账号 14px；角色名、环境标签等元信息 12px。环境标签不是主导航。

### 5.4 响应式与文字的完整显示

桌面、平板和手机保持上述正文/标题比例。宽度不足时换行、调整列数、收起侧栏或在表格内部滚动，而不是把标题/菜单缩到 11～12px。

长卡片分组标题允许自然换行；应用对象名称可使用省略号，但必须有可读取完整名称的 `title` 或 Tooltip。标题加徽标时徽标不跟随标题放大。工具栏按钮可换行，不能挤压按钮文字。

侧栏折叠时隐藏导航文字、保留图标与可访问名称；不能把整行 `font-size:0` 当成文字系统。移动端登录品牌名称允许取 `section` 16px，属于装饰区适配，不改变业务文字基准。

### 5.5 图表文字不能随画布缩小

SVG 的 `fontSize=12` 不代表屏幕上就是 12px：固定宽度 viewBox 缩到小卡片时，文字也会缩小。本工程 `TrendChart` 使用 `useElementWidth` 获取 CSS 宽度，viewBox 与显示宽度一致；`chartTickIndices` 在窄图减少横轴刻度数量，保持实际标注至少 12px。

环图中心文字使用 HTML 覆盖层，不放进随图缩放的 SVG；图例使用可读文字角色。后续新增图表必须核对 `getScreenCTM()` 后的实际字号，而不只看源码的 fontSize。

### 5.6 本次修订优先级

V2.2 本节替代历史 V2.1 的 22px 页面标题、14px 卡片标题、13px 正文及 11px 图表刻度规则。历史需求文档的业务条款仍保留，但文字/密度实施以当前 `design.md` 为准。

## 7. 页面框架与导航

桌面采用固定视觉的深色侧栏、白色顶栏和浅色内容区。页头包含面包屑、搜索、账号类别、通知、帮助和当前账号，不提供政企／公众模式切换。侧栏品牌后直接显示功能菜单，展开和折叠时都不添加工程名或产品名分组标题。长账号、平台名称和面包屑不能把右侧操作推到窗口外。

菜单保持统一：原组织、授权、同步功能与“公众身份”并列，公众菜单包含公众总览、自然人管理、法人管理、公众认证账号、身份核验、公众应用、公众应用分组、公众统计。平台管理员、角色、全局安全策略、品牌与审计复用共用入口。依据服务端分域只读菜单权限隐藏不可访问功能，页面自动请求其身份数据上下文；加载或拒绝时不显示旧域资料。搜索、帮助和手机导航与桌面菜单保持一致，刷新、深链接和浏览器后退都能恢复所需上下文。顶栏不显示账号类别标识；右侧个人入口展示登录人员和管理角色。

侧栏底部只保留“构建安全高效的数字身份基础设施”，不显示品牌口号、版本号和服务状态；底部信息不得绝对定位覆盖菜单。折叠与展开状态使用同一组业务入口。折叠后二级菜单支持悬停、点击及键盘打开；鼠标移入弹层后可选择功能，选择或离开时关闭。弹层使用独立展开状态，不改写展开侧栏的分组状态；展开后保持当前功能所属分组。弹层文字使用 navigation 14px，限制高度并内部滚动，保留权限与管理范围过滤。移动端使用内联导航抽屉，不把桌面宽度硬塞进窄屏。

页面结构通常为：页面标题与描述 → 可选指标／摘要 → 筛选或任务上下文 → 内容区域 → 分页／操作。“组织与用户”直接从指标卡和目录列表开始，不重复显示“用户管理”标题及说明。

“设计规范”不属于业务导航，禁止出现。不能保留隐藏路由、个人中心入口、帮助跳转或全局搜索命中。已删除的地址由现有不存在页面逻辑处理。

## 8. 页面模板

### 8.1 总览与统计

使用 `CardMetric` 展示同一语义层级的指标。保留蓝紫概览插画和服务摘要，不把所有业务页都改成带大横幅的总览。

图表、分布和排行应从当前数据计算。不能为了好看填入与表格不一致的总数或把系统健康状态写死为真实监测结论。

### 8.2 查询与列表

复用 `DataTable`。筛选区与操作区职责分离：筛选区提供关键词、条件、查询与重置；工具栏展示列表标题、数量、选择状态及新增／导出等动作。

“组织与用户”人员列表采用停顿后自动查询的关键词筛选，不显示单独的“查询”“重置”按钮；“新建用户”位于筛选区右侧。列表不显示多数为空的“岗位”列，岗位仍在用户信息表单维护。桌面端组织树卡片与相邻列表等高，节点在树区域内部滚动；窄屏按上下顺序展示。

表格必须 `size="small"`，宽表使用 `scroll={{ x: 'max-content' }}` 或经过计算的最小宽度。滚动发生在表格容器内，不得让整个页面水平滚动。

数字右对齐，文本左对齐，状态尽量保持单行。操作列保留常用操作，次要动作收进更多菜单。超出宽度时允许工具栏换行，不压缩按钮文字。

分页保留每页数量选择和总数。紧凑不等于增加默认每页条数；本工程仍默认 10 条。

### 8.3 组织、用户与对象选择

组织树与列表采用双栏。树列桌面 300px，1360px 左右收至 280px，小于 992px 时为 220px，小于 768px 时上下排列。机构节点只默认展开根层；搜索时展开匹配路径。节点名称在行内省略并保留悬停完整名称，树只纵向滚动，不出现横向滚动条。编辑人员的组织选择器使用宽面板、清晰的机构图标和分级行，默认展开根层及当前机构的祖先路径，支持搜索。人员列表“更多”提供删除用户；内置管理账号及当前管理账号不可删除，服务端核验版本、管理范围及授权关联。

树节点文字可以省略，但完整名称可查看。长部门名称、数量和展开图标不得互相覆盖。用户行保留姓名、账号、身份类型及状态，不用头像替代身份信息。

### 8.4 应用

卡片视图与表格视图共享对象和过滤条件。应用标识、名称、接入状态、负责人和访问摘要保持层级；卡片操作位置一致。

应用列表标题仅显示“应用管理”。四项概览依次为可管理应用、这些应用的角色、当前身份域可见人员和这些应用的资源权限。搜索、分组及结果数位于同一侧；调整顺序、卡片／列表切换和新建应用位于工具栏另一侧。顺序保存在控制库 `iam_application_t.sort_no`，由显式 Magic 接口调整，卡片与列表使用同一顺序；公安元数据管理平台初始化排在首位。

应用详情使用统一头部和紧凑页签。概况、角色、资源、有效用户、接入与安全配置不能各自采用不同密度。概览中的基本信息与人数权限在桌面端各占半宽，移动端上下排列；字段与表格保留足够留白及正文 14px 字号。人数权限分别列出租户系统与统一身份平台的实际资料数量，未取得数据时不伪装为零。
接入配置作为末尾页签集中客户端登记、回调与认证配置，不重复放置相同内容的页签，也不显示重复的提示横幅。概览的访问数据采用“应用本地／平台”对照表；人员、机构、角色、资源和授权用户页签先展示已核验运行应用的本地表，再展示平台资料分配或平台授权。本地数据只读；一次性初始化已将公安资料及角色资源定义写入控制库正式 IAM 表，后续租户新增资料不自动回流。

人员和机构分为两个独立页签，连续排列在角色之前，各自展示资料、分配操作和刷新反馈，不再嵌套第二层页签。已部署应用的运行租户及本地权限关联属于连接信息，放在概览的默认折叠区域。界面称“租户库标识”与“租户内权限应用标识”：前者定位数据库，后者在库内定位角色与菜单；“检查并保存关联”仅验证和保存映射，不触发登录或资料下发。连接区不再显示大段提示横幅。

人员、机构页的租户系统资料只读，进入页面时读取一次，“刷新列表”仅再次读取当前租户库，不导入或下发。租户资料表与平台分配表不放大段说明横幅；人员分配用“已分配／已移除”表达资料状态，用“已授权／未授权”表达平台访问授权，账号列直称“账号”。期望版本与接收确认版本属于下发内部状态，不在业务列表直接展示；下发状态仍须保留。两张表在桌面与手机端都使用正文 14px、舒展的行间距和可触达的操作按钮。

### 8.5 授权与权限组

保留对象选择、有效权限与来源、编辑面板的清晰分区。直接授权、机构继承、权限组授权使用一致标签。

权限影响预览使用实际授权计算，不能用固定的“新增 12 项”等展示数字。撤销某一来源不等于移除全部有效权限。视觉改造不得改变授权并集、有效期、停用和身份域约束。

### 8.6 审计与同步

日志表格和详情保持业务时间、操作主体、对象、结果、追踪标识可读。JSON／路径使用可换行或独立滚动区域；不得撑宽抽屉。

同步任务显示真实的当前适配器任务状态；失败明细与重试入口一致。摘要数字应能追溯到任务和记录，不能把失败伪装成成功。

同步配置仅保存接收地址和凭据；人员、机构资料只在操作人员点击下发时发送。任务失败后由操作人员查看回执并点击继续执行／重试，不在页面或后台设置定时轮询、自动下发、自动重试。

### 8.7 配置与个人中心

配置按业务分组，不把所有字段平铺成一张超长表单。小屏单列，较宽内容区才使用双列。双列字段之间用 16px 栅格槽。

底部保存区默认随表单正常文档流排布，不吸底覆盖输入框。以后确需吸底时必须单独设计滚动容器、底部占位与焦点滚动，验证最后一个输入和错误提示不会被挡住。按权限禁用时要提供可理解的原因。

### 8.8 登录、注册与密码流程

复用品牌双栏框架，表单区域最大宽度约 420px，注册页可按字段需要使用 490px。表单字号保持 14px、标题 24px；输入框与普通认证按钮高 44px，主要提交按钮至少 48px，身份域选择高约 40px，字段间距 24px、标签下间距 8px。桌面与移动端都保留这些可读、易操作的尺寸，窄屏保留品牌名称与必要字段，装饰插画可隐藏。

登录品牌区保留系统名称、插画和三项能力名称；将原介绍的“统一身份、安全访问、人员应用权限协同”作为主标题展示。品牌主张“一个身份。连接每一份信任。”放在左侧页脚。三项能力说明不显示，图标与名称上下居中并保持足够间距；管理登录表单标题下不显示额外介绍。

不在页面展示固定开发账号、口令或验证码，不预填管理员密码。输入缺失、错误、锁定与提交中的反馈使用业务语言。

认证内容保持自然文档流；矮屏或注册长表单允许垂直滚动，不能通过缩小控件、全页缩放或裁切字段硬塞进一屏。管理工作区的表格与表单使用 34px 小尺寸控件和舒展的字段、行距。

## 9. 编辑、详情、弹窗

优先复用 `RecordEditor` 和 `DetailDrawer`。普通编辑抽屉约 560px，复杂详情约 736px；其他面板按信息量选择宽度，始终限制在视口内。

使用 Drawer 的 `size={数值}` 和公开语义样式。小屏宽度不能超过 `100vw`。弹窗宽度不超过 `calc(100vw - 24px)`，顶部预留 32px，长内容在正文滚动。表单字段纵向间距 18px，双列字段横向间距 16px；标签、输入和帮助文字分别保持 14、14、13px 的明确层级。

表单优先顶部标签；双列字段使用 `<Col xs={24} sm={12}>`，不能只写 `span={12}`。长标签自然换行，不能用固定标签高度裁切。

表单提交的校验失败与服务端保存失败统一使用 `App.useApp().message.error` 在视口顶部提示，不能只把错误插到可滚动抽屉、弹窗或长页面的开头。字段本身仍保留校验文案，便于定位和修改；长期有效的业务状态与提交回执可继续留在页面。`Form.Item` 必填项由 `required` 规则显示星号；手写标签的条件必填项也要显示同样的星号，并在提交前校验。

详情 `Descriptions` 使用 `size="small"` 和 `column={{ xs: 1, sm: 2 }}`。只读信息不伪装成可编辑输入。

提交中禁用重复动作。失败保留输入并显示原因。未保存关闭需要确认。危险确认明确对象和动作，取消路径始终可用。

## 10. 文案与数据呈现

产品界面只使用正常业务描述：例如“已保存”“执行中”“授权来源”“请求暂时无法完成，请重试”。

页面标题、标签、提示、帮助、通知、空态、错误、成功反馈和导出内容，不得出现 Mock、演示、评审、模拟、当前仅前端、本轮、测试账号等开发语境。

不得用假成功替代缺失能力。配置保存只能表示配置已保存；格式校验只能表示格式通过；密码重置申请不能冒充密码已修改。认证、加密、同步和策略 enforcement 是否真正生效须由服务响应决定。

生产风格的环境标签是展示需求，不构成真实生产安全或后端能力的证明。适配器和交付边界必须保留在 `README.md` 与验证报告中，不放在业务页面反复提示。

保留用户自己输入的自由文本。历史内置开发措辞只做精确匹配的显示迁移，不全库正则替换、不修改用户账号、授权对象 ID 或审计证据快照。

## 11. 响应式、长文本与特殊状态

必须检查 1920、1600、1440、1280、1024、768 和 390px。390px 不是要求把所有桌面字段同时塞进一屏，而是要求页面可操作、表格局部滚动、浮层不超屏。

Grid/Flex 子项按需使用 `min-width: 0`。工具栏和按钮组使用换行；固定布局列使用 `minmax(0, 1fr)`；长 URL、邮箱、JSON 用换行或局部滚动。

禁止 `zoom`、`transform: scale()` 缩放整页，禁止用全页 `overflow-x: hidden` 掩盖溢出。仅有明确滚动契约的面板可以限制溢出。

加载态使用骨架屏或组件 loading，不显示“正在加载已授权资料”等不准确文案。覆盖空列表、无筛选结果、字段报错、权限不足、保存失败、超长名称、批量选中和到期状态。

任何隐藏只限装饰和重复辅助说明；不能为让窄屏好看而隐藏关键业务结果或唯一操作入口。

## 12. 图标、动效与可访问性

使用 `@ant-design/icons`，同层级保持线性图标风格。状态、按钮和导航不能混用 emoji 代替组件图标。

用户头像默认约 32px，应用常用图标约 36–40px，指标图标约 40px。允许资料头部更大，但不得扩大所有行高。

保留原有轻量 hover 和焦点效果。支持 `prefers-reduced-motion`；不添加连续闪动、自动轮播或大面积循环动画。

交互控件需可聚焦、可键盘操作。纯图标按钮提供 `aria-label`／Tooltip。输入与标签关联；错误提示不能只靠红色。不能移除默认焦点环。

## 14. 后续开发流程与验收门槛

1. 先检查已有页面和公共组件，复用布局与状态；再修改业务模块。
2. 所有公共尺寸首先调整 Token／公共组件，不到处覆盖 `.ant-*`。确需 CSS 时使用稳定语义类和页面范围，避免依赖哈希类名、内部 DOM 顺序或 `nth-child`。
3. 新增业务入口更新导航数据、路由、访问控制与测试；不得添加设计规范页面。
4. 运行下列检查，保留真实结果，不把语法通过等同于构建成功：

```bash
npm run tokens:generate
npm run tokens:check
npm run syntaxcheck
npm run audit:ui
npm run audit:typography
npm test
npm run typecheck
npm run build
npx playwright install chromium
npm run test:compact
npm run test:typography
npm run test:e2e
```

`test:typography` 读取真实 React 页面计算样式，核对所有工作区、应用页签、认证页及关键浮层的文字角色；输出测量 JSON 和截图。字体断言不能替代人工视觉复查。

`test:compact` 读取导航清单，覆盖政企／公众全部工作区、认证页、应用详情页签及关键浮层。新增页面应自动纳入或明确补充测试。

截图必须来自实际运行的对应产物。独立 HTML 仅供视觉辅助，不能冒充 React／Ant Design 验证。

每次交付记录：实际检查的页面与分辨率、运行时错误、表格局部滚动、弹窗与抽屉、失败与空态、长字段、删除入口、数据兼容，以及未完成项。

## 15. 不允许的回退

- 恢复标准／紧凑切换，或将管理工作区改为宽松模式；认证页应遵循第 8.8 节的舒展表单规则。
- 重建设计规范菜单、隐藏路由或快捷入口。
- 只给首页换肤、其他页面沿用不同尺寸体系。
- 把所有文字变小、全页缩放或裁切字段来实现紧凑。
- 菜单小于正文，卡片标题小于描述，或同一角色在不同页面使用不一致字号。
- 仅检查不溢出就宣称排版合理，忽略实际字号、字重、层级与文字覆盖。
- 为视觉修改删除授权来源、任职关系或历史用户数据。
- 把本地数据适配器改名就宣称已有真实后端和生产安全能力。
- 在业务页面暴露开发账号、验证码、故障注入、恢复初始数据等工具。
- 未真实运行测试就写“全部通过”或用独立预览截图代替 React 运行截图。

## 16. 第一阶段真实后端接入

管理工作区通过共享后端读取当前租户实际数据，不回退浏览器种子。组织树面对真实大量机构时采用局部纵向滚动，保留相邻人员表的可读位置；不缩小字号或裁切名称。应用、人员和总览的未开通授权统计显示“—”，授权详情、认证协议和 MFA 使用业务未开通状态。人员恢复只提交原请求号，前端不持久化初始密码或恢复业务资料。

人员页左侧组织树与编辑抽屉的组织机构选择树采用相同的紧凑层级间距。树箭头在展开状态向右、收起状态向下，避免出现向上的箭头；弹框深层节点仍可通过搜索定位。

排版与紧凑浏览器测试通过测试层 HTTP 契约固定长字段、空结果、冲突和未开通情况；实时 React 页面另连接 `baseline_ga_old` 验证。两类证据分别记录在 `docs/第一阶段前端接入验证.md`，数据库与框架边界在 `docs/backend-phase1-implementation.md`。

## 17. 用户信息一体化编辑

用户列表姓名与“编辑”进入同一个“用户信息”抽屉，不再提供独立的“身份档案”。抽屉取消重复的头像概要块，基础字段、当前有效授权、应用角色权限预览与可选手动下发按段排列，窄屏改为单列。新建人员并选择立即下发时，创建者填写并确认目标应用初始密码；仅保存中央人员资料时不创建应用登录账号。

账号和兼任机构字段不显示重复的长说明；应用角色、下发区域只保留操作控件及必要的错误反馈。所选角色和已有授权的资源权限按“菜单／按钮／接口”分组展示，组内直接列出权限名称，不在每个名称前重复标注类别。

用户明确选择应用与角色后，页面先保存人员，再新增一条直接应用授权。授权不覆盖已有机构、权限组或其他直接授权。仅显示并允许当前账号可管理的应用，服务端继续按人员、应用和角色逐 ID 校验。立即生效的授权以服务端 UTC 时间为准。选择已测试且启用的目标接收配置，并勾选“保存后立即下发此用户”后，页面先确保人员资料已分配给应用，再创建单人下发任务；保存资料或授权本身不触发下发。公安接收配置使用已有本地目录映射，人员下发时按角色映射自动绑定公安已有角色及其菜单，不新建重复的机构、角色或菜单。新账号下发成功后，初始密码通过独立签名请求即时送达接收端，由目标租户按本地算法加盐保存并启用账号；中央人员和下发任务不保存密码。已有本地密码不得被此流程覆盖。

写入后的工作区数据原位刷新，抽屉保留到全部步骤结束。后续步骤失败时保留输入和已经完成的人员、授权、下发任务编号，允许重试，避免重复建人或重复下发。

公安映射、实际接收联调及管理员操作路径见 `docs/公安应用角色映射与新建用户联调.md`。
